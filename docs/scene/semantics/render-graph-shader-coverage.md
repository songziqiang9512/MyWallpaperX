# Scene Render Graph 与 Shader 覆盖矩阵

> 核验日期：2026-08-05
>
> 范围：Effect definition、material、render graph、FBO 与 Wallpaper Engine shader 合同。
>
> 结论：当前 graph 已有较完整的保真 IR，ShaderContract v1 安全保留 authored source/include/annotation/declaration；R2 建立候选 source graph、bounded preprocessor/variant，R3 把固定 8 槽、exact provider publication、active frontend/reflection、uniform/state 与保守 color transfer 原子形成 `SceneResolvedMaterialProgram`。R4 已让该 Program 的 bounded implicit-framebuffer / straight-alpha / dynamic-uniform 子集进入统一 executor，fresh full45 中 14 个真实样本的 57 个 resolved layer / 75 个 exact subject 取得 GPU/compositor/next-frame 证据；其中 ordinary Tint 本批迁移 41 个 exact subject / 41 层，并修复 owner 转移后的 live-property target lifecycle。这不再是 R3 的全部 `gpuEncoded=0` 状态。但通用跨语言 helper/compile、任意 material/pass/state/resource 和旧 owner 全撤权仍未闭合，因此本页仍无 `L4` 项，也不表示通用 shader 或 Wallpaper Engine 视觉等价；最新实现基线与运行门见 [运行证据索引](runtime-evidence-index.md)。

### 1.1 `linux-wallpaperengine` D 级复核边界

固定 revision `b016d7d1fdcf4e5fd2f9c9fa420a8aaa07fee02d` 没有附带 stock effect/material/shader assets，运行时要求用户提供官方 Wallpaper Engine assets。因此它不能核验 45 个 effect 的逐参数和算法；本页只用它交叉检查 generic contract，并保留以下未进入官方 A 级表的候选：

- `ShaderUnit.cpp:77-94` 的处理顺序是 include -> `#require` -> variables；`#require` 只识别 `LightingV1`，生成的 `PerformLighting_V1` 固定返回零（`ShaderUnit.cpp:313-376`）。这证明私有 shader 中可能存在 module directive，不证明该 stub 或 module schema 正确。
- 它的 annotation/combo/sampler 解析依赖 regex/string，sampler slot 只提取单个数字且 combo 只接受整数（`ShaderUnit.cpp:442-543`）；不得作为未来 frontend 的实现模板。
- `CPass.cpp:824-890` 还尝试绑定 `g_TextureReductionScale`、`g_Brightness`、`g_UserAlpha`、`g_CompositeColor`、`g_LightAmbientColor`、`g_LightSkylightColor` 和 `g_NormalModelMatrix`。这些名称是 D 级 runtime 候选，不追加到官方 Variables 合同；先在合法 assets/样本 source 中确认声明、类型和作用域。
- 同一 binder 把 Left/Right 16/32/64 spectrum 都指向同一 mono 数组，并把部分 effect projection/normal matrix 简化为 identity 或现有 matrix。它只能帮助发现需要的 binder surface，不能提供 stereo、matrix 或 lighting 数值 golden。

| 等级 | 唯一含义 |
|---|---|
| `L0` | 当前代码没有识别或承载该语义；只有文档需求不算实现。 |
| `L1` | 能发现资源、路径、blob、raw token 或给出诊断，但没有可执行的结构化语义。 |
| `L2` | 已进入 typed/loss-preserving IR 或 typed host carrier，并有结构/失败关闭测试；没有 GPU 执行承诺。 |
| `L3` | 至少一个**明确注册的 strict executor 子集**精确消费该语义，并有正向、负向及运行/GPU 证据；只对表中边界负责。 |
| `L4` | generic runtime 能直接按 authored graph/shader 合同执行该语义，不依赖 effect ID、shader path 或固定 profile 手写分派，并覆盖资源生命周期和回归矩阵。 |

每行只能有一个等级。**通用 primitive 取全部已知 authored 形态的共同最低状态**：某个 strict profile 能执行，只能在该 profile 自己的行和 [Effect 执行覆盖表](effect-execution-coverage.md) 记 `L3`，不能反向把通用 definition、pass、FBO、slot、combo、uniform 或 render state 抬到 `L3`。辅助设施存在也不能把官方语义抬级。

**本表的 `L4` 与其他覆盖表的 `L4` 不是同一坐标轴。** [覆盖台账](coverage-ledger.md)、[Effect 执行覆盖表](effect-execution-coverage.md)、[粒子组件覆盖表](particle-component-coverage.md)、[SceneScript API 覆盖表](scenescript-api-coverage.md) 的 `L4` 都指「已与 Windows Wallpaper Engine golden 或官方行为核验」，是**验证轴**；本表的 `L4` 指「generic runtime 不靠固定 profile 分派即可执行 authored 合同」，是**实现通用性轴**。因此本表某行达到 `L4` **不等于**该语义已取得像素 parity，反之靠 strict profile 取得 golden 也不会把本表抬到 `L4`。引用等级时必须带上出处表名。

已删除的派生解释格式曾记录 graph/shader 侧增量：v22 在既有 ShaderContract/binding program 和 exact stock Opacity 合同基础上保存 direct text content/point-size/color binding program，v23 增加 layer `puppetMeshPath`。此后 v24 增加 Puppet attachment bind frame（`attachmentName`/`boneIndex`/`modelBindFrameColumnMajor`）、v25 增加 `puppetAnimationLayers`（MDLA clip 的 `animationID`/`additive`/`blend*`/`rate`/`visible`/`visibilityBinding`）——**这两次都是 Puppet 通道的字段，没有改变 graph/shader 侧合同**。v26 增加 material pass `alphaWriting` 与 `userShaderValues`，v27 增加 layer `brightness`，v28 增加 text layer `anchor`，v29 增加 text overflow 字段；这些版本号现在只作字段落地历史。`a77b875` 起 production host 直接持有内存 `SceneRuntimeInput`，Debug runtime evidence schema 1 与播放输入解耦。execution catalog 仍在启动时从 authored graph 与 ShaderContract 规划；Opacity direct alpha、Local Contrast strength、受限动态文本与 X-Ray target 可 live 消费 per-surface snapshot，SceneScript alpha、其他动态 effect 参数、Shadow 常量与通用 shader uniform 仍未 live。

当前基线 commit 与 schema 版本号以 [运行证据索引](runtime-evidence-index.md) 和 [覆盖台账](coverage-ledger.md) 为准；本表不复制，避免随代码演进失真。

## 3. Render Graph 覆盖

`136d35c` 新增的 Local Contrast strict profile 只接受 `effects/localcontrast/effect.json` 的单 effect stage：4 个 material pass、2 个非 unique 的 quarter-size `rgba8888` FBO、`KERNEL=0`、`GREYSCALE=0`、`MASK=0`、Gaussian `scale=(1,1)`（显式值或该 stock profile 的缺省值），以及 `0...5`、缺省为 `1` 的 `strength`。准入同时核对 exact shader identity/canonical/stage/raw/source hash；这些 fingerprint **只用于确认 stock contract 身份**，实际 GPU 路径仍执行仓内手写 MSL，并未编译 authored source。`strength` 是当前唯一由 property binding program -> per-surface snapshot -> GPU strict executor live 消费的该 profile uniform。

该 profile 不接受 mask、greyscale、非默认 kernel/Gaussian scale 或其他 Local Contrast shape；它只能进入每个 stage 都由 strict backend 接受的 chain，包含任一 unsupported stage 的 mixed chain 整体失败关闭。Metal 实现采用官方非 `HLSL_SM30` 分支语义，没有套用 `0.75 / resolution` 偏移；当前也没有合法 Windows WE 像素 golden，且运行日志尚不能直接证明某一帧把具体 `strength` 数值上传到了 Metal buffer。这些边界不能由 repo-local stage 数值测试或画面变化率代替。

`809b75e` 的 exact Workshop Shadow 只接受 `effects/workshop/3488490208/shadow_____________/effect.json` 的单 material stage、零 authored FBO/bind/slot、`MASK=0`、`BLENDMODE=0`、normal/nocull/depth disabled、black color，以及静态有限 alpha/border/offset；definition、material、vertex/fragment ShaderContract fingerprint 任一差异都拒绝。它复用 target table 的 synthetic input/output texture，在 ordered chain 中消费前一 stage output；仓内手写 MSL 保持 premultiplied host 边界，但 mode 0 没有合法官方 Windows 像素 oracle，因此不等于 WE 像素等价、官方 45 项 Effect、generic Shadow 或 authored shader execution。

`b541867` 的 scheduler 验证全局 effect/node/target identity、layer source -> effect output 连续性和最终输出，并先为整链建立 plan/table、预算与 LRU 候选，成功后一次提交。GPU 在同一 offscreen command buffer 依序执行 strict backend。普通 effect 继续按最长边 2048 分档；受限 authored shader 按 drawable 上的图层投影像素执行，最长边上限 4096，pool 驻留预算 128 MiB。`69cc7f01` 让 preflight 与 allocation 共用同一 extent resolver：先用显式 `width`/`height` 覆盖对应轴，再执行不放大的 `fit`、`scale` divisor 与 floor/min-1；单轴、组合形态及 `scale < 1` 放大都按实际 2048² 参考面积计费，非法值直接拒绝。`c73aa0b0` 只让 string/array 的精确 `[0,0,0,0]` clear 进入 logical target，并在 table 首次创建/重建后与 history seed 一并执行一次初始化；非零或畸形 clear 继续拒绝。该 128 MiB resident transaction 门不是瞬时驱动 VRAM 硬上限。generic compose/condition/function、跨帧 logical swap 与其他 history consumer 仍不执行，也不让下表 generic primitive 整体升级到 `L3`。

## 4. 官方 Shader 六页合同

以下六个 anchor 与 [官方逐页映射](official-page-map.md) 一一对应。这里记录官方公开语义，不把编辑器操作步骤误算成运行时能力。

<a id="op-shader-overview"></a>
### 4.1 Overview

| 官方合同 | 当前级别 | 当前边界 / 实现门 |
|---|---|---|
| effect shader 使用类 GLSL source，并在需要时翻译为 HLSL | `L3 子集` | ShaderContract 保真后，中性 preparation/frontend 可把 bounded framebuffer/单源颜色、host/dynamic uniform 与 texture schema 编译成完整 Program；现役 GPU owner 是 resolved-material graph executor。三组 exact Scroll 只作历史 oracle，不再通过 profile 推断独立 owner；include/combo、任意 material texture、复杂 state/FBO/多 pass 与 arbitrary source 仍不能外推为官方完整兼容。见 [E-SHADER-PREPARATION](runtime-evidence-index.md#e-shader-preparation) 与 [E-AUTHORED-SHADER](runtime-evidence-index.md#e-authored-shader)。 |
| 官方向 effect shader 提供向后兼容承诺 | `L0` | MyWallpaperX 只有 bounded Program/executor 子集，尚不能承接官方的通用向后兼容承诺；剩余 strict MSL 也不能冒充 source compatibility。 |
| 3D 自定义 shader 必须兼容 `generic2.vert` / `generic2.frag` | `L0` | 无 3D model/runtime，也未取得这两个 stock contract 的合法本地 schema。 |
| 不应替换 particle 等 system shader；官方不保证其向后兼容 | `L0` | 产品门：即使未来能读取，也必须默认拒绝 system-shader override，不能把它纳入首期 arbitrary shader。 |

### 4.6 Desaturation Tutorial

官方教程给出了首个 generic shader executor 的最小合法 fixture：hidden framebuffer `g_Texture0`、`v_TexCoord`、`texSample2D`、`CAST3(dot(...))`、`gl_FragColor`，再加入 `u_DesaturationAmount` slider 与 `mix`。当前为 `L0`：现有色彩近似/手写 pipeline 没有执行这份 authored source。只有这份 fixture 能经 source parse、annotation、material/slot、variant、uniform upload、GPU 编译和像素门端到端通过后，才能把对应 primitive 升级。

## 6. 当前开发门序

1. **Shader contract IR v1（已完成）**：只读、安全保存 source/stage/include/annotation/declaration、raw/canonical hash 与诊断。当前是 line-based loss-preserving source contract，不是完整 AST；不运行外部编译器，也不声称 GPU 支持。
2. **strict Local Contrast（已完成）**：`2902406982` layers `167/177` 已闭合 exact stock 4-pass/2-quarter-RGBA 单效果 profile；`2938612768` mixed chains 保持 fail closed。边界仍是 mask/greyscale/nondefault kernel/scale、mixed chain、generic shader、`HLSL_SM30` parity、直接 uniform 上传遥测和 Windows golden。
3. **Ordered strict effect-chain（已完成有界执行；D6 extent 为 `L2`）**：完整支持的 material-only stage 已按作者顺序消费 target/bind/read/write，同 command buffer、整链 allocation/LRU 和末段合成有原子失败门；synthetic 与真实 Workshop chain 均有正向门，unsupported mixed chain 仍整体关闭。`69cc7f01` 让 authored `width`/`height`/`fit`/`scale` 保真、allocation 与 preflight area cost 共用同一算法，但没有因此建立 generic FBO/material executor。
4. **Exact Workshop Shadow（已完成）**：`3724289844:20` 的 `Blur Precise -> Shadow` 已成为首条真实 strict chain。该 backend 只接受完整 definition/material/ShaderContract、normal/no-mask/default-blend/静态常量合同；它不是官方 45 项 Effect、generic Shadow 或 authored shader，且 mode 0 无官方 Windows 像素 oracle。
5. **Stock Opacity `MASK=0` + live alpha（已完成）**：exact single-pass profile 已让 alpha 经既有 binding program/per-surface snapshot 被 GPU 消费；同批覆盖 premultiplied RGBA、ordered chain、invalid/mixed rebuild、same surface/window 与 unsupported stage 原子失败。
