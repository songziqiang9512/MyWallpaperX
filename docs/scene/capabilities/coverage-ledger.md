## 1. 口径

> 状态：现役 current capability 唯一系统摘要；逐项合同与专题内等级由各专项能力表维护
>
> 原系统汇总核对：2026-09-01；2026-10-03 按已有冻结执行记录同步 Batch2 的有界能力摘要，本次未复跑 App、GPU 或官方对照；各批代码/输入/产品身份与未验边界见[冻结记录入口](runtime-evidence-current.md#batch2-frozen-records)。
>
> 当前系统能力、主要缺口和明确待办只由本页汇总；唯一执行顺序见 [Scene 兼容执行路线](../roadmap/scene-compatibility-roadmap.md)，精确 App、矩阵、报告与运行身份统一见 [运行证据索引](runtime-evidence-current.md)。路线只拥有 V0-V5 顺序，不复制或改写 current capability；逐批迁移过程只从[统一历史索引](../../history/README.md)追溯，不得覆盖当前结论。

本表把已收集的 Wallpaper Engine 作者语义逐项映射到 MyWallpaperX 当前代码、运行证据和下一道验收门。详细语义仍以同目录专题文档为准；这里回答三个问题：官方是否有这项能力、当前播放器走到哪一级、下一步补什么公共能力。


专项 `L0–L4` 按各专项自己的等级定义解释；运行证据深度按 [S0–S5](runtime-evidence-current.md#evidence-levels) 解释，两者不机械换算。`recognized` 只表示识别，`wired` 只表示接线，两者均不单独证明已执行或可见。系统行的等级、支持子集、缺口与升级门一同读取；日期、route 数和单样本 PASS 不能替代当前行为证据。

<a id="route-mapping"></a>

## 8. 现役路线映射

本页不再维护 B/R/Coverage-first 实施顺序。current capability、边界与待办仍由本页汇总；[Scene 兼容执行路线](../roadmap/scene-compatibility-roadmap.md)只拥有 V0-V5 的执行顺序和结果声明口径，其中任何能力族摘要都只是返回本页/专项表的导航，不是第二份 current 状态：

- V0：ordinary authored shader/material 通用编译、Program、GPU 与 compositor；
- V1：ordered pass、FBO、copy/swap/compose/history/named dependency；
- V2：真正 ECMAScript VM、handle、event、timer 和 mutation lifecycle；
- V3：Particle component registry/interpreter；
- V4：properties、pointer、audio、media、text 与 provider；
- V5：Puppet、lighting/HDR、3D、RGB、offline、性能与发行。

所有后续 V1–V5 原子都不得按 Effect 名称新增 strict backend；普通作者程序优先进入通用 backend，一个 stage/quad 失败只收窄到真实 effect/依赖面。当前段位和下一 atom 只由[现役路线](../roadmap/scene-compatibility-roadmap.md)选择，旧 B/R 标签仅用于追溯已有证据包。

## 9. 更新规则

1. 每次 Scene 能力提交必须更新本表对应行和精确边界；只更新开发流水账不算完成。
2. 本页系统行升级必须写明其 bounded 子集、结构/执行/可见证据和未证明边界；专项 `L0-L4` 只按该专项自己的等级定义升级，不得套用另一专题的同名阈值或机械换算为 `S0-S5`。
3. 新发现的官方能力先补 [官方页面全目录](../history/reference/official-page-catalog.md)、[页面能力映射](../history/reference/official-page-crosswalk.md) 和专题语义，再进入本表；私有字段按 [资料来源与证据索引](../development/source-index.md) 标证据等级。
4. 当前 baseline、矩阵报告、测试总数和签名 App 身份只以 [运行证据索引](runtime-evidence-current.md) 为主答案；本表只维护系统摘要与专项入口，带日期的文档全部属于 history。语义自动门校验布局合同与相对链接，不假装同步这些动态事实。
5. 开发开始顺序：先看[现役路线](../roadmap/scene-compatibility-roadmap.md)的当前可见目标，再从本表和专题合同定位首断边；不得按本表行号或旧批次标签排队，也不得凭截图写视觉特判。
6. 总表每行只允许一个本行摘要等级；若同一能力同时存在 IR、wired、executor 或 visible 子集，必须拆行或明确写成 bounded current + missing remainder，不能把不同专项的 `L`/`S` 拼成一个可比较等级。
7. 每行至少要能追溯到专项表中的代码、测试和运行证据；只有 parser 或结构时不得写成执行支持。
