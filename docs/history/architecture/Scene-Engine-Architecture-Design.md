日期：2026 年 11 月 1 日

产品目标：在原生 macOS 壁纸应用中，持续扩展 Wallpaper Engine Scene 内容兼容性，同时控制能耗、启动成本和维护复杂度。

## 1. 产品目标与兼容承诺

### 1.1 用户可见结果

用户选择壁纸后，应用应当正确显示内容，响应作者提供的设置与交互，在多显示器及休眠唤醒后保持合理行为。运行成本应与正在播放的内容相关，静态内容、暂停内容和关闭的管理界面不产生持续的无用工作。

Scene 兼容需要同时覆盖以下维度：

| 维度 | 需要一致的内容 |
| --- | --- |
| 内容读取 | 文件格式、项目入口、包资源、依赖与版本 |
| 场景语义 | 图层、父子关系、坐标、相机、变换、可见性 |
| 图像与几何 | 纹理、模型、字体、视频纹理、变形和粒子几何 |
| 渲染 | Shader、材质、采样、混合、遮罩、深度与多 Pass |
| 动态行为 | 时间轴、粒子更新、脚本、动态建模和事件顺序 |
| 外部输入 | 鼠标、用户属性、系统音频、媒体事件和显示尺寸 |
| 生命周期 | 初始化、暂停、恢复、销毁、切换和资源释放 |

“打开文件”“编译成功”“出现非黑画面”分别只能证明其中的一部分。

### 1.2 将完全兼容转化为可验证的目标

确定一个参考客户端版本及其内容版本范围，并记录对应基础资源版本。能力表按语义登记，不按壁纸名称登记。每项能力分别记录：已实现、语义测试通过、真实画面通过、性能已测，以及已知限制。

完整兼容应指约定范围内的格式、行为和可见结果通过验证。后续客户端增加的新功能进入新的兼容范围。第三方在线服务失效、缺失字体、缺少基础资源和 macOS 无对应公开系统能力，应分别标记原因。

### 1.3 本次设计的边界

本方案负责 Scene 播放内核及其宿主接口。Web 壁纸由独立浏览器后端处理；壁纸库、下载、账号和创意工坊访问属于应用服务。导入编辑器、视频导出、屏幕保护程序和锁屏展示是独立宿主能力，不能由桌面播放通过推导其可用性。

首版优先交付播放器。通过复用运行内核支持预览和验证，但不同时建设通用游戏引擎、完整编辑器或跨平台图形抽象。

### 1.4 证据如何影响设计

| 证据 | 可以支持什么 | 使用边界 |
| --- | --- | --- |
| 官方公开页面与类型声明 | 作者 API、事件、类型和公开能力 | 不自动提供私有格式、数值公式或全部顺序 |
| 固定客户端静态研究 | 版本有界的结构和行为线索 | 不能直接升级为像素或时序等价结论 |
| 官方 changelog 与编辑器字符串 | 能力范围、字段名称、演进和待验证问题 | 不从名称反推公式，不把旧实现顺序当开发顺序 |
| 第三方结构研究 | 核对职责、信息传播和常见失败位置 | 不作为官方行为真值，不复制其实现 |
| 自有语义用例与官方同输入结果 | 可观察行为、顺序、数值和画面对照 | 结论限于记录的版本、输入及环境 |

授权目录中的主要官方客户端研究固定于 Wallpaper Engine 2.8.42；第三方研究也绑定特定 revision。它们不能说明 MyWallpaperX 当前实现状态。文中以独立架构承接研究问题，不跟随链接扩读其他仓库文档。

## 2. 核心设计决定

| 决定 | 推荐方案 | 原因与代价 |
| --- | --- | --- |
| 主要实现语言 | Swift 6 语言模式，选定并固定工具链 | macOS 专属，减少系统接口和内存所有权转换；实时路径需主动控制分配与复制 |
| 图形后端 | 原生 Metal | 直接面向 Apple GPU；无需维护其他平台后端 |
| GPU 语言 | 自有程序使用 MSL，作者 Shader 经兼容前端转换 | 保留作者可编程能力，避免逐效果改写 |
| 第三方编译库 | 局部 C++，优先 glslang 与 SPIRV-Cross | 复用编译基础设施；约束跨语言接口及版本 |
| SceneScript | JavaScriptCore 优先，P0 验证模块、对象与执行行为 | 系统集成直接；宿主 API 和语言适配需要单独实现 |
| 组件组织 | 轻量节点、类型化存储、显式执行计划 | 支持大量组合，保持所有权和更新顺序清楚 |
| 渲染组织 | 准备好的 Pass 依赖与唯一最终合成出口 | 正确表达图层引用、多 Pass 和历史反馈 |
| 并发 | 后台准备，单场景串行更新，GPU 异步执行 | 减少锁、竞争和逐节点任务开销 |
| 缓存 | 缓存昂贵准备结果，失败后沿原链重建 | 加速启动；缓存不成为播放许可 |
| 初始进程形态 | Scene 与应用同进程，场景工作离开主线程 | 成本最低；强制终止失控脚本的产品要求在 P0 决定是否改为辅助进程 |
| 构建组织 | 少量 Target，内部先按目录划分职责 | 保留编译与测试边界，避免为每个组件建立库或服务 |

macOS 26 上的 Apple Silicon Mac 支持 Metal 4，但具体纹理格式和高级功能仍应查询设备能力。API 版本统一不代表所有硬件特性相同。图形实现按真实收益使用新能力，不强制引入所有新机制。[Apple Metal 支持范围](https://support.apple.com/en-hk/102894)、[Metal 能力表](https://developer.apple.com/metal/capabilities/)

### 2.1 语言方案的取舍

| 方案 | 适用条件 | 本方案选择 |
| --- | --- | --- |
| Swift 主体，局部 C++，Metal | macOS 专属、原生交互、希望减少语言边界 | 推荐 |
| C++ 场景内核，Swift 宿主，Metal | 已有成熟 C++ 内核、团队以 C++ 为主或明确需要跨平台 | 可行，但不预先引入 |
| Rust 主体，Swift 宿主，Metal | 团队已熟悉 Rust，且关键依赖接入成本可控 | 暂无足够收益支持再增加语言边界 |
| 通用游戏引擎作为 Scene 内核 | 可以接受其场景、材质和生命周期模型 | 需要大量语义映射；本方案直接实现所需能力 |

不能仅凭语言推断速度。先测量 CPU 更新、JS 桥接、GPU 工作、资源上传、同步等待和持续分配，再决定优化位置。

### 2.2 Swift 与 C++ 的边界

跨语言接口只传递 Shader 源码、编译选项、编译产物、反射结果和错误信息。一次编译任务批量进出，普通帧不遍历 C++ AST 或通过桥接逐个读写材质参数。

本方案默认给第三方编译库提供一个窄 C 接口，内部捕获 C++ 异常并转成结果。若直接 Swift/C++ 互操作能显著减少代码，可在原型证明后替换接入方式，避免同时保留多套包装。Swift 官方说明了互操作的类型、异常和容器性能限制。[Swift C++ 互操作约束](https://www.swift.org/documentation/cxx-interop/status/)

## 3. 总体数据流与职责边界

```text
项目入口与资源来源
        │
        ▼
Content：读取、解析、解释格式版本
        │ SceneDefinition 与解码资源
        ▼
Preparation：解析引用、属性绑定、更新顺序和渲染依赖
        │ SceneProgram
        ├──────── Shader 编译与反射
        ▼
SceneSession：装配运行状态和 GPU 驻留资源
        │
        ├── SceneInstance：脚本、动画、变换、粒子、属性
        │          ▲
        │          └── 本帧时间、输入、音频、外部事件
        ▼
MetalRenderer：执行计算和渲染 Pass
        │ 最终场景纹理及完成信息
        ▼
macOS 宿主：尺寸适配、桌面表面、发布与展示
```

依赖向内容更明确的方向推进。Content 不访问 NSWindow，Runtime 不读取项目 JSON，Graphics 不按资源路径猜测视觉行为，宿主不管理场景节点。

宿主与 Scene 的交互保持有限：加载、设置输出尺寸、更新用户属性、输入事件、播放状态和释放。音频与媒体服务提供数据，由 Scene 解释这些数据如何影响内容。

### 3.1 两种计划分别解决不同问题

更新计划描述状态何时变化、何时被读取。渲染计划描述图像或缓冲依赖和绘制顺序。父子层级描述空间关系。这三者保持联系，但各自有明确用途。

同一个图层可以跟随父节点移动，又将另一个图层的输出作为特效输入。一个不可见节点也可能被脚本读取，或为其他 Pass 提供图像。是否参与更新和是否在最终画面直接出现，分别判断。

### 3.2 模块与 Target

目录是职责划分，Target 是构建边界。初期可以采用 App Target、SceneEngine Target、ShaderCompilerBridge Target，以及测试 Target。SceneEngine 内部再分 Core、Content、Preparation、Runtime 和 Graphics。

当编译时间、第三方依赖或独立测试形成实际收益时，再拆分 Target。不要用“模块化”解释一对一转发层、每类型一个管理器或无消费者的接口。

## 4. 核心数据模型

| 数据 | 主要内容 | 可变性与生命周期 |
| --- | --- | --- |
| SceneDefinition | 解析后的节点、材质引用、动画、脚本与版本语义 | 准备阶段使用，可释放无后续用途的数据 |
| SceneProgram | 节点布局、类型数据定义、绑定、更新计划、渲染计划与资源需求 | 准备后稳定；结构改变时替换受影响部分 |
| SceneInstance | 当前属性、变换、时间轴、粒子、脚本和动态对象 | 单场景执行域中更新 |
| SceneGPUState | 实例缓冲、中间纹理、历史纹理及实例资源引用 | Graphics 管理，随会话和 GPU 使用期存续 |
| FrameContext | 本帧播放时间、步长、视口、输入与音频引用 | 小型数据，本帧只读 |
| SceneSession | 装配 Program、Instance、GPUState 与播放状态 | 场景会话的根所有者 |

SceneProgram 表达语义和逻辑资源引用，不包含 NSWindow 或宿主控制器。GPU 对象留在 Graphics 所有的状态中，准备出的材质布局通过明确接口连接后端。

FrameContext 只传递消费者所需的少量输入，不复制整个场景。Renderer 在同一执行域中消费准备数据和可复用缓冲；如果未来并行编码，再为真实并发的部分建立最小快照。

属性系统定位到类型化状态本身，不再同步保存一份包含全部当前值的通用字典。GPU 参数缓冲是对应状态的消费产物，作者初值用于初始化或明确回退；三者的用途不能混成多个可写权威。

### 4.1 身份与引用

场景身份、节点身份和资源身份分别定义。名称用于作者查找与诊断；内部已解析的绑定使用轻量 ID 或索引。重复名称、大小写和查找范围按参考语义实现，不自行假定名称全局唯一。

脚本跨帧引用的动态节点需要稳定句柄。删除后被旧引用访问时，在句柄解析入口识别失效；内部同一次同步调用不再层层重复检查。若使用可复用槽位，代次只用于防止旧引用误指向新对象。

### 4.2 类型与默认值

外部数据中的缺失、显式空值、零值和未知字段分别处理。默认值由格式版本及具体属性语义决定，集中在解析或准备入口补齐，运行时消费完整类型。

文件偏移、长度和索引边界在解析时检查。脚本动态写入的值在属性桥接处转换。不要把所有内部数值操作都包装成通用验证链。

### 4.3 动态修改

普通属性写入修改状态；改变 Shader 变体、资源或拓扑的操作进入明确的结构修改路径。修改在与参考行为一致的边界生效。脚本要求立即读回的数据先在运行状态体现，GPU 准备可以按依赖延后完成。

避免任意写入都触发全场景重建，也避免用“下一帧统一生效”覆盖本应立即可见的脚本语义。

## 5. 坐标与基础语义合同

必须在初期建立坐标合同，并用最小场景验证。图形后端统一内部表达，兼容前端解释作者语义，最终显示适配由宿主负责。

| 项目 | 需要确定的规则 |
| --- | --- |
| 2D 坐标 | 原点、轴方向、项目尺寸、图层锚点与单位 |
| 3D 坐标 | 手性、前向轴、相机朝向、角度单位 |
| 矩阵 | 行列布局、组合顺序、局部与世界变换、父级缩放 |
| 透视与深度 | 投影约定、近平远平面、深度范围、深度写入 |
| 纹理坐标 | 原点、翻转、图集子区域、旋转、边缘填充 |
| 视口 | 项目像素、逻辑点、实际输出像素、显示缩放 |
| 鼠标 | 桌面坐标转换、归一化、跨屏与命中区域 |
| 颜色 | 输入色彩信息、运算空间、混合空间、最终输出 |

集中完成坐标转换，尽量通过矩阵、采样变换和编译适配表达。逐个效果中的临时翻转或额外乘系数会使错误相互抵消，必须避免形成长期路径。

适应、裁切和拉伸虽然由宿主配置，但相关视口变化必须进入 Scene 的相机、屏幕参数和输入转换。只在最终显示时缩放，而脚本和命中测试继续使用旧映射，会使画面与交互错位。

## 6. 组件分类与组织

### 6.1 分类原则

组件按实际执行能力划分。一个资源文件、一个特效名称或一个作者图层配置不自动对应新的 Swift 类型。组合数据能够表达的变化，继续由组合表达。

| 分类 | 数据与行为 | 主要所属位置 |
| --- | --- | --- |
| 节点公共状态 | 身份、父子关系、变换、可见性、图层顺序 | Runtime 节点与变换 |
| 图像实例 | 图像、精灵帧、材质绑定、局部几何 | 图像运行与 Graphics |
| 文本实例 | 内容、样式、排版、字形与纹理引用 | Runtime 文本与 Graphics |
| 模型实例 | 网格、子材质、骨骼、动画和实例状态 | Runtime 模型与 Graphics |
| 粒子实例 | 发射、粒子状态、操作列表、绘制数据 | Runtime 粒子与 GPU 程序 |
| 相机与灯光 | 投影、朝向、照明参数、阴影需求 | Runtime 视图与光照数据 |
| 行为绑定 | 时间轴、用户属性、脚本和输入 | Runtime 对应行为 |
| 媒体状态 | 视频时间、声音播放、音频输入需求 | Runtime 媒体与平台媒体后端 |
| 特效描述 | 参数、输入、Pass、目标与历史需求 | Preparation 与材质 |
| 共享资源 | 纹理、网格、字体数据、Shader 产物 | 内容资源与 Graphics 缓存 |

这是目标能力的组织表。具体格式和能力覆盖仍由兼容基线逐项确认。

### 6.2 轻量节点与类型化存储

节点保存公共状态及类型数据引用。粒子、模型、文本等专属数据集中存储，允许连续遍历与批量操作。低频且复杂的状态可以使用对象，实时数据优先采用结构体与连续缓冲。

初期只为实际存在的多种类型实现所需存储，不预先创建自动注册、查询语言、依赖注入容器或通用 ECS 调度器。一个局部枚举、类型存储及明确分派能承接时，直接使用。

### 6.3 三类关系

空间关系由父子层级表达；状态读写顺序由更新计划表达；图像和 GPU 资源依赖由渲染计划表达。所有关系在创建、删除或相关结构变化时维护，不每帧从全部作者数据重新推导。

### 6.4 新增能力应该影响哪里

| 新需求 | 应当主要修改的位置 |
| --- | --- |
| 新粒子力场 | 粒子操作定义、准备和执行 |
| 新材质参数 | 参数解析、布局和属性绑定 |
| 新特效组合 | 材质、Shader 与 Pass 描述 |
| 新场景对象类型 | 专属类型数据、准备和更新或绘制 |
| 新脚本函数 | SceneScript 绑定与对应的运行时操作 |
| 新跨帧反馈 | 渲染计划、历史资源与重置行为 |

新增能力若普遍要求修改窗口、播放调度、下载服务和资源缓存，应先检查职责泄漏。

## 7. 内容读取与资源解析

### 7.1 单一读取入口

项目加载器确定入口、格式版本与资源来源。包读取器负责包结构、条目和解压；具体解码器负责纹理、网格、动画等格式。上层消费解码结果，不再次解释二进制头。

采用按需读取：先加载项目和必要定义，再读取引用的资源。建立包条目索引即可定位内容，不因播放一个壁纸而解压整库、复制全部依赖或遍历全部无关条目。

### 7.2 资源来源与优先级

资源可能来自项目包、项目目录、明确依赖包和基础资源集合。建立唯一 ResourceResolver，按参考语义确定来源优先级，并保留解析来源供诊断。基础资源版本是兼容基线的一部分。

作者资源覆盖基础资源的条件、大小写、分隔符和相对路径语义必须有用例。不要把 Windows 风格路径直接交给 macOS 文件系统，也不要把所有资源名无条件转小写后丢失原始映射。

文件系统访问在入口把逻辑路径解析为允许来源中的资源。内部使用已经解析的资源引用，避免每次采样或绘制时再次认证路径。

### 7.3 资源完整性与可选内容

导入事务可以确认需要的内容完整性，播放阶段按实际资源消费处理缺失。可选缩略图、缓存和无关文件不影响有效场景播放。基础材质或必需模型缺失时，给出明确的受影响节点与资源来源。

无法合法随应用提供的基础资源，应明确由用户提供或以独立实现的资源替代；分发方案需要单独确认授权。不能假定创意工坊项目总是包含完整基础依赖。

### 7.4 格式演进

版本差异在格式解析处解释，向内输出统一语义。只有实际语义不同才保留版本分支；行为相同的差异在入口消除。未知内容报告具体能力缺口，避免将所有未知值吞成同一个默认值。

## 8. 场景准备与执行计划

准备阶段完成节点解析、资源引用、材质参数、属性目标、动画轨道、粒子操作、脚本模块需求及渲染依赖的解析。目标是让普通帧通过明确索引和句柄执行。

### 8.1 属性绑定

将“某节点的某属性”准备为目标句柄、属性标识、值类型及写入规则。常见动画和用户属性绑定直接访问对应状态。动态按名称查询保留给确实需要它的脚本操作。

不为每个浮点参数创建独立对象；标量、向量、颜色、布尔、枚举和资源引用有各自明确表达。

### 8.2 更新计划

计划记录行为的执行顺序及需要更新的类型范围。能批量的工作在兼容顺序允许的范围内合并。脚本的任意动态读取不能靠猜测静态依赖重新排序，默认保留参考可观察顺序。

### 8.3 渲染计划

计划记录绘制和计算 Pass、输入输出、目标尺寸规则、格式需求及跨帧资源。普通同帧依赖形成可执行顺序；反馈通过明确的上一帧资源表达，避免用循环依赖掩盖时间语义。

### 8.4 准备的失效范围

| 变化 | 最小处理范围 |
| --- | --- |
| 位置、颜色、透明度 | 更新对应运行状态或参数区域 |
| 文本内容、字体、排版约束 | 重做受影响文本排版与图形资源 |
| 输出尺寸 | 更新视口及受尺寸影响的目标和参数 |
| 纹理内容 | 更新该资源与依赖它的绑定 |
| 材质变体 | 准备该材质及受影响 Pipeline |
| 动态增删节点 | 更新相应节点、任务和渲染依赖 |
| 基础格式解释改变 | 使对应版本的准备缓存失效 |

失效范围由实际消费者决定。初期用局部脏标记和明确修改入口即可，不预先建设通用增量计算框架。

## 9. 时间与普通帧执行

### 9.1 时间域

SceneSession 保存一个播放时钟，输入来自单调时间。FrameContext 同时提供本帧有效步长与累计播放时间。现实日期时间独立采样，不能用播放累计值代替。

统一时间来源允许存在多个局部时间：图层动画时间、粒子系统时间、视频播放位置和动画片段时间由各自状态从播放输入推导。局部速率与暂停不创建第二个全局时钟。

暂停恢复时重置采样基线，避免将暂停期间全部时间作为首帧步长。是否存在暂停渐变、速率平滑和长帧限制，要用参考结果确定具体行为；不从静态研究复制私有常量。

### 9.2 帧阶段与可观察顺序

每帧先接收已完成的外部结果，随后按已确认的行为顺序处理事件、时间轴、脚本与模拟，再完成变换、绘制数据和 GPU 提交。阶段名称只是组织，具体覆盖和可见点由兼容合同确定。

授权静态研究支持媒体事件、动画事件、音频数组刷新、timer、普通 update 与延迟销毁之间存在顺序关系。把这些关系转为区分性用例：同一回调写入的值由谁在本帧读到，新对象何时 init、update 和显示，销毁何时使引用失效。验证前不任意按组件类型重新排序。

### 9.3 模拟步长

渲染帧率与模拟步进分别建模。动画曲线可按时间求值；粒子、弹簧和骨骼物理需要按对应语义采用步进或子步。CPU 与 GPU 实现必须消费相同的时间定义。

不能以“固定步进更稳定”为由改变所有作者脚本的 update 次数，也不能把预热实现成只增加累计时间。预热应通过对应模拟路径形成状态，预热范围与资源成本在场景准备和首次激活时安排。

零步长重绘是有效需求，例如输出重新呈现但内容不推进。此时不要重复派发只应发生一次的事件。

时间轴需要明确 Loop、Mirror、Single、起始暂停、随机起帧、速率、关键帧插值及事件跨越。大步长跨多个关键点时按事件语义处理；seek、反向和循环边界分别验证。只有时间变化的动画轨道参与更新，用户属性与脚本对同一目标的覆盖顺序保持可观察一致。

### 9.4 普通帧成本

普通帧不解析 JSON，不编译 Shader，不扫描资源目录，不重新发现脚本导出，不整图序列化或哈希。只更新正在活动、被事件改变或被实际消费者需要的状态。

静态变换可以复用；引用时间的 Shader 仍需按时绘制；隐藏的纹理提供者可能仍需产出。以真实需求区分这些情况，避免简单用 visible 统一停止所有工作。

## 10. SceneScript 与属性系统

### 10.1 以属性绑定为基本身份

脚本绑定记录包含源码或模块引用、宿主对象、目标属性、作者初值及目标类型。宿主对象可以是图层、特效、材质参数或场景全局属性。绑定位置由合法属性结构确定，不能只搜索任意 `script` 键并猜测目标。

保留 `init(value)` 与 `update(value)` 的 typed return 写回语义，同时支持脚本直接修改其他属性。脚本产生的修改直接作用于同一个 SceneInstance，避免维护第二棵脚本场景树。

作者初值与当前运行值分别有用途。字符串是否表示向量，需要结合目标属性类型判断；普通文本中存在空格不构成向量识别条件。授权 binding-target 研究提供了上述输入形态与反例。内联脚本与绑定目标研究

### 10.2 按实际事件注册

模块完成求值后解析导出的事件，只把存在的 update 加入逐帧工作列表。用户属性、尺寸、鼠标、媒体和动画事件使用各自监听列表。只响应属性变化的脚本在普通帧没有无意义的空调用。

初始用户属性通知、首次 resize 是否派发以及 init 与其他事件的相对顺序，按版本化 API 合同与用例确定。回调载荷中的“变化项”与完整当前属性快照分别表达。

### 10.3 VM 与模块环境

优先验证系统 JavaScriptCore。每个实际需要脚本的场景建立自己的 VM 生命周期；模块和每个属性绑定的环境按共享与隔离语义组织。`shared` 的共享范围限于对应场景，不能意外跨壁纸。

模块缓存按解析后的资源身份及所需环境区分。实现 import/export、内建模块、循环引用、错误定位和重新加载语义。若系统公开接口不能直接承接所需模块行为，使用成熟 ECMAScript 解析基础进行必要的模块适配，不用字符串替换处理完整语言。

固定客户端 changelog 指向 V8，这只说明参考环境，不直接决定本方案的 VM。JavaScriptCore 是否合适由模块、对象、性能和中断能力的 P0 用例决定。[SceneScript 公开参考](https://docs.wallpaperengine.io/en/scene/scenescript/reference.html)、[JavaScriptCore](https://developer.apple.com/documentation/javascriptcore)

### 10.4 宿主 API 能力族

| 能力族 | 需要承接的职责 |
| --- | --- |
| 基础值 | Vec2/3/4、Mat3/4、标量广播、构造、返回值和对象身份 |
| 当前绑定 | 当前图层、特效、材质、属性及动画引用 |
| 场景访问 | 查找、顺序、创建、删除、可见性和父子关系 |
| 动态几何 | 网格创建、同布局数据更新、结构替换和释放 |
| 时间与任务 | runtime、frametime、timer、取消函数及 owner 生命周期 |
| 音频 | 注册、分辨率、左右声道与平均数组 |
| 输入 | 实时状态、事件快照、命中与传播 |
| 媒体 | 播放状态、元数据、封面与时间线事件 |
| 存储 | 每壁纸、每屏幕和共享范围的持久化 |
| 用户操作 | 仅用户配置的快捷方式，通过宿主执行 |

声明文件中的继承聚合便于作者使用，不要求内部创建一个同时包含所有类型字段的巨大 Layer 类。外部表面保持兼容，内部按实际类型分派。[本地 v2.8 声明快照](../../scene/development/reference/lib.sceneScript-v2.8.d.ts)

### 10.5 Timer 与销毁

Timer 归属于脚本 owner，随 owner 移除而取消。消费场景播放时间，不借用系统定时器绕过暂停。长帧是否追补、回调中新建任务何时进入执行、取消函数的行为，都建立正反用例。

动态 owner 的创建、遍历和销毁是显式生命周期。保证 destroy 只执行一次，并在后续事件分发前处理真正失效的引用。不要以一次遍历快照或统一下一帧提交，未经验证地改变新 owner 的同帧行为。

### 10.6 桥接与内存

缓存已解析的函数与属性访问入口，复用稳定音频数组，减少每帧标量和向量桥接临时对象。优化不能改变对象身份、返回新对象或直接赋值等可观察行为。

JS 与 Swift 对象的持有关系单独设计，避免回调闭包与上下文形成循环引用。Apple 明确要求正确处理导出对象和 JSValue 的引用关系；同一 VM 中的并发访问也会串行等待。[JSVirtualMachine](https://developer.apple.com/documentation/javascriptcore/jsvirtualmachine)

### 10.7 异常与失控脚本

脚本异常记录绑定目标与调用位置，按错误影响范围保留可用内容。具体采用作者值或最后一次有效值，应成为明确的项目策略并接受对照，不宣称天然等同官方行为。

无限循环可能使场景执行域无法返回。异常处理器不能解决这个问题，也不能安全强杀同进程线程。P0 必须验证可公开使用的执行中断方案；若产品要求可靠强制停止任意第三方脚本而当前 VM 无法提供，则在量产实现前选择可终止 VM 或将完整 Scene 会话移到专用辅助进程。不能带着这一限制承诺可靠隔离。

## 11. 渲染依赖与合成

### 11.1 三段绘制职责

图层源绘制生成自身内容；图层特效在相应工作空间执行；图层最终合成使用正确几何、相机与材质状态进入场景。随后才进入场景级后处理和最终输出。

中间 Pass 的覆盖写入与最终图层的混合、alpha 写入、深度和裁剪分别准备。最终输出不能遗留中间 Pass 的状态。

### 11.2 Pass 与资源身份

为材质绘制、copy、swap 和显式函数调用建立明确表达，保留定义 Pass 的 ordinal 与实例 override 对应关系。资源槽位保留空槽和稀疏编号。

copy 表达内容传递；swap 表达逻辑资源映射交换；compose 表达合成链的可见边界。授权静态研究说明它们在固定客户端并非同一种执行操作，具体像素、别名和错误输入结果仍需独立验证。客户端运行结构研究

同一逻辑目标的不同写入拥有明确前后关系。历史资源、资源映射与底层纹理分开管理；resize 是否保留逻辑映射、重载是否重置历史，都进入生命周期用例。

### 11.3 条件与工作空间

条件在受影响的 Pass、目标或绑定纳入执行计划前求值。运行期 combo 改变时更新受影响计划与资源。静态 false 分支不分配无消费者目标。

保留图层源尺寸、特效工作尺寸、场景逻辑尺寸、输出尺寸与实际分配尺寸。相应参数和相机明确使用哪一种尺寸。

### 11.4 合成层

至少分别表达指定尺寸的子对象合成、对齐整个壁纸的合成、对齐屏幕的后处理，以及内建后处理控制位置。背景捕获、子层预渲染和特效启用是可组合的语义，不能合成一个“全屏图层”标志。

屏幕对齐层不随壁纸相机移动，壁纸对齐层参与相应映射。各类型的确切范围通过作者定义和正反场景确定。合成层作者面研究

### 11.5 Clear 与历史

区分资源新建或重建后的初始化、每帧首次写入、保留既有内容、显式 clear 命令和深度初始化。FBO 上出现 clear 字段不自动意味着每帧清屏。

历史反馈声明前一帧数据及重置条件。物理纹理按存活区间复用；作者要求独占或需要保留历史的目标维持隔离。对有可观察共享语义的目标，不做改变行为的跨实例合并。

### 11.6 唯一最终输出

所有场景内容经过同一最终合成路径。桌面、预览、截图和离屏验证消费同一语义出口。宿主传入最终绘制目标且无需额外处理时，可以直接写入，避免强制增加一次全屏复制。

诊断截图是按需 GPU 读回。正常播放不把最终画面取回 CPU。

## 12. 材质与 Shader 编译

### 12.1 材质完整表达

材质包含 Shader 变体、常量布局、纹理及 sampler、混合、alpha 写入、深度、裁剪与 Pass 特性。Shader 能编译只证明语言链可用。

参数来源包括作者值、用户属性、脚本、内建帧数据、资源尺寸和 Shader 默认值。准备阶段确定来源与位置，运行时只更新对应区域。

### 12.2 编译路线

```text
作者 Shader、include、宏、元数据和材质配置
                    ↓
兼容前端：来源解析、有效声明与语义适配
                    ↓
                标准化 GLSL
                    ↓ glslang
                  SPIR-V
                    ↓ SPIRV-Cross
                    MSL
                    ↓ Metal 编译
          Pipeline 与反射后的资源布局
```

glslang 提供 GLSL 前端及 SPIR-V 生成，SPIRV-Cross 提供 MSL 生成和反射。使用这一中间格式无需引入 Vulkan 运行时。[glslang](https://github.com/KhronosGroup/glslang)、[SPIRV-Cross](https://github.com/KhronosGroup/SPIRV-Cross)

### 12.3 兼容前端

保留 include 来源、注解、有效宏环境、纹理槽身份和未知元数据供诊断。宏默认值、显式 combo 和条件分支共同决定活跃声明；可选纹理的作者存在性与默认资源回填要分清，避免填了默认纹理后错误启用功能。

普通词法和语法问题采用成熟编译器能力，必要的元数据解析做成有限、清楚的逻辑。新增转换规则必须对变量改名、等价表达式和邻近反例成立，不按 Shader 文件名、资源路径或固定源码片段选择算法。

`[PASS]` 等研究中出现但公开语义不完整的元数据，保真记录并单独验证。不能因为发现一个 token 就创建无限扩展的通用调度语言。

### 12.4 变体与绑定

变体身份包含最终有效的宏、Shader 内容及传递依赖、顶点布局、渲染状态、目标格式和编译环境中真正影响结果的部分。限制预热为当前场景所需变体，避免枚举所有组合。

反射结果在准备阶段转成布局和绑定。普通帧不按参数名称搜索，也不遍历完整反射结构。Swift 与 MSL 的标量、向量、矩阵和数组对齐明确验证，不能依赖两边结构体天然一致。

### 12.5 编译失败

错误定位到源文件与 include 行、材质、变体和 Pass。可选特效失败时使用明确的局部降级；决定主体内容的必需材质失败时拒绝该候选激活。最后一次有效场景可继续展示，避免将空结果发布为新壁纸。

### 12.6 Shader 阶段与输入边界

上述转换链首先验证 vertex 与 fragment，计算程序按实际需要接入。geometry、tessellation 等其他阶段需要单独确认能力映射、输入输出和执行调度；不能从编译库“支持多种阶段”的总表推断每种阶段都能直接输出可运行 MSL。

绳索和拖尾等内建几何由明确的通用几何语义实现，可采用 CPU 或 Compute 生成顶点与索引，再进入普通绘制。对作者自定义的额外阶段，必须建立通用转换与宿主支持后才能登记兼容。不能用改成简单 quad 的方式隐藏缺失。

编译链以获得的作者源码和明确格式为输入。仅有其他后端编译产物时，不自动视为该路线已覆盖。Apple Metal shader converter 是另一种工具候选，有自己的输入格式、部署和调度约束；只有真实需求与原型支持时才采用，避免为了预防未知内容常驻两套工具链。[Metal shader converter](https://developer.apple.com/metal/shader-converter/)

## 13. 纹理与采样

纹理描述应保留存储格式、用途、物理尺寸、映射尺寸、mip、动画帧、UV 变换及色彩信息。某个数字格式不能单独决定它是颜色、法线还是数据。

### 13.1 GPU 格式策略

根据设备实际支持选择原生上传或加载阶段转换。转换后的结果可缓存；普通帧不重复解压或转换整张纹理。压缩块、mip 边界、3D 纹理和数组或帧布局分别解析。

保留资源实际存在的 mip；是否生成缺少的 mip 由作者和用途决定。不要为了统一流程给所有资源生成 mip 或统一缩小分辨率。

### 13.2 按槽传播采样语义

每个纹理槽拥有解析后的资源与 sampler policy。过滤、寻址、mip 和 comparison 等影响采样的字段进入对应 sampler 身份。某张纹理被多个材质使用时，各槽的消费方式可以不同。

纹理物理尺寸、有效内容尺寸、图集区域与最终显示尺寸沿绑定传播。跨平台方向规范化只在确定的边界完成，不根据“图片曾经翻转”再对所有 TEX 统一翻转。纹理与采样研究

### 13.3 动态资源

精灵序列、视频帧、用户图片、专辑封面、图层输出和纹理变体都是明确的资源生产者。保持稳定逻辑身份，变化时更新对应内容、尺寸或绑定。只有改变材质特征或依赖结构时才重新准备相关部分。

动态图片替换与视频替换分别处理。异步结果在发布入口确认仍属于当前资源请求，避免旧封面或旧视频帧覆盖新内容。

## 14. 粒子系统

### 14.1 定义与运行实例

ParticleProgram 保存已解析的发射器、初始化器、操作器、绘制器、control point 和子系统定义。ParticleInstance 保存活动粒子、局部时间、发射累积、随机状态、事件与子实例。

父子实例共享准备好的定义与不可变资源，保留各自的可变状态。重复触发的 child 可以在明确复位后复用，避免重新解析或复制整份定义。

### 14.2 操作列表与数据通道

按照作者顺序准备发射器、出生初始化器和每步操作器。不同发射器和操作器不能随意交换顺序；碰撞参与其规定的位置。只分配和更新实际使用的数据通道，例如没有旋转需求的定义无需承担完整角运动状态。

至少覆盖以下能力族，具体数值行为逐项验证：

| 能力族 | 关键事项 |
| --- | --- |
| 发射 | 盒、球、图层图像或网格，速率、序列与空间 |
| 初始化 | 寿命、颜色、大小、速度、旋转、偏移与继承 |
| 运算 | 运动、阻力、重力、噪声、振荡、remap 与群集 |
| 碰撞 | 有限或无限边界、单面性、空间、事件和反弹 |
| Control point | 位置与角度、父级继承、对象或输入驱动 |
| 子系统 | 静态 child、出生、跟随与死亡事件，状态继承 |
| 覆盖 | 颜色、速度、数量、寿命、大小、亮度和禁用规则 |
| 预热 | 通过真实模拟形成初始分布，保持子系统一致 |

### 14.3 Renderer 是几何能力

Sprite、SpriteTrail、Rope 和 RopeTrail 使用明确的几何表达。保留非方形纹理的宽高比、轨迹长度、顺序、朝向、UV、细分、淡出及法线切线。

一个定义可能组合多个 renderer。共享粒子状态，各自生成所需绘制数据。折射、光照与背景采样属于材质和依赖需求，不能仅靠 renderer 名称决定全部行为。

图层图像发射若依赖文字或变形后的几何，需要消费相应生产结果。CPU 模拟不能每帧为此读回全屏图像；按内容变化准备可采样数据，或把相关采样与发射移到 GPU，并验证同步与可见时机。

### 14.4 CPU 与 GPU 分工

先建立可测试的公共语义与数据布局，选择有收益且能保持事件顺序的操作迁移到 GPU。绘制几何和大量独立粒子更新适合优先评估；需要顺序事件或跨粒子依赖的操作单独分析。

迁移完成后退役无消费者旧执行路径。短期 CPU 对照只作为验证用途，不能永久维护两套具有不同结果的自动 fallback。

随机种子可在验证环境控制，但自有确定性不证明与参考客户端的随机序列一致。比较分布、轨迹、事件和画面时分别说明证据范围。

## 15. 模型与 Puppet Warp

模型、Puppet 和动态网格共用网格、材质、变换及绘制接口；各自独有的动画和变形语义留在对应运行模块。

### 15.1 导入与动画

读取已发布的网格、索引、子材质、骨骼、权重、绑定姿态、动画轨道和附加通道。播放器消费制作结果，不重新执行作者的建模、自动绑骨或深度图生成过程。

关键帧、动画层、混合、附件、IK、约束与物理的先后关系形成明确合同。骨骼矩阵按模型批量上传，蒙皮按子网格和材质正确消费。

### 15.2 Puppet 专属语义

Puppet 包括部件顺序、深度、纹理通道、嵌套裁剪、附件点、blend shape、blend rule、交互和骨骼约束。遮罩绘制与主体绘制使用一致的变形状态，防止动画时轮廓与遮罩分离。

未知动画通道保留身份与数据，报告受影响动作。授权研究中的 MDLA6 post-bounds 标量只证明存在及存储归属，消费含义尚未确定；不能把它当 padding 丢弃，也不能猜成深度后宣称该动作兼容。

### 15.3 动态网格

区分同布局数据更新与改变布局的结构替换。同长度、同格式的顶点或索引更新进入复用缓冲；改变子网格、格式或容量时走对应准备路径。遵守作者 API 的阶段约束，避免每帧重建完整模型。

### 15.4 照明与模型 Shader

按作者启用的模型与光源特征准备照明、阴影、投影纹理、雾、反射及体积光 Pass。每光源、每材质和全局设置分别保留。基础 PBR 或一个“通用模型 Shader”不代表所有专用模型材质已兼容。

## 16. 文本与字体

文本需要独立处理内容、字体、排版、字形呈现及特效。保留换行、对齐、宽度、行数限制、省略号、字距、行距、锚点、padding 和动态属性。

推荐优先使用 Core Text 完成 macOS 字体解析和 shaping，并验证与参考字体度量的差异；需要更精确的跨平台度量时再选择有实证收益的排版基础。[Core Text](https://developer.apple.com/documentation/coretext)

字形呈现根据目标兼容用例确定。授权 changelog 指向固定客户端的 MSDF 与轮廓、阴影、模糊特效演进；这要求验证距离场语义、padding 和缩放质量，但不能单凭它断言所有位图路径错误或复制其公式。文字与字体演进研究

对同一字体样式复用字形或排版结果；文本或排版参数不变时不每帧重新栅格化。字体缺失、替换和不支持字符应可诊断，使用系统替代字体时明确不保证像素一致。字体分发授权随资源方案确认。

## 17. 声音与视频纹理

### 17.1 声音

声音资源与播放 voice 分开。资源共享解码数据或流描述；每个播放实例拥有播放位置、循环、音量、速率、随机环境声与空间参数。按需要选择系统媒体 API，避免为每个声音独立建立全局音频设备。

场景暂停、作者停止和宿主静音分别表达。空间化消费正确坐标和 listener 状态。释放前停止实例，设备切换后按保存的播放意图恢复受影响部分。

### 17.2 视频纹理

优先采用 AVFoundation、VideoToolbox 与 Core Video 的适用路径，复用系统硬件解码能力。解码器是持续资源生产者，场景消费最新符合时序的帧；不在 draw 内创建播放器。

保留播放意图与实际帧就绪状态，处理循环、seek、速率、暂停、音轨和首帧。seek 或替换后旧帧不能回流。视频纹理只在取得新帧或需要重新绑定时更新 GPU 输入。

颜色矩阵、量化范围、方向和色彩元数据进入视频到纹理的转换。合法黑画面不能被通用“首帧非黑”规则永久挡住，首帧策略必须按实际播放器行为验证。

多屏共享视频需同时满足播放位置、速率、音轨与消费意图一致；只因文件路径相同就共享播放器会造成串台。

## 18. 系统音频与媒体输入

### 18.1 唯一音频分析来源

系统音频采集和频谱分析由应用级平台服务负责，Web 与 Scene 按实际需求消费同一来源。按需要启停，避免每个脚本、每个场景或每种频段重复 FFT。

macOS 可以通过 Core Audio taps 采集输出音频；用户授权与设备变化在平台服务处理，不进入每帧材质绑定。[Core Audio taps](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)

Scene 侧准备需要的频谱档位、声道与稳定数组，提供给脚本、Shader 和粒子。值域、频轴、投影和动态适应分别建模。

授权研究的后续更正指出：原始 FFT worker 的静态结果不能代表公开 AudioBuffers 全链，黑盒还观察到动态音量适应。因此不能简单认定“参考音频无平滑或无动态处理”。16/32 档投影算子等未定问题需要单音、双音和噪声区分实验，项目近似单独标记。

### 18.2 系统媒体

平台 adapter 发布当前歌曲、播放状态、封面和时间线的可用信息。macOS 公开能力或应用支持不足时，明确报告该能力不可用，不伪造事件或元数据。

异步封面与派生颜色在发布处核对当前媒体请求身份，防止上一首歌的结果覆盖当前歌曲。没有消费者时停止不必要的封面解码与分析。

### 18.3 存储与用户快捷方式

SceneScript localStorage 按壁纸和屏幕等约定范围隔离，内存状态及时可读，落盘合并写入；避免普通帧同步文件 I/O。共享范围的具体行为由用例确定。

用户快捷方式交给宿主执行，只允许用户明确配置的目标。场景脚本环境不获得任意操作系统命令或应用内部对象。入口完成目标解析与授权边界，内部不重复层层认证。

## 19. 缓存与资源生命周期

### 19.1 按产物缓存

| 缓存 | 内容 | 主要失效依据 |
| --- | --- | --- |
| 包条目索引 | 资源定位信息 | 包发生修改或导入替换 |
| 解码资源 | 纹理、网格、动画等 CPU 产物 | 来源修订及解码格式版本 |
| SceneProgram | 绑定、更新计划与渲染计划 | 场景、传递依赖及准备格式改变 |
| Shader 编译产物 | 标准化结果、MSL、反射等 | 有效源码、选项与工具链改变 |
| GPU 共享资源 | 纹理、网格、sampler、Pipeline | 资源用途、设备及实际描述改变 |
| 文本产物 | 排版、字形与 atlas | 文本、字体、样式和排版约束改变 |

不同缓存复用同一资源来源信息，不各自扫描整库。只缓存成本高于缓存管理的产物。

### 19.2 暖命中与修改检测

受管理的导入内容在导入、替换或明确修改时建立资源修订。可编辑目录通过文件变化通知和针对性检查使相关缓存失效。不要在每次启动为全部文件计算全文摘要。

需要内容摘要的编译键，在读取或导入实际依赖时生成并复用。缓存缺失、损坏或过期时沿原读取和准备链重建。可选落盘后台完成，不阻塞首帧。

### 19.3 所有权

会话持有其所需资源引用。共享缓存保留可共享的不可变产物；运行中的粒子、脚本、voice、播放位置和历史纹理属于具体实例。

缓存淘汰只释放缓存自己的引用，仍有使用者的资源继续存活。缓存条目数或内存压力可以限制驻留，但不据此让正在播放的场景突然失去资源。

### 19.4 GPU 使用期

CPU 停止引用不代表 GPU 已完成。会话释放和资源替换通过已有提交完成信息退役仍在使用的资源。避免每帧同步等待 GPU；回调只把完成事实送回资源 owner。

新资源就绪后替换对应绑定，旧资源在最后一次提交结束后释放。动态资源在实际发布边界检查请求身份，普通同步采样不重复检查全部代次。

## 20. 播放会话与场景切换

### 20.1 根所有者

应用播放协调者决定哪个会话属于哪个输出及其运行策略。SceneSession 只负责一个内容运行实例的准备结果、状态、GPU 资源和生命周期。

选择另一壁纸时，当前会话继续展示；候选独立准备必需内容。候选完成有效首帧后，在显示发布边界切换所有者，随后退役旧会话。候选失败只报告本次失败，不清空仍有效的当前内容。

连续选择 A、B、C 时，只有最后仍被请求的候选可以发布。请求身份在异步结果进入当前状态的地方检查，避免所有底层函数反复传入并验证同一个 token。

### 20.2 暂停、静音与停止

暂停影响时间推进、模拟与媒体播放；静音影响声音输出；停止与释放具有自己的清理语义。宿主统一汇总休眠、锁屏、用户操作和电源策略，再将最终意图传给会话。

局部系统仍保留作者状态，例如粒子停止发射但存活粒子继续运动。宿主解除暂停不能把作者已经停止的动画或声音全部启动。

### 20.3 恢复与失败

窗口重建、输出尺寸改变、媒体设备切换和 GPU 资源失败分别处理。只重建受影响资源族，保持能继续使用的播放意图与状态。确实需要完整重载时，显式走场景替换路径。

不以递归重试隐藏持续错误。恢复失败保留可诊断原因，由用户重试或选择其他内容。

## 21. 多显示器与 macOS 宿主

### 21.1 显示身份与输出模式

平台显示注册表唯一维护当前屏幕及其尺寸、缩放和稳定关联。瞬时屏幕编号不能直接作为持久设置身份。

| 模式 | 实例与输出关系 |
| --- | --- |
| 独立壁纸 | 每个独立播放意图建立实例，可共享不可变资源 |
| 镜像 | 只有状态、输入和时间语义允许时共享模拟或最终输出 |
| 跨屏 | 根据共同画布及各屏视口设计，避免多输出重复推进同一实例 |
| 预览 | 默认独立实例；明确共享时使用只读输出，避免扰动桌面交互 |

相同资源不等于相同实例。屏幕级 localStorage、鼠标、用户属性与视频播放位置可能要求隔离。

### 21.2 桌面窗口

AppKit 宿主负责桌面层级、Spaces、显示尺寸、窗口重建及实际展示。SceneEngine 不接触 NSWindow。行为必须在真实 macOS 桌面验证，包括显示器插拔、不同缩放、全屏应用、Mission Control、睡眠唤醒和管理窗口开关。

不依赖屏幕采集来常态判断壁纸可见性。系统通知、已知窗口状态和有限策略能解决的情况直接使用，避免引入持续截图与高频整机查询。

### 21.3 输入与桌面操作

桌面壁纸通常不能吞掉 Finder 或其他应用的正常输入。平台层确定实际可用的输入来源及交互资格，Scene 层负责坐标转换、命中、候选顺序、传播与捕获。

保留事件次序和按钮边沿。只传当前 pressed 布尔值会丢失两帧之间完成的点击。事件快照与实时 getter 分别表达。

visible、solid、传播及对象销毁是独立状态；隐藏节点不自动失去交互资格。命中应使用对应几何和相机，不能把所有旋转、透视或 Puppet 图层简化为世界空间 AABB 后宣称完整兼容。

### 21.4 帧驱动

使用适合目标系统的显示同步机制并结合用户帧率上限。一个运行实例每次推进只有一个 owner；多个输出可重复使用其状态或结果，不分别累计同一时间。

不可见或完全暂停时停止不需要的帧驱动。需要播放声音、处理独立事件或维持特定历史的内容，根据明确策略保留对应工作。

## 22. GPU 内存与颜色输出

### 22.1 分配与复用

初期采用简单的复用缓冲和少量在途帧，测量后确定容量。纹理、Pipeline、sampler 和中间目标在准备或结构变化时创建。常规 uniform 与实例数据写入可复用区域。

Render target 池按尺寸、格式、用途和存活区间管理。只在存在足够证据时引入 heap 别名、间接命令或复杂 GPU 调度。

以 3840×2160 为例，单张 RGBA8 纹理约 31.64 MiB，RGBA16Float 约 63.28 MiB，均未计 mip、对齐和驱动开销。两张全尺寸 RGBA16Float 目标已约 126.56 MiB。特效工作尺寸、HDR 中间格式和历史数量应进入明确的资源需求说明。

### 22.2 颜色与 alpha

分别规定颜色纹理、数据纹理、法线、视频和渲染目标的采样与写入解释。straight 与 premultiplied alpha、颜色写入与 alpha 写入、内部覆盖与最终混合都需要独立用例。

兼容目标优先决定运算空间。不能把所有作者效果统一改为某种“更物理正确”的线性混合后假定结果一致。

### 22.3 HDR 与屏幕

作者的 HDR 后处理设置、浮点中间缓冲和 macOS 显示 EDR 是三个不同层次。场景后处理按设置准备，最终出口根据输出能力执行明确的颜色转换与必要映射。

高亮保留、bloom、LUT、色域、曝光及显示转换顺序进入测试。避免在材质、最终合成和宿主重复 gamma 或 tone mapping。使用浮点缓冲或开启显示 HDR 也不能单独证明 HDR 兼容。

Renderer 按输出描述负责内容最终颜色转换，宿主负责匹配显示目标的颜色配置。诊断和导出必须声明观察的是转换前的场景结果，还是面向指定输出的最终结果，避免比较两个不同出口。

## 23. 并发与进程边界

### 23.1 执行域

| 执行域 | 工作 | 约束 |
| --- | --- | --- |
| App 主线程 | 界面、窗口、用户操作 | 不读取大包、编译 Shader 或等待首帧 |
| 后台准备任务 | 文件、解码、编译和无状态准备 | 只发布完整结果；可取消无消费者工作 |
| 场景串行域 | 事件、脚本、动画、模拟及指令编码 | 明确可变状态所有权，避免逐节点锁 |
| 平台媒体工作域 | 采集、解码、系统事件 | 提供稳定结果，不回调操纵场景树 |
| GPU | 计算、绘制、合成与必要转换 | 显式提交和资源使用期 |

不为一个组件创建一个线程。并发首先用于彼此独立的加载、解码和编译。多场景并行在内存、设备和真实 CPU 收益允许时启用。

### 23.2 同进程起步的实际限制

独立队列能保持界面响应，但无法在原生崩溃后保住应用，也不等于可以可靠终止失控 JS。开发内核与离屏测试可先同进程运行，产品进程形态须在 P0 收口。

若采用辅助进程，将完整场景会话及其脚本和 GPU 工作放入同一个 Scene Host。IPC 只承载控制、输入、音频快照、诊断和输出描述，不为组件属性建立远程调用。

共享 Metal 纹理和事件句柄可经 XPC 传递，但同设备限制、完成同步、资源回收和实际复制成本必须验证。不要同时常驻两套自动切换的场景后端。[共享纹理句柄](https://developer.apple.com/documentation/metal/mtlsharedtexturehandle)、[共享事件句柄](https://developer.apple.com/documentation/metal/mtlsharedeventhandle)

### 23.3 外部输入的最小检查

| 检查位置 | 防止的实际错误 | 控制成本的方法 |
| --- | --- | --- |
| 二进制解析入口 | 偏移越界、长度错误、错误分配或崩溃 | 解析时一次确认，内部使用完整类型 |
| 资源解析入口 | 读取错误来源或越出用户允许资源范围 | 解析为资源引用后直接消费 |
| 异步发布边界 | 快速切换造成旧结果覆盖新内容 | 发布处检查对应请求身份 |
| 动态句柄入口 | 删除后旧脚本引用误指向新对象 | 句柄解析处确认存活身份 |
| GPU 资源退役 | 尚在使用时释放资源 | 复用提交完成事实 |
| 脚本宿主入口 | 类型错误、越权访问宿主或无限执行 | 最小 API 表面、类型转换和已验证中断方案 |

新检查需要说清具体错误和最小影响范围。不要为内部已确定的数据增加反复认证、全量摘要或每帧完整诊断。

## 25. 核心接口与一次帧执行

### 25.1 宿主输入

| 输入 | 内容与使用时机 |
| --- | --- |
| 内容请求 | 项目来源、用户选择和允许资源来源，加载时传入 |
| 输出描述 | 逻辑视口、物理尺寸、颜色能力和显示模式，变化时更新 |
| 用户属性变化 | 已解析的用户值与变化集合，事件时传入 |
| 输入批次 | 有序事件及当前状态，按帧消费 |
| 外部快照 | 最新音频、媒体及完成的异步资源 |
| 播放意图 | 运行、暂停、静音和释放，策略改变时更新 |

Scene 不接收完整 App 状态、壁纸库记录或窗口控制器。需要哪个字段就传哪个字段或小型描述。

### 25.2 会话职责示意

以下是职责伪代码，用来说明正常链路，不是可以直接编译的 API 定稿：

```swift
func render(_ request: FrameRequest) throws -> FrameSubmission {
    let frame = clock.makeFrame(from: request)
    instance.consume(request.events, external: request.external)
    instance.advance(using: program.updatePlan, frame: frame)
    return try renderer.encode(
        program: program,
        instance: instance,
        resources: gpuState,
        frame: frame,
        target: request.target
    )
}
```

函数由场景执行域调用。事件细分、顺序、局部错误和参数更新在对应 owner 内处理。主流程不包含整库校验、重新解析、全面诊断或层层 fallback。

FrameSubmission 只携带本次输出身份、必要完成信息和失败状态，不携带整棵场景。最终输出进入宿主发布边界一次。

### 25.3 对外稳定性

只有宿主确实需要的 Scene 接口公开。内部类型不提前建设插件 ABI，也不承诺任意外部组件可注册到执行链。未来出现插件产品需求时，再评估 ABI、版本和生命周期。

## 26. 诊断与能力管理

### 26.1 定位链

保留“作者位置 → 准备节点 → 属性或资源绑定 → Pass → 最终输出”的按需定位信息。错误至少能够说明受影响资源、节点、材质或脚本绑定及可采取的动作。

常规播放只保留少量必要计数与错误事件。完整图、反射、资源清单、截图和逐回调跟踪由诊断开关或失败触发，且限制数量。普通帧不构造完整诊断对象。

### 26.2 能力表

按通用语义维护一个权威能力表，分别记录实现、语义验证、真实画面、性能及限制。界面显示用户需要理解的“不支持内容或资源缺失”，实现编号和内部计划名称留在开发诊断。

记录版本与证据身份，避免“曾有一个样本通过”长期变成无限范围的支持承诺。声明存在、字段读入、状态更新和最终画面是不同的完成程度。

### 26.3 错误与局部降级

| 错误 | 建议影响范围 |
| --- | --- |
| 可选特效或非关键资源失败 | 隔离相关特效或节点，保留其余内容并记录限制 |
| 必需主体资源失败 | 本次候选不激活，当前有效壁纸继续播放 |
| 单个脚本异常 | 隔离对应回调或绑定，采用明确项目策略 |
| 无法解释的动画通道 | 标记相应动作不可完整执行，避免冒充成功 |
| 输出尺寸或目标临时不可用 | 本次跳过呈现，待有效目标恢复 |
| GPU 或媒体持续失败 | 最小恢复，失败后显式停止重试并提供原因 |

没有证据支持的视觉替代只能标为近似模式。近似、禁用或降级不会把能力状态提升为完整兼容。

## 27. 验证与性能验收

### 27.1 四类验证

| 验证层 | 验证内容 | 不足以证明什么 |
| --- | --- | --- |
| 语义用例 | 解析、默认值、绑定、事件和失败边界 | 不证明 GPU 结果 |
| 真实 Metal 离屏用例 | 参数、资源、Pass、像素和同步 | 不证明桌面系统行为 |
| 真实壁纸对照 | 同输入的图像、运动和交互结果 | 少数样本不代表整个能力范围 |
| 原生宿主运行 | 多屏、输入、切换、休眠、能耗和资源释放 | 不代表屏保、锁屏或正式发行已通过 |

使用真实实现，测试不复制业务逻辑。离屏 harness 复用 SceneSession 和同一个 Renderer。仅平台不可控边界使用必要替身，GPU 结果和脚本执行不用假实现代替。

### 27.2 重点语义用例

至少覆盖：默认值缺席与显式值、稀疏资源槽、宏默认与显式覆盖、条件准入、copy/swap/compose、clear 与历史、不同纹理尺寸、非方形精灵、脚本返回与赋值、纯事件脚本、timer 暂停、动态 owner 创建销毁、隐藏交互节点、精确坐标、嵌套 mask、动画混合和异步旧结果。

每个兼容规则同时有正例、相邻反例、变量或资源改名及等价表达式变体。源文件路径和样本名称只用于定位证据，不用于产品分派。

### 27.3 画面对照

在相同逻辑尺寸、输出尺寸、设置、时间、输入与资源版本下比较。确定性内容可以使用像素或区域误差；随机粒子和动态媒体还需轨迹、分布、事件及连续帧观察。

不同 GPU、字体栅格和浮点计算可能存在差异。阈值依据实际误差与用户可见影响建立，不为了通过而不断放宽。修复样本之外保留独立样本和不应变化的相邻能力。

### 27.4 性能维度

测量冷启动、暖启动、首个有效输出、CPU 更新、脚本与桥接、GPU 时间、资源上传、内存峰值、持续能耗和切换后的回落。固定内容、分辨率、帧率和热状态才能比较。

以一台较低配置的目标 Apple Silicon Mac 作为基线，再覆盖高分辨率、多屏和高刷新设备。60 FPS 的帧间隔约 16.67 ms，这只是调度尺度，不能把平均帧时低于它当成完整体验通过。

P0 建立实际基线后确定各内容级别预算。现阶段不写未经测量的“零 CPU”“零复制”或统一功耗承诺。

### 27.5 持续运行

反复切换、创建删除动态节点、播放视频、替换封面、修改属性、热插拔与休眠恢复后，资源应回到合理稳定范围。执行持续运行以发现增长，结合实际引用与分配定位，避免把正常缓存驻留直接判为泄漏。

### 27.6 构建与产物

使用工程选定的 Xcode 与测试入口。Swift 产品变更做 Debug build；GPU、脚本、媒体、生命周期及可见变化增加相应隔离运行。文档设计本身不要求构建 App。

测试源媒体只读，自有夹具和隔离副本放受管理位置。构建、缓存与截图进入忽略的产物目录；每批保留必要最终日志和少量证据，清理已无消费者的重试产物。

## 28. 实施顺序与停止条件

每一阶段都交付能运行的完整切片。没有完成所有高级能力时，准确记录支持范围，继续服务已经正确的内容。

| 阶段 | 最小可用结果 | 通过条件与重评估点 |
| --- | --- | --- |
| P0 关键原型 | Shader 转换、SceneScript、最终输出及进程形态验证 | 各自通过真实用例；失败时调整工具链或边界，不按样本写补丁 |
| 1 基础内容 | 项目与资源读取、静态图像、变换、相机及正确输出 | 颜色、alpha、坐标、尺寸和资源来源用例通过 |
| 2 通用材质与合成 | 多纹理、Shader、条件、命令、多 Pass 及合成层 | 资源身份、状态恢复、历史及实际多效果画面通过 |
| 3 动态属性与常见粒子 | 用户属性、时间轴、通道、常用操作、child 与预热 | 不重解析普通帧，时间与组合行为通过；覆盖真实内容 |
| 4 完整脚本运行链 | 属性绑定、模块、事件、timer、存储与动态拓扑 | 同帧可见性、销毁、中断策略及真实脚本作品通过 |
| 5 高级内容族 | 文本、媒体、模型、Puppet、复杂粒子及光照 | 按依赖逐族闭合，避免为完成列表建设空壳能力 |
| 6 产品运行与发行 | 多屏、输入、功耗、持续运行及签名分发 | 相应设备与系统运行通过，所有组件与依赖为 arm64 |

文本、视频或某类基础动画若能以低成本解锁大量内容，可以在既有语义和数据流内提前实施。用户指定能力优先于自主排序，调整时说明依赖和收益。

### 28.1 P0 必须回答的问题

| 决策 | 区分实验 | 退出或替换条件 |
| --- | --- | --- |
| GLSL 转换路线 | 多纹理、宏、旧语法、数组、模型、所需阶段和相邻变体 | 转换缺口无法通用解决时改进前端或重选编译链 |
| JavaScriptCore | 模块、属性返回、对象身份、TypedArray、事件与中断 | 无法满足关键语义或可靠停止要求时评估 V8 等替代 |
| 进程形态 | 失控脚本、崩溃、强制切换、共享输出和能耗 | 同进程不能满足明确产品要求时选择完整 Scene Host |
| 文本管线 | 同字体、缩放、轮廓、阴影、模糊和裁剪 | 位图或距离场结果达不到目标时调整单一正式路径 |
| 色彩输出 | 透明叠加、数据纹理、视频、浮点高亮与显示转换 | 发现重复或缺失转换时先修正颜色合同 |
| 基础资源 | 普通项目离开参考安装后的依赖完整性 | 分发无法成立时确定用户提供或独立资源替代方案 |

这些是能改变实现成本的前置实验。完成后把选择写入设计决定，保留必要结果，退役无消费者的原型与双路径。

### 28.2 每批工作单位

从用户可见问题或通用能力出发，说明输入语义、所属 owner、最小改动、失败范围和验证。完成后说明产品、测试和文档变化，移除被替换路径。

当反复失败、覆盖收益递减或只能通过固定路径识别才能推进时，停止扩大补丁，重新评估语义理解和工具路线。不得以支持率数字替代真实画面与运行成本。

## 29. 容易遗漏但必须提前处理的事项

| 事项 | 需要确定的决定 | 所属职责 |
| --- | --- | --- |
| 基础资源与字体分发 | 来源、版本、授权及缺失体验 | 内容与产品分发 |
| 按版本的默认值省略 | 缺失、显式默认与关闭的差异 | Content |
| 多种时间源 | 场景、图层、粒子、现实时间及零步长 | Runtime |
| 隐藏对象 | 是否参与脚本、命中或离屏资源生产 | Runtime 与渲染准备 |
| 可选采样器与宏 | 作者存在性、默认回填与有效变体 | 材质准备 |
| 三种合成空间 | 图层、壁纸、屏幕对齐与相机传递 | 渲染准备与宿主 |
| 清屏与历史 | 创建、resize、每帧写入与显式函数 | Graphics 与会话生命周期 |
| 稀疏槽与实例 override | 保留槽和 Pass 身份 | Content 与 Preparation |
| 未知动画通道 | 保留、诊断与最小拒绝范围 | 模型导入与动画 |
| 系统媒体可用性 | 可获得信息、事件缺失和封面异步身份 | Platform |
| 音频动态处理 | 原始分析与公开结果的差异及近似范围 | 共享音频服务 |
| 失控脚本 | 中断能力、强制切换与恢复范围 | 脚本运行与进程选择 |
| 持久存储 | 壁纸、屏幕、全局范围及合并写入 | Runtime 与宿主存储 |
| 质量策略 | 用户选择如何影响分辨率、帧率与特效 | 产品策略和对应参数 |
| 打包运行 | arm64 依赖、资源定位、签名与运行权限 | 构建与分发 |
| 第三方依赖 | 固定版本、许可证、分发声明和必要补丁归属 | 构建与分发 |
| 故障诊断 | 按需定位、错误去重与有限证据保留 | Diagnostics |

签名与 hardened runtime 下的脚本执行、动态 Shader 编译和辅助进程必须在实际分发配置中验证。开发环境可运行不能替代这一检查。只配置实测需要的权限，不能为未来假设预先扩大能力。

质量调整作为用户可见策略，明确改变了什么。默认兼容路径保持作者语义；省电模式的近似与降质不计入无差别画面一致承诺。
