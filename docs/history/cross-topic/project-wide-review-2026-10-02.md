#### B05 [medium][bug] D1 composition 组在成员全部未编码时，composite 读取未清屏/陈旧的组 target

- **位置**：MyWallpaperX/Core/SteamWorkshopScene/Rendering/Composition/SceneUtilityLayerRuntimePlan.swift:351-394

#### B06 [medium][bug] authored sizeWH 经 SceneLayerEffectSourceExtent 直通后 Int(CGFloat) 强转可溢出崩溃

- **位置**：MyWallpaperX/Core/SteamWorkshopScene/Rendering/Frame/SceneResolvedMaterialFramePreflight.swift:397-398
- **触发场景与证据**：逻辑链：①renderSizeWH 就是原始 authored sizeWH（SceneRenderDescriptor+Layer.swift:87-89），layerSizeWH 构建器（同文件 :381-390）只做 padding，无上限钳制，Float 可表达 1e30 这类有限大值；②SceneLayerEffectSourceExtent.resolve（SceneCaptureGeometry.swift:25-48）对它只做 isFinite && >0 校验即放行为 pixelSize；③preflight 的 capturedLayerTexture 非 solid 非 geometry 路由把该 extent 直接并进 desiredSize（SceneResolvedMaterialFramePreflight.swift:206-215、245-254），随后 :397-398 执行 Int(desiredSize.width.rounded(.up))——Double→Int 超范围是运行时 trap，不是截断；④同一模式存在于 SceneImageLayerCompositor+Uniforms.swift:81-84（offscreenDimensions），覆盖普通带 effect 图层的直接路径。触发场景：一个带可见 effect 的 image 图层 authored sizeWH 填 1e30（有限、通过全部 isFinite 门）→ 帧准入 preflight 在 :397 崩溃，壁纸进程退出。旁证：同文件同数据流的 projectedPixelSize 路径已经用 Int(exactly:) 显式拒绝该隐患并留注释 "reject before that cast"（SceneCaptureGeometry.swift:71-76），说明这类 cast 在本项目被认定为崩溃源，但 renderSizeWH 直通路径漏掉了同样的防护。
- **独立核实依据**：逐环节核实，逻辑链成立，触发场景真实可达。核实过程：(1) SceneResolvedMaterialFramePreflight.swift:397-398 确认 `Int(desiredSize.width.rounded(.up))` 无上限守卫，且执行于 :407 pool 规划之前——下游 SceneOffscreenResolutionPolicy（SceneOffscreenResolutionPolicy.swift:41 standardMaximumDimension=2048、:77-95 resolvedDimensions 钳制）来不及生效。(2) 数据源：SceneRenderDescriptor+Layer.swift:87-89 renderSizeWH 即 authored sizeWH；构建器无钳制确认，但实际位置是 SceneRenderDescriptor.swift:381-390（发现把"同文件"写成了 +Layer.swift，属引用小误，实质不变）；解析层 SceneDocument+NumericParsing.swift:38-47 saturatingFloat 只饱和到 Float.greatestFiniteMagnitude(~3.4e38)，1e30 甚至 ≥9.23e18 均以有限 Float 原样通过。(3) SceneCaptureGeometry.swift:17-23/25-48 确认 resolve/init 仅做 isFinite && >0 校验即放行。(4) preflight :205-215/:245-254 确认非 solid capturedLayerTexture 路由把 extent 经 max() 并入 desiredSize，quantizedUp 对非有限值返 0 但 max(1e30,0)=1e30 无挽救。(5) 自证探针（/private/tmp/mwx-review，swiftc 编译+运行）：CGFloat(1e30).rounded(.up)=1e30 有限，Int(1e30) 使进程 SIGTRAP（exit=133），后续语句未执行——确认运行时 trap 而非截断。(6) 旁证：SceneCaptureGeometry.swift:71-76 projectedPixelSize 确用 Int(exactly:) 且注释 "reject before that cast"；preflight 的 solid(:268-277)/utility(:332-342)/direct-draw(:360-370) 路由全部经它防护，唯独非 solid extent 路由没有。(7) 第二处：SceneImageLayerCompositor+Uniforms.swift:75-85 offscreenDimensions 同款无守卫 cast，经 SceneMetalRenderer.swift:547-552 同一 resolve+authored renderSizeWH 供数，在 SceneImageLayerCompositor.swift:282 未 claim 层 routesOffscreen 时触发。(8) 可达性：claim 准入见 SceneResolvedMaterialExecutionCapability.swift:564-574，带可见 effect 的 image 层属已迁移主链会进 preflight 路由；未迁移层走普通路径 twin site。上下限结论：无上游守卫（解析饱和上限 3.4e38 远超 Int 范围）、无下游兜底（2048 钳制在 cast 之后），问题不可被现有防线拦截。保留两点范围说明：①未逐一审计 sizeWH 全部其他消费方（脚本桥、粒子编译器）以排除同帧更早 trap 的可能，故"首个崩溃点恰为 :397"对任意场景形状不作强断言，但两处具名 cast 均真实在数据直通路径上，任何更早 trap 只会加强而非削弱该崩溃类；②严重级维持 medium：本地 authored 数据触发、非远程可利用，但后果是帧准入即进程退出，且与项目自身硬拒绝合同（非法数值/投影范围）及 projectedPixelSize 先例确立的防护意图相悖，属真实缺陷而非应驳回的过度防御。
