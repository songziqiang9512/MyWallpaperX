# 壁纸画质执行合同

<!-- document-role: stable-contract -->

本合同定义档位对当前画面的承诺、统一决策权和回执。算法比较、官版证据和预算门归[技术评估](../development/wallpaper-quality-settings-plan.md#decision)。实际交付范围、候选和未通过的验收归[现役工作卡](../development/wallpaper-quality-work-card.md#execution)。

## 修改怎样生效

`PlaybackQualityPreference` 唯一保存请求，`SceneQualityPreset.projection` 唯一定义预设组合。AppKit、v8 导入、复位和恢复使用同一请求类型。引擎执行投影由各自原消费者从准备事实和目标屏能力求出。设置页读取请求和运行结果，运行时无需读取控件或重新解释预设。 [值和预设](../../MyWallpaperX/Core/PlaybackControl/PlaybackPerformanceProfile.swift) · [Scene 原执行架构](../scene/architecture/runtime-architecture.md#effective-quality-policy)

| 操作 | 生效边界 |
|---|---|
| 单项手调 | 一次提交仅改变该字段。Scene FPS、两个超高后处理之间的显示 HDR 切换、Web 帧率建议在活动执行边界热更。Scene 抗锯齿、其余后处理切换（含禁用↔启用）、纹理、阴影、体积及反射沿原同源候选重新准备。暂停使用现有冻结重绘或暂停候选。 |
| 选预设或复位 | 一次提交完整请求。依赖新准备的字段共用一个候选。热项按各自原执行边界采用，冷项只有随新画面接管才生效。相同向量无需重启。 |
| 连续调档、换壁纸或换屏 | 更晚的操作沿既有事务撤销旧候选。每个实际状态绑定活动请求及对应 Surface；更换 Surface 时从新执行事实取得。用户晚改先前的值以最终请求为准。 |
| 导入、恢复或失败 | 尚未采纳的导入显示「待应用」，继续原活动画面。复原活动播放时读取保存请求。候选失败保旧画面，反馈「应用失败」并沿现有同源动作重试。 |

手调完成以消费者的结果为准。有适用输入时，每一公开选项须能改变实际调度、附件、绑定、算法或工作量；效果有真实贡献时，用同相位画面或物理呈现证实预期变化。保存值、预设名、准备成功和菜单勾选只代表各自阶段。对当前内容无作用的全局请求仍可保存，并需说明当前实际情况和下一次采用条件。 [接管与失败](playback-lifecycle-transaction-design.md#三唯一产品事务)

一个设置拥有一种产品语义。原调度、资源和渲染生产者只接自己消费的请求字段，决定各自范围并返回实际结果；AppKit 用这些结果显示本屏或各屏摘要。预设、手动、恢复走同一执行链。扩展一个受影响的执行路径时，沿其现有准备、帧绑定、呈现和回执补齐；相同的资源决定与回退规则由既有资源 owner 共享。

<a id="quality-feedback"></a>
## 实际档如何回显

下列状态为交付要求。已接入的选项和实际验证范围见[现役工作卡](../development/wallpaper-quality-work-card.md#execution)。

| 状态 | 依据和反馈 |
|---|---|
| 待应用／应用中 | 保存请求尚未由相应运行端采用／替代候选正在准备或等待新画面。可保留旧画面的实际档，须注明归属旧画面。 |
| 已采用 | 活动消费者确认实际规格、算法或调度。所需证据按下表；画面结论另由匹配的窗口捕获或实际呈现取得。 |
| 当前不适用 | 已知本作品无相应输入或消费者，例如无全景 Bloom、无投影灯。已保存请求在下一适用作品继续执行。 |
| 本画面等效 | 通过实际输入证明没有更细的可用信息或更高档数学等价，例如点光衰减指数为零、纹理原级已满足 Auto，或两个定向档达到同一接收目标所需的网格上限。回显相同的实际值及原因。 |
| 当前实现未覆盖 | 存在适用贡献，但现有路径缺少请求规格的执行方式，例如当前聚光影图的高档上限。回显已经执行的规格和覆盖限制，并由工作卡登记缺口。 |
| 回退／不可用 | 设备规格或资源不足时说明实际采用的较低档和原因。只有实际消费者采用较低值后才确认回退；没有有效方式提供该效果时报告不可用。 |
| 结果待确认／应用失败 | 尚无有效执行证据时保留待确认。替代候选或热更失败时报告失败和仍在播放的有效结果。失败或迟到的提交不得改写有效回执。 |

回执由原本的资源、算法与调度消费者生产，按活动请求、Surface 与当前准备结果收敛。每屏可分别待确认、采用或回退，任一屏缺报也能读到其他屏的结果。同一 Surface 按实际值及理由筛选，新的活动请求或 Surface 都从自身结果重新确认。事件沿原合并窗口发送逐屏摘要，活动请求变化与跨屏值互换都能被识别。附加回执共用原生命周期和通知，变化才发，无逐帧 IPC、第二份持久状态或为回显扫描作品。AppKit 只能翻译已报告的事实。设置帧率上限、GPU 成功完成且请求呈现、窗口真正实呈各自用本职责的证据。

同屏有多个灯种、纹理用途或根段时，写明实际作用范围。单个模型用了 4× 即可报告对应根段，整幅的单采样尾段仍须可见于实际说明。一个高规格灯或一张降级纹理不能替代其他参与者的结果。只接入一部分的控制项用对应能力范围描述，未证路径保待确认或说明缺口。新档尚无可执行规格、不能与相邻档稳定区分，或只有候选准备证据时，留在实现与验证路线，暂不提供为可用菜单项。

| 设置与选项 | 如何执行当前画面 | 实际档必须来自 |
|---|---|---|
| 帧率 10–120 FPS，步长 1 | Scene 的目标节律取请求与目标屏集合共同可用上限的较小值。目标屏刷新率一致时用已知同值，混合或未知时取该组的保守上限且不超过 60。下调减少调度更新，上调允许更多更新。作者时基和速度沿原时钟，帧回调与本帧间隔随实际调度更新。暂停、可见性、渲染超时及显示节律会改变实呈频率。画布像素尺寸不随这个数值变动。 | 活动帧驱动的有效调度上限。实呈频率由窗口呈现时间计算，保存值、显示上限与实呈各有标签。 |
| 抗锯齿 无／2×／4× | 无用 1×。2×／4× 分别要求有效几何覆盖的 Metal 色／深附件和 PSO 采用对应样本数。根合成按原层序开合，多样本段解析到同一主色。可安全共用的 1× 前缀／尾段保留原职责。根域不合格时保 1× 出图并区分无可采样图元与现行根域限制；附件不可用或前缀转换可撤销时，回显已执行的 1× 和原因。原生编码或 GPU 提交失败沿原掉帧／延后，保最近成功结果。8× 先证设备、实际附件与相对 4× 的收益再开放。4×→2× 属于降档策略，须由实际 2× 执行确认。 | 成功完成且已请求呈现的帧实际开启的根段样本数。最高成功样本用于简读数，混合帧只有原生段改变覆盖；纯 1× 与 4× 加 1× 尾段分开。 |
| 后处理 禁用／启用／超高 | 禁用撤全景 Bloom 与超高的 HDR 工作域。启用在普通工作域按作者输入做提亮、纵向模糊、横向模糊、加法合成四步。超高对作者 HDR 使用浮点工作域、HDR gain 和浮点 Bloom 金字塔，作者普通输入继续同一普通链。作者禁用或零强度时无需生成对应泛光。终端映射始终保普通出画。作者 HDR 且 `clear=false` 使用同代持久 raw 合同，降为 SDR 工作域后仍保累积。 | 本帧实际工作域、Bloom 有没有成功编码和终端映射。作者关闭、可选链规格不支持（如现行 HDR 迭代不足两级）、附件或资源失败分别归因。是否有亮源产生可见光晕由画面对照确认。 |

| 纹理 高质量／自动／高性能 | 按[纹理资源表](#quality-textures)分别用原可用表示、满足投影的真实作者级、合格的较小作者级。档位只改变有资格的指定资源用途，不统一缩小 Scene 主目标或所有材质槽。 | 真正绑定的基级与尾链尺寸、适用用途和保原原因。Auto 改选基级时证明新资源发布并实绑；保同一级时报告尺寸和原因。 |
| 阴影 禁用／低／中／高／超高 | 禁用停可选影图写入及接收采样。每种光源的规格和覆盖范围见[阴影与体积表](#quality-lighting)。保作者投影资格、直接光、相机深度和镂空轮廓。 | 各参与光种实际写入并采样的影图尺寸及实际滤波路径。按光种说明规格上限、接收范围或实际预算回退。 |
| 体积 禁用／高／超高 | 禁用撤点光遮挡重放、点光积分和聚光锥加光。高／超高按[阴影与体积表](#quality-lighting)采用实际积分阶数。低／中须分别具备明确积分／覆盖、画质可接受范围和稳定成本档，验收后公开。 | 点体积路径和阶数、聚光锥实际执行及尚无差异化的范围。 |
| 反射 关／开 | 开启为实时环境消费者提供最近合格完成的场景颜色及必要 mip。首个有效历史到来前为准备中。晚到具名阴影占用原有顺序而跳过环境前置时，或可选资源准备失败时，回显具体受影响范围。关闭停止可选快照和采样，仍需合法槽的作者 Program 读到匹配范围和 mip 的不透明黑环境。作者自带反射纹理、独立反射特效、必需画布历史和同帧折射继续各走原用途。 | 真正绑定的实时环境来源及代次，或关闭后的黑源和已跳过的可选生产。无实时消费者时报告当前作品不适用。 |

## Web 与 Video 的实际范围

| 引擎与设置 | 消费与结果 |
|---|---|
| Web 随显示器／跟随动画帧率 | 随显示器给当前目标屏的建议值，最高 60。跟随模式经原作者 API 投递保存的 10–120 FPS 建议。按参与的文档分发，导航后新文档得到当前值。暂停时保最新建议，恢复回调前交付。同一屏实际建议未变时沿用已有投递，模式请求照常更新。作者可以用它节流动画或忽略它。宿主发出建议，文档收到由作者回调证明，实际节奏以作者绘制验证。作者属性若自有画质档，独立按其声明传递。 |
| Video 原片与填充方式 | 选定文件的真实轨道与 AVFoundation 能力决定视频的像素、帧率、VFR 时间与 HDR 输出。完整显示／填充屏幕分别等比保全或等比裁切，冷热转换继续使用同一布局。Video 只消费自己的媒体与布局设置。Web 的 Scene FPS 跟随模式只投递建议，其余 Scene 画质字段专供 Scene。 |
| Video 下载规格 | Pixabay 提供哪几个真实源文件，就显示对应规格。改档影响新下载实际内容，详情读取已下载文件的轨道尺寸和标称帧率。已在播放的本地文件继续用其原轨道；离线更低规格派生要求独立能耗和音画门，尚无该播放档。 |

## 阴影与体积逐档值

| 阴影 | 定向目标上限 | 点光每面与聚光目标 | 执行边界 |
|---|---:|---:|---|
| 禁用 | 无 | 无 | 可选光空间深度写入与接收比较退出。 |
| 低 | 512 | 512 | 原比较滤波按真实 texel 宽度工作。 |
| 中 | 1024 | 1024 | 取得更细的投影网格，实际使用受投影范围和资源预算约束。 |
| 高 | 2048 | 1024 | 定向可加密。点光高档每面 1280 候选；当前仅有点／聚光时须说出灯种规格上限。 |
| 超高 | 4096 | 1024 | 定向继续加密。点光超高每面 1536 候选。聚光高／超高尚需验证不同的真实规格或滤波，按现有 1024 和灯种限制回显。 |

定向按接收绘制所在 render pass 的目标长边选择网格。长边超过 2048 取 4096，超过 1024 取 2048，否则取 1024，再取档位上限。场景中的接收者边界另供投影拟合。点光用 D32 的 3×2 atlas，512／1024 为每面分辨率；定向和聚光用单图。定向用十六点比较，点光和聚光用原四点比较。网格适配也要核 PCF 世界空间宽度、偏移和实际边缘。现行池按计划灯组预约，整组无法取得时可能回到基础规格。扩档应将增量限制在受影响光种并保已有工作，设置报告实际受影响的绑定。阴影回执以活动 Surface 完成帧中受光材质实际绑定的影图为据，含具名和组绘制。只生成影图时，按已知接收或执行状态报；只有原预约明确拒绝额度时才标为预算回退。覆盖取同相位终图判断。 [光种试验与正式门](../development/wallpaper-quality-settings-plan.md#scene-shadow-steady-author)

| 体积 | 点光 | 聚光 | 与阴影组合 |
|---|---|---|---|
| 禁用 | 不建立可选积分／遮挡重放 | 不加锥光 | 表面直接光、作者距离雾照常；启用的表面阴影仍独立生成。 |
| 高 | 原尺寸四点积分 | 现役作者锥 | 独立遮挡深度维持。关闭表面阴影不取消已有体积资格。 |
| 超高 | 原尺寸六点积分 | 现行仍用同一作者锥 | 指数零仍用解析线段。六点 PSO 无法准备时原准备槽尝试四点。实际执行后回显回退；两者均不可用则报告点光体积未执行。纯聚光须说明高／超高共用同一路径；不同规格尚未接入。 |
| 低候选 | 最低实际积分成本，接受有限平滑；须保持遮挡轮廓和可见的窄亮核 | 在保持作者锥顺序和覆盖时减少实际贡献成本，方法待证 | 阴影设置不改体积档。固定相机和原深度，先证实际成本低于中，再开放。 |
| 中候选 | 较低档进一步保亮度、窄峰和截线的梯度；实际成本低于高 | 若有分档，须在相同覆盖下改善质量且可证成本低于高 | 同一相机和原深度作参考，验真实点光、聚光和两者同帧后再开放。 |

<a id="quality-textures"></a>
## 纹理资源逐类与分辨率

高性能从合格普通静态根色图的作者链中取长边不超过 2048 的首个级。原长边不超过目标或没有满足上限且合格的较小级时继续使用原表示。自动只接受可证明的固定正交投影，以目标屏集合最大 drawable 相对作者画布的 cover、静态 zoom 和对象范围计算每轴向上取整的物理需求。同一源逐轴取各有效普通对象的最大需求，选择两轴都够用的最小作者级。同源有精确用途或投影不能确定时，自动保原。有动态模型查找请求或保留动态默认别名时，现役 Auto 对整场保原。后续按来源缩小限制须正向证明可达用途。放大且跨级时成组更新，缩回保留当前规格。高性能可让互相独立的普通用途用较小表示，实际精确用途和别名供体保原。两种独立用途可同时绑定原规格和小级，报告各自的绑定与实际分配。

| 资源与实绘用途 | 高质量 | 自动 | 高性能 | 必须保持 |
|---|---|---|---|---|
| 原物理与映射尺寸一致、无图集/padding/动画的普通静态根色图，TEXB0003 内嵌 PNG／JPEG 作者链 | L0/原当前表示 | 选满足最大投影的真实级 | 选合格尾链 | 作者逻辑尺寸、归一 UV、颜色空间、alpha 和采样。仍用原载入 owner。 |
| 原生 BC1／BC2／BC3／BC5，raw 颜色、R8／RG8 | 原角色与上传路径 | 同左 | 同左 | 块布局、合法级、尺寸、原设备格式和通道语义。BC 尾链候选暂退出。 |
| 独立 PNG／JPEG 等 ImageIO 图像 | 原解码路径，现有普通图按比例以 4096 长边为上限 | 同左 | 同左 | 方向、ICC、覆盖、透明边、作者布局。按档向下解码仍是候选，交付须改变实际分配和绑定尺寸。 |

归属先看消费用途，再看容器与真实 mip 链。精确数据保原是作者画面合同；有可缩普通颜色，但当前只对内嵌作者 mip 接通时，属于实现覆盖范围。每个参与的颜色源维护自己的逻辑范围和 UV 变换，实际分配尺寸以选中基级为起点。对相同来源的不同绑定，各消费者仍按自己的数据合同执行。资源只按真实用途形成所需的表示，帧中直接绑定既有结果。

常规尺寸例以长边决策，不用「2K／4K」营销名替代物理规格。

自动依物理需求选级，结果可以比固定高性能更大、相等或更小。已发布资源的自动升级以两轴覆盖、实际换入和下一次绑定为准；用户从自动改为高质量或高性能仍沿完整冷接管。

现行静态色图资格为原生单输入透明、无深度的普通 quad，且没有父子层、依赖、混合式实色、模型、utility 或作者 effect（含隐藏实例）。最近点和线性都保材质原 sampler。最近点采样本身可用于普通归一色图，依赖逐 texel 或物理像素格的用途则必须保原格。色源有实际合成效果时，相同 UV 采样保输入角色和原滤波，纹理降档只改变选中基级的细节与尾链接续。写入物理像素尺寸、像素步距或显式 LOD 的用途仅在能保持原语义时允许选级。没有可确认用途时沿现有采样资格保原表示，旁路的普通消费资格仍按其自身事实判定。合法链的小级解码或上传失败时，冷准备沿原 Loader 尝试原级。已显示的 Auto 热升失败时保留已发布表示。坏容器沿原局部失败范围。以 GPU 实际绑定的基级尺寸和作者尾链证明资源生效。逐片元 LOD 和尾链各级像素用可辨 mip 颜色读回证明。回执从原选级结果保留类型化原因，区分原规格请求、Auto 投影已需原级、无合格尾链、原像素用途和小级执行失败。仅选中、解码、上传或交换资源时都保持待确认。原普通色图绑定确认实际物理尺寸、基级与尾链，现有 Surface 完成回调只接收实际完成且请求呈现的结果。收到换档、延迟图提交或 Auto 实际换级后重新确认。原根颜色继续复用、drawable 缺失或 GPU 失败时保留上一次真实结果及其归属。稳定帧沿用现有摘要，无需遍历资源、记录全层绑定或发送 IPC。摘要最多保两组已确认规格，分别取完成采样帧中面积最大的普通直接绑定原级与较小作者级。已有候选但本帧还未看到普通绑定或所需的小级时，沿后续原绘制继续等待实际结果。摘要是代表规格。脚本切换多个已有图层不驱动逐层可见统计。尚无该路径的实绘样本时只报已知事实；静态选级中无适用资源的结果来自原准备事实。 [TEX, Auto 和源用途](../scene/architecture/runtime-architecture.md#scene-texture-quality-policy)

## 组合顺序与验收

1. 从同一用户请求和真实屏幕、内容、设备能力选择当前采用的档。作者时钟、属性输入与预设彼此独立。具名和局部图由实际依赖准备，原有的局部图、模型、普通层、粒子与聚光锥按确定的作者层序交错，包含作者定义的透明深度排序。依赖具名材质的阴影在实际供货后准备。可提前的独立局部图只在原层序消费。光空间阴影和点光体积遮挡各持独立深度。
2. 根颜色按作者实际顺序合成。根采样决定颜色与相机深度附件和切点，同相机深度的模型与图像终端采用同一域。需要已完成颜色的 1× 段从相同根目标读取。点光体积在有序层完成后以独立遮挡积分加至主色，早于该点执行的作者读回使用此前已完成颜色。下一帧实时环境可取成功完成、含点体积且在终端 Bloom 前的主色。作者 HDR 且 `clear=false` 的必需 raw 仅在匹配池、代次和身份的历史中延续，冷切新 Surface 按新代接管，两个超高的热切仍在原 Surface。当前帧最终 Bloom、显示映射、原 drawable 呈现按这一顺序完成。
3. 各选项只对自己负责的资源和执行边界生效。资源先满足作者必要依赖，再保护固定内容、屏幕与其它请求时基础规格已能运行的效果，最后尝试可选扩档。增量资源不足时只降低受限规格，经实际执行回显。预设组合使用同一优先顺序。一起编辑得到同一偏好向量，冷准备采用该快照；预设、连续手调、导入、暂停、取消、换作品、换屏与预算变化都验证归属和可见接管。

例如，开启 4×、高性能纹理、高阴影、超高体积、反射开和超高后处理时，一条独立的合格普通色图先绑定较小作者级，模型的精确投影 mask 仍绑定原级。光空间写入在实际受光绘制前完成；主相机域按适用图元覆盖编码并解析。点体积从独立遮挡深度积分到同一主色，成功完成的颜色供下一帧实时环境。最后采同一主色做作者 Bloom 和显示映射。把反射关掉只撤其实时环境供货，画布历史和同帧折射继续有效。把后处理禁用会改变工作域和终端处理，前述依赖的颜色格式须沿同一准备重新取得。最终组合须在两种修改顺序下得到相同的有效选择与稳定画面。

| 必测组合 | 像素及执行不变量 |
|---|---|
| MSAA × 透明／相机深度／作者读回／HDR | 保透明顺序、关联颜色和原作者采深。只在原生段改覆盖，读回取得已经完成的同一主色，终端映射只执行一次。已有 1× 逐值深度必须按实际深度合同使用。 |
| MSAA × 点体积／实时环境／具名材质 | 以实际遮挡、颜色历史、具名供货和深度依赖决定可用根段。实际点光积分在有序层末尾从独立 D32 取遮挡。合格多样本根段先解析到原主色，再由 1× 加光。仅有体积声明或没有实绘贡献时，根段照常结束。合格模型在相同混合方式的 2×／4× 管线读取上一完成环境，尚无历史时以同采样基础材质出画。缺少实际所需反射管线、活动具名模型色图、图像／Program 的环境依赖或已有 1× 深度前缀仍可能使根域采用 1×，按实际路径回显。先改 MSAA 再改另一档，也换次序验证。体积覆盖实际积分、仅有声明却没执行积分及关闭三态，核深度、环境代次和每段覆盖。 |
| 纹理 × 镂空阴影／显式 LOD／共享材质 | 精确 mask 保原级，普通色图按各自资格下采样。检查前景孔洞、影边、颜色细节及每个实际绑定，图集与原始坐标不变。 |
| 阴影 × 体积／MSAA／前向供货 | 阴影关仍保作者资格内的独立体积、直接光与雾。把其它请求固定后提高阴影档，冷预算若仅容原点光 atlas、实际前缀 scratch 与体积 D32，继续使用原影图规格和其它原贡献。核同帧光种尺寸、前缀与原生采样、独立深度绑定和亮区像素。 |
| 体积 × Bloom／反射 | 体积增量先写当前主色，Bloom 从完成颜色取亮，实时环境由下一帧按完成历史读到该贡献。 |
| 反射关 × `clear=false`／named／折射 | 可选实时环境退出，明确的环境槽走黑源；同帧前缀、作者命名生产者、持久 raw 和独立折射仍有原实际供货。 |
| FPS × 所有画质档 | 帧率按目标屏和运行能力约束。作者运动在等时间点具有同一语义，比较画面锁定实际相位。降低层级不能顺带修改作者计时、输出尺寸或视频轨道。 |

## 验收与交付

1. 每项公开能力用一个合适的普通作品与一个独立真实作品验实际消费。离散画质档在适用对象上证明资源／算法及可解释的像素、覆盖或成本变化。连续 FPS 用边界、步长、相邻或代表值验证有效调度和实呈。Web 先验实际文档交付，再以接受建议的作者验证绘制，以忽略建议的作者验证作用边界。Video 的新下载档以实际文件与播放轨道验证。相邻档在各自实际范围内验证正常、适用但等效、内容无关、容量失败、切换中断及迟到回执。作品画面对照用相同作者时间和输入并核邻区。显示 HDR 补仅接入未选、目标组有 HDR 屏、已保存后目标退出。未过对应证据的新增选项保持候选。
2. 受控验收使用同一实际 AppKit 手动操作或提交路径，验证已保存请求、准备收据、实际消费者、已显示画面或实呈时间和用户反馈。不能用内部专用开关绕过正常下发。参与的 GPU 测量包括实际 extent、附件和有效采样，物理呈现与性能长窗单独记录。涉及作者无适用内容的负例保证原合法画面可正常显示。
3. 每个纵向批次在原设置窗口执行相邻档 A→B→A 或一次原事务可比的单向修改。验收证据需同时连接用户动作、活动身份、实际消费和输出／成本；恢复档复现基线。原作者动态造成的像素差、模拟设备结果、单次峰值和只成功创建资源分别限定用途。样本、通过范围及未发布选项只维护于[现役工作卡](../development/wallpaper-quality-work-card.md#execution)。

| 生效证据 | 应观察的变化与邻例 |
|---|---|
| 预设与帧率 | 按四个向量核每个实际参与项。10／120 边界、60／高刷代表值与连续往返核帧间隔和实呈；同时间相位与输出像素尺寸保持。 |
| 抗锯齿 | 核 1×／2×／4× 实际开段、深度、解析和覆盖。取有效斜边、透明叠放或实体剪影的邻区，检查覆盖误差、亚像素移动和恢复；满屏贴图内部边及原采样的作者图独立取邻例。 |
| 后处理 | 同亮源核禁用撤实例、启用普通 Bloom、超高作者 HDR 工作域及 HDR Bloom；取亮核、光晕、暗区、局部作者效果及持久 raw 邻例。显示 HDR 单列实际目标屏及其输出。 |
| 纹理 | 各受益档核真实基级、绑定尺寸及分配，固定投影取纹理细节；动态增大投影确实发布新级。精确数据、图集、视频和多用途同源分别核原语义。 |
| 阴影与体积 | 分别核影图绑定与边缘、积分阶数与光束亮度及遮挡。关阴影保直接光和合格体积，关体积保直接光与合格阴影。逐光种证明受益、已知等效及现行未覆盖。 |
| 反射 | 按同一材质的实际环境槽核开启历史、首帧无历史和关闭黑源；捕获稳定真实高光及折射、独立反射和历史的邻区。仅记录快照创建无法证明任何像素采用。 |
