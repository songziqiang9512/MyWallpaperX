# 壁纸画质执行合同

<!-- document-role: stable-contract -->

本合同定义档位对当前画面的承诺、统一决策权和回执。算法比较、官版证据和预算门归[技术评估](../development/wallpaper-quality-settings-plan.md#decision)。实际交付范围、候选和未通过的验收归[现役工作卡](../development/wallpaper-quality-work-card.md#execution)。

## 修改怎样生效

- `PlaybackQualityPreference` 唯一保存请求，`SceneQualityPreset.projection` 唯一定义组合。AppKit、v8 导入、复位和恢复使用同一请求类型。Scene 帧率、同工作域的显示 HDR、Web 建议在原活动边界热更。改 Scene 准备契约时，直接编辑沿原同源候选重新准备并实际呈现后接管。导入只改变已保存请求时报告待应用。更晚的编辑和新选片按现有事务精确取消旧候选。 [值和预设](../../MyWallpaperX/Core/PlaybackControl/PlaybackPerformanceProfile.swift) · [接管与回退](playback-lifecycle-transaction-design.md#三唯一产品事务)
- 每个运行端按当前作品、资源用途、设备、目标屏与实际消费者选择有效方案。Scene 根采样的收敛目标是从现有准备与帧图取得所有顺序与用途事实，先确定采样、读写切点和依赖，再兑现相机深度、图目标等资源。普通帧只消费已准备的 typed 值、作者动态输入与实际可用资源。逐项回执的交付要求是由资源与算法的原消费者报告采用和回退，最终合成与提交沿原职责。 [Scene 渲染架构](../scene/architecture/runtime-architecture.md#effective-quality-policy)
- 控件必须对应可证明的实际行为。已确认当前无适用内容或硬件不支持时说明原因，控件如保留全局编辑须明确用于适用作品或设备。当前作品有目标消费者时，档位必须改变该消费者的调度、算法、物理资源或出画。后续准备失败、共同降到同一档、暂时不可用及结果未知分别回显。回显须对应当前 active request、Surface／屏和准备代。前台切换依次表达「等待新画面」「已采用的实际档」「当前作品不适用」「回退到实际档」或「应用失败，继续显示旧画面」。未知仅在缺少有效收据时使用。设备或预算变化可重算有效档，保存的用户请求继续保留。禁止把请求已保存、候选已准备、Shader/PSO 可建或 GPU 完成当作该项画面已实现。
- 一个界面可以显示请求和实际状态。实际状态沿现有活动 request／Surface 变化回执发布。静态资格和资源结果在准备、接管、用途或规格变化时更新。动态效果仅在实际有用状态变化时汇总。采样率、实际绑定规格、影图 extent 和积分阶数从原执行点取得，无新增逐帧 IPC、整图扫描、内容识别或并行设置 owner。GPU 完成、实际调度上限和窗口实呈各用自己的证据。

## 八项逐档定义

| 项 | 选择与实际消费者 | 当前画面含义、并档与回退 |
|---|---|---|
| 预设 | 低 10 FPS、Bloom 关、低阴影、反射关、1×；中 15 FPS、普通 Bloom、中阴影、反射开、1×；高 25 FPS、普通 Bloom、高阴影、反射开、2×；超高 30 FPS、超高 Bloom、超高阴影、反射开、2×。四档纹理均高质量，前三档体积高、超高预设体积超高。 | 一次提交请求组合，对应消费者各依其规则采用。预设名从保存组合派生，手调产生自定。一个字段回退时回执仍保留同一次请求里的其他实际生效项。 |
| 帧率 | 10–120，步长 1，默认 60。Scene 原时钟分别保逻辑时间、用户调度上限与有效目标屏刷新率。同一 Scene 多屏取可共同维持的调度范围，连续运动保作者时基。 | 更高上限允许出更多帧，低档允许更少更新，壁纸速度不随 FPS 线性改写。实际呈现还受渲染时间、显示节律与窗口可见性影响。Web 跟随模式给原作者 API 建议，随显示器模式延用相应显示器建议且上限 60。Video 继续原文件时基。 |
| 抗锯齿 | 无为 1×。2×／4× 分别请求真实附件及管线样本数。设备、准备、实际层序或帧资源无法执行所请求档时，现行沿 1× 出图。8× 和 4×自动降到 2× 都需独立验收。 | 改变几何边缘覆盖、半像素遮挡和参与的透明合成。直接主域可共用片上色深，在无后续逐样本需求的切点 resolve 至同一主色。只支持低档的实际原因按屏或根域回显。纯贴图内部的锯齿由贴图过滤或作者 Shader 处理。 |
| 后处理 | 禁用停全景 Bloom，终端仍做正常显示映射。启用按作者普通 Bloom 在普通工作域做分离模糊。超高在作者请求 HDR 工作域时用原浮点金字塔，普通作品保持普通 Bloom 路线。超高（显示 HDR）共用同一准备域，按实际目标屏和作者输出资格热换 EDR。设置按 Scene 当前配置选定的同一组目标屏展示显示选项，多屏中任一目标有 EDR 潜力即可保存请求，实际仍逐屏确认。位于选定组之外的 HDR 屏不参与；已保存但不可用的显示档仍可见并明确标注。 | HDR 开关只改变显示侧的合格亮度能力，工作域与作者 HDR 输入各自有明确条件。作者强度为零、作者禁用、可选分配失败时的无 Bloom 结果与局部效果单独报告。禁用／启用离开超高工作域时也停止作者 HDR 工作域的 gain。作者 HDR 且 `clear=false` 时仍沿原 SDR 同代 raw 合同。画面中的作者模糊、调色和像素化仍按原图。 |
| 纹理分辨率 | 高质量保原作者表示；高性能用合格作者 mip 选较小物理表示；自动用实际投影与用途求同源共享的最小足够物理规格。各类资源按[纹理规则](#quality-textures)。 | 例如静态背景细节、纹理闪烁与 GPU 占用改变，原作者几何、UV、输出窗口像素和其它精确用途保持。读出绑定的真实规格与对应范围。无合格小级时说明原规格已用及原因。 |
| 阴影 | 禁用撤可选影图与接收采样。低／中／高／超高的定向上限分别 512／1024／2048／4096，实时受投影范围和预算。低档点光每面及聚光目标 512，中及以上当前基线 1024。 | 改影边采样、稳定性和实际目标成本，保直接光、主相机深度、镂空轮廓和作者 `castsShadow`。同目标规格的相邻档说明等效。点光 1280／1536 是高／超高候选，仅在六面深度及独立长窗通过后采用。 |
| 体积照明 | 禁用撤点光独立遮挡重放和积分、聚光锥加光。高用原尺寸四点积分，超高用六点，指数零用解析线段。聚光高／超高沿现有相同锥。低／中以更少实际成本维持可比遮挡、亮窄峰和作者形状，须在证明可区分的两级算法后开放。 | 只控体积贡献，表面直接光、相机深度、场内雾及灯作者参数保持原职责。六点准备失败时点体积局部不可用，聚光锥独立。自动改用四点须在通过对应准备与实绘后才采用。只含同档聚光或根域无合格体积消费者时明确说明。 |
| 反射 | 开启按真实模型、图像和 Program 需求采最近合格完成的环境色与 mip。关闭停可选实时环境快照和相应采样。要求合法槽的作者 Program 取匹配 extent／mip 的暗环境。 | 可见范围为实时屏幕环境反射。作者单独纹理反射、材质的非反射用途、具名资源和必需画布历史按原图。开档尚未有合格历史时报告准备中。 |

## 纹理资源逐类与分辨率

高性能从合格静态根色图作者链中取长边不超过 2048 的首个级，原长边不超过目标或无合格较小级时用原表示。自动只接受可证明的固定正交投影，以目标屏集合最大 drawable 相对作者画布的 cover、静态 zoom 和对象范围计算每轴向上取整的物理需求。同一源逐轴取各有效普通对象的最大需求，选择两轴都够用的最小作者级。同源有精确用途、已接纳动态模型查找或投影不能确定时，自动保原。放大且跨级时成组更新，缩回保留当前规格。高性能可让互相独立的普通用途用较小表示，实际精确用途和别名供体保原。

| 资源与实绘用途 | 高质量 | 自动 | 高性能 | 必须保持 |
|---|---|---|---|---|
| 原物理与映射尺寸一致、无图集/padding/动画的普通静态根色图，TEXB0003 内嵌 PNG／JPEG 作者链 | L0/原当前表示 | 选满足最大投影的真实级 | 选合格尾链 | 作者逻辑尺寸、归一 UV、颜色空间、alpha 和采样。仍用原载入 owner。 |
| 原生 BC1／BC2／BC3／BC5，raw 颜色、R8／RG8 | 原角色与上传路径 | 同左 | 同左 | 块布局、合法级、尺寸、原设备格式和通道语义。BC 尾链候选暂退出。 |
| 独立 PNG／JPEG 等 ImageIO 图像 | 原解码路径，普通图按比例以 4096 长边为上限 | 同左 | 同左 | 方向、ICC、覆盖、透明边、作者布局。按档向下解码仍是候选，交付须改变实际分配和绑定尺寸。 |
| 法线、掩码、位移、高度、光度、深度、LUT、多通道数据、跨材质精确采样、点采样像素图 | 原用途规格 | 原用途规格 | 原用途规格 | 通道含义、数值、像素对齐、opaque/straight/associated 表示。由消费类型决定。 |
| 图集含 padding、数值寻址、独立动画帧、翻页、模型合成、脚本持有的合法模型别名 | 原映射与规格 | 原映射与规格，除非用途已证明可以独立选级 | 独立普通消费者可减级，别名和精确使用保原 | 帧尺寸、实际归属层和脚本返回的资源对应。延迟图只在原到期准备采用档。 |
| named、临时 RT、Framebuffer 复制、效果图输出与历史、shadow atlas、alpha cutout 的精确模板、作者 Project 尺寸 | 每个生产者的原合同 | 每个生产者的原合同 | 每个生产者的原合同 | 路由、extent、代次、颜色／深度格式和消费时序。阴影和后处理自己的尺寸属于各自档位。 |
| 视频素材、Web 图片与作者创建的 WebGL/Canvas 资源 | 各引擎按已选择文件和作者 API | 同左 | 同左 | 不在 Scene mip 策略内。Video 规格必须来自真实更低规格文件。Web 若有声明的画质字段由作者处理。 |

## 特效怎样参与合成

按已经准备的图输入、同步顺序、附件读写、采样用途和输出表示分类。作者 Shader 或自定义组合通过同一套职责，不以效果名、作品路径或固定样本切路。

| 实际效果职责 | 画质设置能改变它的部分 | 与其它设置组合时保持的事实 |
|---|---|---|
| 模型、实体几何、图元、透明卡片、材质 cutout | 合格原生段的 MSAA 改覆盖和相机深度。阴影档改独立 shadow target；普通色图用途可用符合其 mip 合同的纹理档。 | 保作者 blend、正反深度、遮挡与写入顺序。无覆盖且无有效关联 RGB 的终端片元保原跳写深规则，保留零 alpha 仍有有效关联 RGB 的作者语义。套在贴图上的内部纹样走原采样。 |
| 普通 2D、文字、精灵、粒子和作者程序几何 | 兼容同域 PSO 时参与原生根 MSAA；只有被证实为可缩放颜色时才降纹理规格。 | 原字形、颜色、输出 alpha、sprite 动画帧、透明顺序、粒子出生/速度、作者相机运动。粒子采深、屏幕折射等使用真实附件时，按明确读写断点选择可执行域。 |
| 局部调色、噪声、模糊、像素化、扭曲、位移、自定义水面或光晕 | 采其合法颜色源时固有纹理过滤能与档位共同作用，实际源规格按类别决定。 | 作者 Program、参数、逻辑域、分配比例、输入资源和终端采样保持。全景后处理禁用仅撤全局 Bloom，局部作者效果照原职责执行。 |
| 具名图与历史、Fullscreen、Composition、Project、背景读回 | 合格几何在它之前 resolve，或先完成独立局部图再进原生段；需要已产生的逐样本深度时必须有真实存储合同。 | 同一来源、目标 identity、作用域、顺序、透明表示和历史 pin。保持独立目标尺寸，原根色读回时不得误用另一个背景。图结果只在原位置消费一次。 |
| 实时屏幕环境、作者专用反射、折射、自带纹理高光 | 用户反射开关只作用于现有实时环境消费者。 | 折射非环境读取、作者自有贴图、当前反射贡献的历史代次与基础 PBR 保持。开启时读取已完成的有效环境；关闭后不能读出本该退出的历史。 |
| 作者直接光、三种投影阴影、场景距离雾 | 阴影档只改变实际影图和可选阴影采样；体积档只作用选定的独立体积路径。 | 直接灯、相机深度、雾、作者是否投影、材质透明和体积是否有真实光路彼此保持，不由另一档补造作者未声明的贡献。 |
| 作者 HDR/普通 Bloom 与显示侧 | 后处理选全景 Bloom 算法和工作域，超高显示档确认实际目标屏后可更改终端 EDR。 | 独立 Bloom 源于完成的主颜色，含本帧实际体积。显示 mapping 写原输出；影图、相机深度、反射快照和作者持久 raw 都不读已映射显示颜色。 |

## 组合顺序与验收

1. 从同一用户请求和真实屏幕、内容、设备能力选择当前采用的档。作者时钟、属性输入与预设彼此独立。具名和局部图由实际依赖准备，原有的局部图、模型、普通层、粒子与聚光锥按源顺序交错执行。依赖具名材质的阴影在实际供货后准备。可提前的独立局部图只在原层序消费。光空间阴影和点光体积遮挡各持独立深度。
2. 根颜色按作者实际顺序合成。根采样决定颜色与相机深度附件和切点，同相机深度的模型与图像终端采用同一域。需要已完成颜色的 1× 段从相同根目标读取。点光体积在有序层完成后以独立遮挡积分加至主色，早于该点执行的作者读回使用此前已完成颜色。下一帧实时环境可取成功完成、含点体积且在终端 Bloom 前的主色。作者 HDR 且 `clear=false` 的必需 raw 仅在匹配池、代次和身份的历史中延续，冷切新 Surface 按新代接管，两个超高的热切仍在原 Surface。当前帧最终 Bloom、显示映射、原 drawable 呈现按这一顺序完成。
3. 同一真正输出先核每个档的独立作用，再选会共同消费同一物理资源的交互。MSAA×HDR/透明/作者读回核覆盖、近远遮挡、空 alpha 和终端色域。纹理×镂空阴影/显式 LOD 核绑定、孔洞和影边。阴影关×体积核作者投影资格与独立遮挡。体积×Bloom/反射核加光后终端和下一完成环境。反射×`clear=false`/named 核必需历史和开关代次。预设、多项手调、暂停、取消、导入、换作品、换屏及设备预算变更沿现有接管验证实际消费者。
4. 每个公开档需有一个能力适合的正常作品与一个独立的真实作品，至少一组有可解释的画面或覆盖差异和相应资源/算法证据。单档相邻对照须证每档自己的实际结果，同一作者时间与输入并核非目标区域，补无适用、规格相同、容量失败、切换中断和较旧回执的反例。显示 HDR 补混合屏三态，验证仅接入但未选中、目标组包含 HDR 屏以及原已保存请求在取消 HDR 目标后仍可见。失败须在作用范围或状态反馈中说明；未具备此证据的选项保持候选。
5. 受控验收使用同一实际 AppKit 手动操作或提交路径，验证已保存请求、准备收据、实际消费者、已显示画面或实呈时间和用户反馈。不能用内部专用开关绕过正常下发。参与的 GPU 测量包括实际 extent、附件和有效采样，物理呈现与性能长窗单独记录。涉及作者无适用内容的负例保证原合法画面可正常显示。
