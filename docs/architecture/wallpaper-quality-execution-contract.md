# 壁纸画质执行合同

<!-- document-role: stable-contract -->

本合同定义档位对当前画面的承诺、统一决策权和回执。算法比较、官版证据和预算门归[技术评估](../development/wallpaper-quality-settings-plan.md#decision)。实际交付范围、候选和未通过的验收归[现役工作卡](../development/wallpaper-quality-work-card.md#execution)。

## 修改怎样生效

`PlaybackQualityPreference` 唯一保存请求，`SceneQualityPreset.projection` 唯一定义预设组合。AppKit、v8 导入、复位和恢复使用同一请求类型。引擎执行投影由各自原消费者从准备事实和目标屏能力求出。设置页读取请求和运行结果，运行时无需读取控件或重新解释预设。 [值和预设](../../MyWallpaperX/Core/PlaybackControl/PlaybackPerformanceProfile.swift) · [Scene 原执行架构](../scene/architecture/runtime-architecture.md#effective-quality-policy)

| 操作 | 生效边界 |
|---|---|
| 单项手调 | 一次提交仅改变该字段。Scene FPS、同工作域的显示 HDR、Web 帧率建议在活动执行边界热更。Scene 抗锯齿、跨工作域后处理、纹理、阴影、体积及反射沿原同源候选重新准备。暂停使用现有冻结重绘或暂停候选。 |
| 选预设或复位 | 一次提交完整请求。依赖新准备的字段共用一个候选。热项按各自原执行边界采用，冷项只有随新画面接管才生效。相同向量无需重启。 |
| 连续调档、换壁纸或换屏 | 更晚的操作沿既有事务撤销旧候选。每个实际状态绑定活动请求及对应 Surface；更换 Surface 时从新执行事实取得。用户晚改先前的值以最终请求为准。 |
| 导入、恢复或失败 | 尚未采纳的导入显示「待应用」，继续原活动画面。复原活动播放时读取保存请求。候选失败保旧画面，反馈「应用失败」并沿现有同源动作重试。 |

手调完成以消费者的结果为准。只要作品有适用输入、当前设备能执行，独立变更必须改变实际调度、算法、物理资源或可见画面之一。若两个选项在当前作品或预算下会执行同一方案，保留全局请求并说明等效原因。已经知道当前作品无该效果、设备不支持或候选失败时，应明确反馈。设置页允许继续编辑可供下一适用作品采用的全局偏好。 [接管与失败](playback-lifecycle-transaction-design.md#三唯一产品事务)

## 实际档如何回显

下列状态为交付要求。已接入的选项和实际验证范围见[现役工作卡](../development/wallpaper-quality-work-card.md#execution)。

| 状态 | 依据和反馈 |
|---|---|
| 待应用／应用中 | 保存请求尚未由相应运行端采用／替代候选正在准备或等待新画面。可保留旧画面的实际档，须注明归属旧画面。 |
| 已采用 | 活动消费者确认实际规格、算法或调度。所需证据按下表；画面结论另由匹配的窗口捕获或实际呈现取得。 |
| 当前不适用 | 已知本作品无相应输入或消费者，例如无全景 Bloom、无投影灯。已保存请求在下一适用作品继续执行。 |
| 本画面等效 | 两档有合法消费者且实际执行值相同，例如投影范围只需同一影图 extent。回显实际值和已证的并档原因。 |
| 回退／不可用 | 已知能力、根域或资源约束，并且较低方案已经成功使用时回显实际值与原因；无法提供该效果时说明不可用。 |
| 结果待确认／应用失败 | 尚无有效执行证据时保留待确认。替代候选或热更失败时报告失败和仍在播放的有效结果。失败或迟到的提交不得改写有效回执。 |

回执由原本的资源、算法与调度消费者生产，按活动请求、Surface 与当前准备结果收敛。每屏可分别待确认、采用或回退，任一屏缺报也能读到其他屏的结果。同一 Surface 按实际值及理由筛选，新的活动请求或 Surface 都从自身结果重新确认。事件沿原合并窗口发送逐屏摘要，活动请求变化与跨屏值互换都能被识别。附加回执共用原生命周期和通知，变化才发，无逐帧 IPC、第二份持久状态或为回显扫描作品。AppKit 只能翻译已报告的事实。设置帧率上限、GPU 成功完成且请求呈现、窗口真正实呈各自用本职责的证据。

| 预设 | FPS | 抗锯齿 | 后处理 | 纹理 | 阴影 | 体积照明 | 反射 |
|---|---:|---|---|---|---|---|---|
| 低 | 10 | 无 | 禁用 | 高质量 | 低 | 高 | 关 |
| 中 | 15 | 无 | 启用 | 高质量 | 中 | 高 | 开 |
| 高 | 25 | MSAA 2× | 启用 | 高质量 | 高 | 高 | 开 |
| 超高 | 30 | MSAA 2× | 超高 | 高质量 | 超高 | 超高 | 开 |

预设名从保存的全向量派生，手调偏离向量显示自定，手调回到某档完整向量恢复对应名称。恢复默认采用 60 FPS、抗锯齿无、超高后处理、高质量纹理、超高阴影、高体积、反射开及 Web 随显示器。预设不改 Web 跟随模式、Video 原片和填充方式。某一字段回退时仍保留本次组合其余成功生效项。

| 设置与选项 | 如何执行当前画面 | 实际档必须来自 |
|---|---|---|
| 帧率 10–120 FPS，步长 1 | Scene 的目标节律取请求与目标屏集合共同可用上限的较小值。目标屏刷新率一致时用已知同值，混合或未知时取该组的保守上限且不超过 60。下调减少调度更新，上调允许更多更新。作者时基和速度沿原时钟，帧回调与本帧间隔随实际调度更新。暂停、可见性、渲染超时及显示节律会改变实呈频率。画布像素尺寸不随这个数值变动。 | 活动帧驱动的有效调度上限。实呈频率由窗口呈现时间计算，保存值、显示上限与实呈各有标签。 |
| 抗锯齿 无／2×／4× | 无用 1×。2×／4× 分别要求实际 Metal 附件、深度和 PSO 采用对应样本数。根合成按原层序开合，多样本段解析到同一主色。可安全共用的 1× 前缀／尾段保留原职责。根域不合格、附件不可用或前缀转换可撤销时可用 1× 成功出图，并回显原因。原生编码或 GPU 提交失败沿原掉帧／延后，保最近成功结果。8× 和 4× 自动降 2× 均为候选。 | 成功完成且已请求呈现的帧实际开启的根段样本数。最高成功样本用于简读数，混合帧只有原生段改变覆盖；纯 1× 退档与 4× 加 1× 尾段分开。退档回显区分已确认的设备限制、MSAA 准备失败与当前单采样路径。 |
| 后处理 禁用／启用／超高 | 禁用撤全景 Bloom 与超高的 HDR 工作域。启用在普通工作域用作者普通 Bloom 和原四次分离模糊。超高对作者 HDR 使用浮点工作域、HDR gain 和原浮点 Bloom 金字塔，作者普通输入继续普通 Bloom。作者禁用或零强度时无需生成对应泛光。终端映射始终保普通出画。作者 HDR 且 `clear=false` 使用同代持久 raw 合同，降为 SDR 工作域后仍保累积。 | 本帧有效工作域、实际启用的全景 Bloom 链及终端映射。区分作者本身无 Bloom、已开但没有亮源贡献和执行缺少必要资源。 |
| 后处理 超高（显示 HDR） | 与普通超高共用准备域、作者 HDR 内容及 Bloom。显示侧仅对当前选定且合格的目标屏申请 EDR，在设备能力和当前余量内输出。SDR 邻屏仍按普通超高映射。非目标 HDR 屏不影响菜单资格。保存后失去目标资格继续显示保存项并说明不可用。无独立 HDR 全局开关。 | 作者输出资格与各目标 Surface 的实际显示映射。需要证明扩展亮度时取匹配窗口的扩展线性像素。 |
| 纹理 高质量／自动／高性能 | 按[纹理资源表](#quality-textures)分别用原可用表示、满足投影的真实作者级、合格的较小作者级。档位只改变有资格的指定资源用途，不统一缩小 Scene 主目标或所有材质槽。 | 真正绑定的基级与尾链尺寸、适用用途和保原原因。Auto 要证明切换后发布了新资源。 |
| 阴影 禁用／低／中／高／超高 | 禁用停可选影图写入及接收采样。三个光种按[阴影与体积表](#quality-lighting)的规格工作。保作者投影资格、直接光、相机深度和镂空轮廓。 | 各参与光种实际写入并采样的影图尺寸以及比较滤波。预算回退按被影响光种报，保其他实际结果。 |
| 体积 禁用／高／超高 | 禁用撤点光遮挡重放、点光积分和聚光锥加光。高／超高按[阴影与体积表](#quality-lighting)采用实际积分阶数。低／中维持候选，只有各自有明确画面与成本结果才公开。 | 实际执行的点体积路径和阶数、聚光锥是否执行及与相邻档等效的范围。 |
| 反射 关／开 | 开启为实时环境消费者提供最近合格完成的场景颜色及必要 mip。首个有效历史到来前为准备中。晚到具名阴影占用原有顺序而跳过环境前置时，或可选资源准备失败时，回显具体受影响范围。关闭停止可选快照和采样，仍需合法槽的作者 Program 读到匹配范围和 mip 的不透明黑环境。作者自带反射纹理、独立反射特效、必需画布历史和同帧折射继续各走原用途。 | 真正绑定的实时环境来源及代次，或关闭后的黑源和已跳过的可选生产。无实时消费者时报告当前作品不适用。 |

## Web 与 Video 的实际范围

| 引擎与设置 | 消费与结果 |
|---|---|
| Web 随显示器／跟随动画帧率 | 随显示器给当前目标屏的建议值，最高 60。跟随模式经原作者 API 投递保存的 10–120 FPS 建议。按参与的文档分发，导航后新文档得到当前值。作者可以用它节流动画或忽略它。宿主只确认已投递，真实节奏以作者实际绘制验证。作者属性若自有画质档，独立按其声明传递。 |
| Video 原片与填充方式 | 选定文件的真实轨道与 AVFoundation 能力决定视频的像素、帧率、VFR 时间与 HDR 输出。完整显示／填充屏幕分别等比保全或等比裁切，冷热转换继续使用同一布局。Video 只消费自己的媒体与布局设置。Web 的 Scene FPS 跟随模式只投递建议，其余 Scene 画质字段专供 Scene。 |
| Video 下载规格 | Pixabay 提供哪几个真实源文件，就显示对应规格。改档影响新下载实际内容，详情读取已下载文件的轨道尺寸和标称帧率。已在播放的本地文件继续用其原轨道；离线更低规格派生要求独立能耗和音画门，尚无该播放档。 |

<a id="quality-lighting"></a>
## 阴影与体积逐档值

| 阴影 | 定向目标上限 | 点光每面与聚光目标 | 执行边界 |
|---|---:|---:|---|
| 禁用 | 无 | 无 | 可选光空间深度写入与接收比较退出。 |
| 低 | 512 | 512 | 原比较滤波按真实 texel 宽度工作。 |
| 中 | 1024 | 1024 | 取得更细的投影网格，实际使用受投影范围和资源预算约束。 |
| 高 | 2048 | 1024 | 定向可加密，只有点光／聚光且实际滤波和规格相同时有明确等效范围。 |
| 超高 | 4096 | 1024 | 定向继续加密。点光 1280／1536 分别是高／超高候选，仍以独立长窗为接入门。 |

定向按接收绘制所在 render pass 的目标长边选择网格。长边超过 2048 取 4096，超过 1024 取 2048，否则使用基线，再取档位上限。场景中的接收者边界另供投影拟合。点光用 3×2 atlas，512／1024 为每面分辨率，聚光用单图。紧预算继续沿原资源回退。在纹理尺寸、比较滤波或采样贡献相同的实际范围内说明并档。

| 体积 | 点光 | 聚光 | 与阴影组合 |
|---|---|---|---|
| 禁用 | 不建立可选积分／遮挡重放 | 不加锥光 | 表面直接光、作者距离雾照常；启用的表面阴影仍独立生成。 |
| 高 | 原尺寸四点积分 | 现役作者锥 | 独立遮挡深度维持。关闭表面阴影不取消已有体积资格。 |
| 超高 | 原尺寸六点积分 | 同一作者锥 | 指数零仍用解析线段，纯聚光场景允许等效并回显。六点 PSO 无法准备时原准备槽尝试四点。只在后备四点实际参与绘制后回显回退，两者均不可用则报告点光体积未执行。聚光保持独立。 |
| 低／中候选 | 每档分别减实际成本并维护遮挡边、窄亮峰和作者衰减形状 | 逐档算法与实际差异待证 | 同一相机和原深度参考下先证每档的画面与独立稳定收益，再接公开设置。 |

## 纹理资源逐类与分辨率

高性能从合格普通静态根色图的作者链中取长边不超过 2048 的首个级。原长边不超过目标或没有满足上限且合格的较小级时继续使用原表示。自动只接受可证明的固定正交投影，以目标屏集合最大 drawable 相对作者画布的 cover、静态 zoom 和对象范围计算每轴向上取整的物理需求。同一源逐轴取各有效普通对象的最大需求，选择两轴都够用的最小作者级。同源有精确用途或投影不能确定时，自动保原。有动态模型查找请求或保留动态默认别名时，现役 Auto 对整场保原。后续按来源缩小限制须正向证明可达用途。放大且跨级时成组更新，缩回保留当前规格。高性能可让互相独立的普通用途用较小表示，实际精确用途和别名供体保原。两种独立用途可同时绑定原规格和小级，报告各自的绑定与实际分配。

| 资源与实绘用途 | 高质量 | 自动 | 高性能 | 必须保持 |
|---|---|---|---|---|
| 原物理与映射尺寸一致、无图集/padding/动画的普通静态根色图，TEXB0003 内嵌 PNG／JPEG 作者链 | L0/原当前表示 | 选满足最大投影的真实级 | 选合格尾链 | 作者逻辑尺寸、归一 UV、颜色空间、alpha 和采样。仍用原载入 owner。 |
| 原生 BC1／BC2／BC3／BC5，raw 颜色、R8／RG8 | 原角色与上传路径 | 同左 | 同左 | 块布局、合法级、尺寸、原设备格式和通道语义。BC 尾链候选暂退出。 |
| 独立 PNG／JPEG 等 ImageIO 图像 | 原解码路径，现有普通图按比例以 4096 长边为上限 | 同左 | 同左 | 方向、ICC、覆盖、透明边、作者布局。按档向下解码仍是候选，交付须改变实际分配和绑定尺寸。 |
| 法线、掩码、位移、高度、光度、深度、LUT、多通道数据、跨材质精确采样、要求原像素格的逐 texel 素材 | 原用途规格 | 原用途规格 | 原用途规格 | 通道含义、数值、像素对齐、opaque/straight/associated 表示。由消费类型决定。 |
| 图集含 padding、数值寻址、独立动画帧、翻页、模型合成、脚本持有的合法模型别名 | 原映射与规格 | 原映射与规格，除非用途已证明可以独立选级 | 独立普通消费者可减级，别名和精确使用保原 | 帧尺寸、实际归属层和脚本返回的资源对应。延迟图只在原到期准备采用档。 |
| named、临时 RT、Framebuffer 复制、效果图输出与历史、shadow atlas、alpha cutout 的精确模板、作者 Project 尺寸 | 每个生产者的原合同 | 每个生产者的原合同 | 每个生产者的原合同 | 路由、extent、代次、颜色／深度格式和消费时序。阴影和后处理自己的尺寸属于各自档位。 |
| 视频素材、Web 图片与作者创建的 WebGL/Canvas 资源 | 各引擎按已选择文件和作者 API | 同左 | 同左 | 不在 Scene mip 策略内。Video 规格必须来自真实更低规格文件。Web 若有声明的画质字段由作者处理。 |

| 1920×1080 → 960×540 → 480×270 | 1920×1080 | 需求 480×271 取 960×540 | 1920×1080 |
| 4096×2048，只有原级或所有可用小级不合格 | 4096×2048 | 4096×2048 | 4096×2048，说明保原 |

现行静态色图资格为原生单输入透明、无深度的普通 quad，且没有父子层、依赖、混合式实色、模型、utility 或作者 effect（含隐藏实例）。最近点和线性都保材质原 sampler。最近点采样本身可用于普通归一色图，依赖逐 texel 或物理像素格的用途则必须保原格。色源有实际合成效果时，相同 UV 采样保输入角色和原滤波，纹理降档只改变选中基级的细节与尾链接续。写入物理像素尺寸、像素步距或显式 LOD 的用途仅在能保持原语义时允许选级。没有可确认用途时沿现有采样资格保原表示，旁路的普通消费资格仍按其自身事实判定。合法链的小级解码或上传失败时，冷准备沿原 Loader 尝试原级。已显示的 Auto 热升失败时保留已发布表示。坏容器沿原局部失败范围。以 GPU 实际绑定的基级尺寸和作者尾链证明资源生效。逐片元 LOD 和尾链各级像素用可辨 mip 颜色读回证明。反馈原因取原选级结果，最终 L0 单独无法说明原因。 [TEX, Auto 和源用途](../scene/architecture/runtime-architecture.md#scene-texture-quality-policy)

<a id="quality-effect-families"></a>
## 特效怎样参与合成

按已经准备的图输入、同步顺序、附件读写、采样用途和输出表示分类。作者 Shader 或自定义组合通过同一套职责，不以效果名、作品路径或固定样本切路。

| 实际效果职责 | 画质设置能改变它的部分 | 与其它设置组合时保持的事实 |
|---|---|---|
| 模型、实体几何、图元、透明卡片、材质 cutout | 合格原生段的 MSAA 改覆盖和相机深度。阴影档改独立 shadow target；普通色图用途可用符合其 mip 合同的纹理档。 | 保作者 blend、正反深度、遮挡与写入顺序。无覆盖且无有效关联 RGB 的终端片元保原跳写深规则，保留零 alpha 仍有有效关联 RGB 的作者语义。套在贴图上的内部纹样走原采样。 |
| 普通 2D、文字、精灵、粒子和作者程序几何 | 普通终端以匹配的色／深 PSO 参加合格根段。现役根段要求有实际模型，粒子或聚光参与时依其采样和层序约束决定切点或退回 1×。只有已证可缩放颜色按纹理档选级。 | 原字形、颜色、输出 alpha、sprite 动画帧、透明顺序、粒子出生/速度、作者相机运动。粒子采深、屏幕折射等使用真实附件时，按明确读写断点选择可执行域。 |
| 局部调色、噪声、模糊、像素化、扭曲、位移、自定义水面或光晕 | 采其合法颜色源时固有纹理过滤能与档位共同作用，实际源规格按类别决定。 | 作者 Program、参数、逻辑域、分配比例、输入角色和终端采样保持。若图读取了受纹理档影响的上游主色，可观察到其输入细节变化。后处理禁用撤全局 Bloom。跨到 SDR 工作域也停止作者 HDR 增益，局部效果照原职责运行，输入亮度可随工作域改变。 |
| 具名图与历史、Fullscreen、Composition、Project、背景读回 | 合格几何在它之前 resolve，或先完成独立局部图再进原生段；需要已产生的逐样本深度时必须有真实存储合同。 | 同一来源、目标 identity、作用域、顺序、透明表示和历史 pin。保持独立目标尺寸，原根色读回时不得误用另一个背景。图结果只在原位置消费一次。 |
| 实时屏幕环境、作者专用反射、折射、自带纹理高光 | 用户反射开关只作用于现有实时环境消费者。 | 折射非环境读取、作者自有贴图、当前反射贡献的历史代次与基础 PBR 保持。开启时读取已完成的有效环境；关闭后不能读出本该退出的历史。 |
| 作者直接光、三种投影阴影、场景距离雾 | 阴影档只改变实际影图和可选阴影采样；体积档只作用选定的独立体积路径。 | 直接灯、相机深度、雾、作者是否投影、材质透明和体积是否有真实光路彼此保持，不由另一档补造作者未声明的贡献。 |
| 作者 HDR/普通 Bloom 与显示侧 | 后处理选全景 Bloom 算法和工作域，超高显示档确认实际目标屏后可更改终端 EDR。 | 独立 Bloom 源于完成的主颜色，含本帧实际体积。显示 mapping 写原输出；影图、相机深度、反射快照和作者持久 raw 都不读已映射显示颜色。 |

<a id="quality-combination-checks"></a>
## 组合顺序与验收

1. 从同一用户请求和真实屏幕、内容、设备能力选择当前采用的档。作者时钟、属性输入与预设彼此独立。具名和局部图由实际依赖准备，原有的局部图、模型、普通层、粒子与聚光锥按确定的作者层序交错，包含作者定义的透明深度排序。依赖具名材质的阴影在实际供货后准备。可提前的独立局部图只在原层序消费。光空间阴影和点光体积遮挡各持独立深度。
2. 根颜色按作者实际顺序合成。根采样决定颜色与相机深度附件和切点，同相机深度的模型与图像终端采用同一域。需要已完成颜色的 1× 段从相同根目标读取。点光体积在有序层完成后以独立遮挡积分加至主色，早于该点执行的作者读回使用此前已完成颜色。下一帧实时环境可取成功完成、含点体积且在终端 Bloom 前的主色。作者 HDR 且 `clear=false` 的必需 raw 仅在匹配池、代次和身份的历史中延续，冷切新 Surface 按新代接管，两个超高的热切仍在原 Surface。当前帧最终 Bloom、显示映射、原 drawable 呈现按这一顺序完成。
3. 各选项只对自己负责的资源和执行边界生效。相同资源出现两个请求时优先保作者语义和依赖完整性，按实际约束回显降档。一起编辑得到同一偏好向量，冷准备采用该快照；预设、连续手调、导入、暂停、取消、换作品、换屏与预算变化都验证归属和可见接管。

| 必测组合 | 像素及执行不变量 |
|---|---|
| MSAA × 透明／相机深度／作者读回／HDR | 保透明顺序、关联颜色和原作者采深。只在原生段改覆盖，读回取得已经完成的同一主色，终端映射只执行一次。已有 1× 逐值深度不能伪装成 2×／4× 相机深度。 |
| MSAA × 点体积／实时环境／具名材质 | 以实际遮挡、颜色历史、具名供货和深度依赖决定可用根段。实际点光积分在有序层末尾从独立 D32 取遮挡。合格多样本根段先解析到原主色，再由 1× 加光。仅有体积声明或没有实绘贡献时，根段照常结束。活动具名模型色图、实时环境或已有 1× 深度前缀仍可能使整根落到 1×，按实际路径回显。先改 MSAA 再改另一档，也换次序验证。体积覆盖实际积分、仅有声明却没执行积分及关闭三态，核深度、环境代次和每段覆盖。 |
| 纹理 × 镂空阴影／显式 LOD／共享材质 | 精确 mask 保原级，普通色图按各自资格下采样。检查前景孔洞、影边、颜色细节及每个实际绑定，图集与原始坐标不变。 |
| 阴影关 × 体积开 | 表面影图和接收比较停掉，体积按作者资格继续使用独立遮挡，直接光与作者雾保持。 |
| 体积 × Bloom／反射 | 体积增量先写当前主色，Bloom 从完成颜色取亮，实时环境由下一帧按完成历史读到该贡献。 |
| 反射关 × `clear=false`／named／折射 | 可选实时环境退出，明确的环境槽走黑源；同帧前缀、作者命名生产者、持久 raw 和独立折射仍有原实际供货。 |
| FPS × 所有画质档 | 帧率按目标屏和运行能力约束。作者运动在等时间点具有同一语义，比较画面锁定实际相位。降低层级不能顺带修改作者计时、输出尺寸或视频轨道。 |

## 验收与交付

1. 每项公开能力用一个合适的普通作品与一个独立真实作品验实际消费。离散画质档在适用对象上证明资源／算法及可解释的像素、覆盖或成本变化。连续 FPS 用边界、步长、相邻或代表值验证有效调度和实呈。Web 先验实际文档交付，再以接受建议的作者验证绘制，以忽略建议的作者验证作用边界。Video 的新下载档以实际文件与播放轨道验证。相邻档在各自实际范围内验证正常、适用但等效、内容无关、容量失败、切换中断及迟到回执。作品画面对照用相同作者时间和输入并核邻区。显示 HDR 补仅接入未选、目标组有 HDR 屏、已保存后目标退出。未过对应证据的新增选项保持候选。
2. 受控验收使用同一实际 AppKit 手动操作或提交路径，验证已保存请求、准备收据、实际消费者、已显示画面或实呈时间和用户反馈。不能用内部专用开关绕过正常下发。参与的 GPU 测量包括实际 extent、附件和有效采样，物理呈现与性能长窗单独记录。涉及作者无适用内容的负例保证原合法画面可正常显示。
3. 每个纵向批次在原设置窗口执行相邻档 A→B→A 或一次原事务可比的单向修改。验收证据需同时连接用户动作、活动身份、实际消费和输出／成本；恢复档复现基线。原作者动态造成的像素差、模拟设备结果、单次峰值和只成功创建资源分别限定用途。样本、通过范围及未发布选项只维护于[现役工作卡](../development/wallpaper-quality-work-card.md#execution)。
