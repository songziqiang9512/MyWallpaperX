## 1. 授权、范围与唯一顺序

状态：2026-11-13，**P0 设计/生图阶段；等待用户认可效果图并同意执行**。分支 `MWX/ui-immersive-redesign`，起点为原 `codex/engine-refactor-program`。本轮尚未改写产品 UI，不提交、不推送。视觉、交互及功能映射以[设计规范](immersive-ui-design.md)为唯一权威；本文只管理依赖、实施、退役和验收。

用户本轮要求取代旧侧栏、常驻工具栏、方卡等全部旧 UI 目标；原引擎、数据、来源服务与事务职责继续工作。不得只做首页外壳便将任务结项。功能清单以[规范第 11 节](immersive-ui-design.md#capability-map)为准，每行最终要有明确结果或待解决项。

本批写入范围：本规范/计划、旧主界面方案的目标退出指针、文档入口、文档角色索引、设计登记和与之对应的文档预算。参考项目只读保留在 `Reference Project/folia-major`；生图材料在 `.artifacts/ui-immersive-design/`，不把图片及参考仓库纳入产品或 Git。新增两份设计文档是用户明确要求的规范与流程交付，分别拥有“是什么”和“如何完成”，不是重复计划；审批前产品代码净增长为零。

## 2. 阶段与停止条件

| 阶段 | 最小完整结果 | 主要职责范围 | 必须完成的验证与退出 |
|---|---|---|---|
| P0 研究与设计 | 固定参考版本、完整规范、功能迁移表、四种关键状态效果图 | 设计文档与登记、生图材料 | 文档/链接/设计门；逐图审查比例、聚焦、导航和工具；收到用户同意执行前停在这里 |
| P1 原生几何切片 | 在同一候选 Shell 中打通二维画布、原图比例、稳定大小、复用与手势 | 原 GridController、ScrollView、一个新 layout、统一 cell；隔离 fixture | Debug build；真实窗口横纵/斜向惯性、跨坐标重定位、捏合、点击/拖动区分、退入窗口；只验证几何，不先铺设所有面板 |
| P2 主窗与本地完整链 | 八胶囊、单工具入口、两个本地来源、详情/预览、明确应用、播放底条 | 主窗口装配、Shell、原 Commands/Inspector 接线 | 导入→浏览→选择→详情→应用→暂停/切换→关窗重开；不会因导航改变播放；替换完成即删旧主窗侧栏/工具栏及本地卡呈现 |
| P3 在线与下载 | 四在线来源全部接新墙/筛选/登录；下载聚合与任务管理 | 原来源 UI adapter、工具子页、任务/登录表单 | 各源查询/取消/换页/迟到/失败；登录只影响对应源；下载→发布→本地应用，真实账号可用性单独声明；删除原在线网格/工具栏 UI |
| P4 列表与组织 | 目录、列表页、喜爱/最近、多选、拖入列表、编辑/撤销完整 | 原关系 Commands、目录/Picker/Artwork、新表单 | 新建→导入/添加→跨类型播放→重命名/复制→移除/撤销→删除；副本不重复计数；删旧列表目录、header、侧栏拖入和选择面板 |
| P5 全部附属界面 | 六页设置、Web/Scene 属性、屏保、状态栏、关于/帮助/更新入口统一 | 原设置/属性/系统/状态栏 UI owner | 设置往返和真实消费者、输入法/快捷键、参数保存/取消、屏保边界、关主窗后控制；旧附属 UI 逐项删除 |
| P6 完整接管与试用 | 一套 AppKit UI，全功能表与未解决项完成结算 | 当前 UI 及对应文档/测试/项目引用 | 相称行为门、Debug build、隔离真实运行、完整 UI 检查；用户试用确认；零旧 UI 路由/回退、零新增 SwiftUI/Web UI；未授权不提交/推送/安装 |

P1 是原生可行性的先验切片：若 NSCollectionView 有界副本窗口不能无缝保住原生惯性或真实比例，先在同一设计文档重评集合与 clip 的接法，不把失败藏进“暂时纵向滚动”的实现。达到阶段结果后进入下一项，不反复只优化 hover 而遗留来源、设置或编辑功能。

获用户同意执行后，先把本规范确认项写回并更新设计登记，同步 [AppKit 合同](../architecture/appkit-migration.md)中主窗口由强制 source list/NSToolbar 转为沉浸 Shell 的目标；保原生 AppKit、0 SwiftUI 与唯一产品状态边界。完成这些目标对齐再写 P1 产品代码，不能让旧装配目标和新设计同时裁决实现。

每阶段先给出精确路径集合、核对 Git 状态；按原 owner 内替换优先。跨目录必要，但不借 UI 重构扩张到引擎算法、认证/下载机制或用户数据库重做。共享 JSON 与全仓质量基线只由本会话合并精确项，保其他会话内容。

<a id="retirement"></a>
## 3. 旧 UI 退役对应表

表内类型是当前核查的起点，删除前查真实调用者；不能按文件名批删业务。替换阶段中，只允许一个主窗口装配入口。未迁移页面可由该入口暂时挂载旧子控制器，但不能把它称为完成；其旧样式与生命周期必须在所属阶段结束时退出，最终不保经典模式开关。

| 旧呈现 / 入口 | 承接结果 | 退出阶段 |
|---|---|---|
| `AppKitMainSplitViewController` 主窗分栏装配、`WallpaperLibrarySidebarController` | 新沉浸 Shell、胶囊导航与列表接收区；Inspector/生命周期必要职责接回新 Shell | P2 主窗路由；P4 清完列表拖入残留 |
| `WallpaperLibraryWindowToolbar` 与各来源 ToolbarController | 单工具面板、胶囊专属内容、原生主菜单同命令 | P2 本地，P3 在线 |
| `WallpaperLibraryPageChrome`、旧页标题/提示布局 | 短上下文、局部状态与一致的空态/错误反馈 | P2–P4 随页面退出 |
| 方卡 metrics、各源 GridItem/卡内玻璃 bar | 真实比例 layout、统一新 cell、最小来源 adapter | P1–P4 随消费者退出，不能最后再留一套重复布局 |
| 来源自建网格/预览呈现 | 同一个画布与 cell，原图片/动画 producer 复用 | P3；无消费者的旧 UI 与预取装配同批删除 |
| 旧 Inspector 容器与详情排版 | 原 InspectorCoordinator 接聚焦面板；原业务/预览能力继续由原 owner 承担 | P2 基础、P3 来源详情、P5 属性表单 |
| `AppKitPlaylistDirectoryController`、旧 Header/Picker/列表编辑外观 | 新目录墙、胶囊列表、自定义选择/编辑 sheet | P4 |
| `AppKitSettingsContainerView` 旧导航与排版、旧 UI 偏好投影 | 新六页设置；可保原依赖/动作绑定，不保旧 view 树或空 wrapper | P5 |
| 下载 Popover、登录/API、Scene/Web 属性、屏保配置、状态栏旧外观 | 同一语言的任务页/表单/窗口/状态面板 | P3/P5 |
| 旧首图染色/侧栏宽度/列数等 UI 专属无消费者字段与测试 | 新外观/密度/锚点；保业务设置与原图缓存，入口一次映射或使用默认 | 每个实际消费者替换时一并删除 |
| 本轮目标已退出的旧文档视觉条款与失效源码形状测试 | 新规范与真实行为断言；关系/播放语义收回原合同 | P6 文档最终合并，不留旧视觉裁决并列 |

新增职责的理由：一个画布 layout 承接旧固定方格不能表达的二维/真实比例几何；一个沉浸 Shell 承接旧 split/toolbar 的全窗布局，**替代**旧装配；一份统一 cell 退役多来源 UI 副本。其余优先改原 controller/view。不得再增“通用 UI 平台”、第二 Workspace、另一个播放状态树、全局事件总线或常驻布局监控器。

## 4. 验证矩阵与证据等级

| 范围 | 真实动作与反例 | 使用现有门 / 运行边界 |
|---|---|---|
| 比例与稳定几何 | 横/竖/方/超宽/长图、方向修正、尺寸未知后回填；前后往返位置不洗牌 | 扩现有 `test_wallpaper_library_grid.py`、`test_ui_library_algorithms.py`；断言产品布局值，不抄实现 |
| 平移/缩放/命中 | 两轴/斜向/惯性与反向、跨副本窗口、缩放锚点、滚动后点击和复用 | 原 `test_grid_scroll_interaction.py`；真实 AppKit 窗口/触控板补验，合成事件只认其覆盖范围 |
| 缩略图与生命周期 | 同媒体多副本、退出视口/切页、A→B 迟到、清缓存、关窗重开 | 原 grid lifecycle/thumbnail 门；不取消其他可见消费者，不以占位消失证明流畅 |
| 导航与面板 | 非当前项一次切页、当前项展开/收起、子页切换、外点不穿透、Esc/焦点、最小窗口 | 扩 `test_native_ui_equivalence.py` 等最近原生行为门；真正发输入到新控件 |
| 播放隔离 | 浏览≠播放、选中≠应用、最新切换意图、失败保当前输出、系统暂停状态 | 既有 grid playback、command multiplexer、sequence 门；隔离代表图片/视频/Web/Scene 应用 |
| 在线/下载 | 分页去重、错误/取消/迟到、账号切换、本机历史离线可见、发布后应用 | 原各来源 HTTP/下载控制/任务门；受控响应不冒充真实在线服务 |
| 关系/列表 | 副本去重、缺文件保关系、多选/删除/撤销、拖入列表、目录顺序/封面 | 原 playlist directory/picker、metadata、collection 门；保真实用户库只读 |
| 设置/属性/系统 | 所有字段有可达入口，当前值与原消费者一致、输入提交/取消、屏保诚实说明 | 现有 settings/property/screen-saver 门；运行副本不覆盖真实偏好/媒体 |
| 辅助功能/动效 | VoiceOver 唯一媒体、全键盘、输入法、减少动态/透明度、高对比、深浅 | 原生窗口实际观察；生图不能代替此项 |
| 性能成本 | 滑动不全库重算/解码、只有当前卡动态预览、关窗无新增常驻工作 | 现有需求/投影效率门 + 有界实际操作采样；先记环境与同条件基线，不预写“120 Hz/低功耗已达成” |

实施批次先从 `script/verify_scene_change.py --phase inner --path <实际路径>` 预览选中门，按当前 `--help` 与 manifest 执行；Swift 产品变化补 checkpoint Debug build，可见/生命周期变化补隔离运行。无关的全仓存量失败单列，不能降门、改数字或改引擎凑全绿。没有产品改动的 P0 不运行 App build。

每阶段分别记录产品/测试/文档增删与必要的新状态；代码净增长须能对应清单中的实际能力。通过一个窗口或一个来源只证明其范围，不代表全界面交付。真实用户媒体只读，样本、HOME、App、截图和运行输出按项目现有隔离流程放置。

## 5. 最终完成定义

以下全部成立才可以宣告 UI 重构完成：

1. 规范第 11 节每项功能均有新入口，所有来源/设置/附属表单同一语言，不残留旧侧栏、工具栏、方卡及旧详情外观。
2. 原生窗口实际实现真实比例、稳定大小、双向连续漫游，只有 hover/选中聚焦；最小窗口与原生全屏均可操作。
3. 胶囊一击切页/再次展开与工具单按钮行为真实成立；搜索、筛选、详情、任务、表单、焦点和 Esc 无互相抢输入。
4. 导入、下载发布、关系、播放队列与三引擎/静态应用仍沿原权威；跨页不串播放，失败不抹掉当前有效壁纸。
5. 无经典 UI 活路由、重复 cell/预取/toolbar owner、空 wrapper、无消费者偏好或失效测试；Xcode/脚本引用和权威文档已同步。
6. 适用行为门、Debug build 和隔离代表运行通过；未覆盖的真实账号、多显示器、系统宿主/触控板等明确记录，不用生图或 build 代替。
7. 用户试用确认；产物已限量保留与清理；Git 精确路径审查完成。提交、推送、安装与发布分别依用户当轮授权执行。

失败恢复范围按层收敛：坏缩略图留占位，来源失败保原列表，表单失败保草稿，播放失败沿原事务保有效输出。开发候选发现问题先修对应阶段或回退本批精确 UI diff；不重置用户库，不把永久旧 UI fallback 当作完成。

开工前文档基线：`document_health.py --check` 通过；`document_registry.py --audit` 当时有一项未登记文档（Scene 引擎早期设计稿，现已归档）。本批新增文档与路由需全部正确。
