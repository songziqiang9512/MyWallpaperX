## 1. 已确认的范围与裁决

| 编号 | 用户已确认的规则 | 设计影响 |
|---|---|---|
| D1 | 侧栏严格采用“资料库 / 浏览 / 播放列表”三组和指定顺序 | 不新增 Music 的主页、广播或商店，不保留旧的图片/在线/Steam 独立分组 |
| D2 | 暂不纳入底部悬浮播放条 | 沿用菜单栏、状态栏、快捷键及页面既有播放入口；不预留空底栏 |
| D3 | 使用系统强调色 | SF Symbols、按钮、选择标记跟随系统；不固定 Music 红、不把封面取色变成控件强调色 |
| D4 | 全部壁纸使用现在 Steam 的方形卡片，包括内部控制 bar | 不给壁纸另造 Music 专辑卡；列表目录卡才使用“方形封面 + 下方名称” |
| D5 | 最近使用按壁纸去重，保留最近 50 张，重复成功播放移到最前 | 按成功应用时间倒序；不是 50 次播放事件，也不是最近下载或导入 |
| D6 | 视频与图片同名标签自动合并成混合播放列表 | 保留全部成员及原顺序依据，不按来源拆成两个同名列表 |
| D7 | 混合列表支持现有顺序/随机和自动切换设置 | 统一规划图片、视频、Web、Scene 的候选、计时、失败和跨类型交接 |
| D8 | 心形统一表示本地“特别喜爱”，Steam 订阅独立保留 | 不把原 Steam 订阅记录迁入本地喜爱；订阅改用书签入口并保留原服务 |
| D9 | 只有本地或已下载内容可加入喜爱/列表 | 未下载浏览项不创建关系、不隐式下载；下载完成后用户再主动加入 |
| D10 | “我的下载”是各来源本地发布内容的聚合页，通用工具栏与下载管理面板归独立Downloads模块 | 退出Steam专属账号/任务工具栏委托；各来源下载执行、认证、发布、播放和详情仍原owner；下载历史只读本地记录，不以登录作查看许可 |
| D11 | 前轮侧栏首图轻染、Steam网格度量、toolbar分组、默认5列/可选3–6列、紧凑列表头与顶部安全距 | 继续有效；旧堆叠目标由D12替换，前轮实施与限定证据已归档，不作本轮验收 |
| D12 | 单封面、紧凑编辑、独立返回、稳定拖选及详情无位移继续保留；所有编辑/选择/登录面板采用系统sheet调暗与模态输入 | 普通确认仍原NSAlert；自定义内容保当前排版与玻璃材质，优先由原生sheet呈现；不能等价保布局时只在原modal owner补统一调暗，退役避灰罩目标，不另建窗口/输入registry |
| D13 | 本轮五项补充：在线无下拉计数；本地卡只拖侧栏快加；目录名左/数量右同排；自建Header标题后小计数；Steam登录窗不可拖 | 当前覆盖Q01/Q06/Q09；保目录及侧栏列表让位排序，取消媒体成员拖排；不做计数备用入口 |

本轮在原隔离树实施，保留主仓及启动专项树。设备独占须提前与启动专项协调，不把空锁/经过时间当释放；当前先静态开发，最近原生门及Debug统一安排，不在每个小文案修改后全量重建。没有本轮提交授权。旧的“无底部播放条”“控件使用系统强调色”“卡片只轻微hover放大、无按下缩放（§21修订）”“白色 hover 描边”“属性面板保持排版和隐藏滚动条”“不为测试抢焦点补逻辑”继续有效。

除 D1–D13 外，具体尺寸、缺失关系保留、暂停时冻结轮换剩余时间、健康同项重选刷新最近和关系撤销等属于方案细化，仍须最终验收，不冒充既有能力或用户逐项确认。旧审计与N15候选见§13历史入口，最新待办查§22，§15–19为前轮实施与证据；上一候选记录见§15.4，当前状态以§22为准，门通过不等于用户最终验收。全局上下张与视频工具栏历史导航的既有差异默认保留，详见第 8 节。

## 3. 信息结构与路由

侧栏自上而下固定如下；括号内是设计 identity，不是展示文案。第一组视频/图片无标题；随后“资料库 / 浏览 / 播放列表”标题不可选、可折叠，默认展开并保原折叠状态。

| 组 | 顺序 / 标题 | 路由 | 数据范围 / 图标建议 |
|---|---|---|---|
| 无标题首组 | 1 我的视频 | localVideos | 本地导入、内置视频；`film` |
| 无标题首组 | 2 我的图片 | localImages | SIL 本地图片；`photo.on.rectangle` |
| 资料库 | 1 我的下载 | downloads | Steam、Pixabay、Wallhaven、Pixiv本地发布项联合投影；`arrow.down.circle` |
| 资料库 | 2 最近使用 | recent | 成功应用过的最近 50 个规范引用；`clock.arrow.circlepath` |
| 浏览 | 1 创意工坊 | workshop.discovery | 现有发现、分类、作者入口；`shippingbox` |
| 浏览 | 2 Wallhaven / 3 Pixiv / 4 Pixabay | wallhaven / pixiv / pixabay | 原来源浏览、分类、账号与搜索；品牌名不代称在线库 |
| 播放列表 | 1 所有播放列表 | playlists | 新建卡 + 用户播放列表目录；`square.grid.3x3` |
| 播放列表 | 2 特别喜爱 | favorites | 各类型本地喜爱关系的联合投影；`heart` |
| 播放列表 | 3… 用户列表 | playlist(UUID) | 侧栏顺序按 sidebarRank；封面缩略图，缺图采用共享媒体语义符号；单封面与状态见V01/V04 |

“自动显隐”指创建/删除列表后同步增减侧栏节点，**空列表仍显示**。不自动隐藏空列表，不在用户不知情时删除它；本轮不新增“固定到侧栏”开关。无自建列表时仍保留两个固定入口。用户列表默认按创建先后置于末尾，可拖动排序，固定入口和三组不能拖动。

当前页面与播放来源分别保存：点侧栏只浏览，不改变正在播放的列表。新列表创建后选中并进入该列表；删除当前列表返回“所有播放列表”，播放中的内容不因此停播。重命名不改变 URL/UUID、滚动位置和队列来源。设置继续独立窗口，菜单 `⌘,` 与既有入口保留，不新增侧栏设置页。

“我的视频”最终只呈现本地/内置归属；为播放下载内容而静默导入的 Video backing record 仍保留给播放器，但不在“我的视频”重复露出。迁移只有在明确下载 provenance/文件归属时才归并；不能证明来源的旧条目继续可见，禁止按标题、文件名相似或 hash 猜归属。

## 4. 统一视觉标准

### 4.1 主窗口、侧栏与背景

| 项目 | 首版标准 | 原生实现 / 边界 |
|---|---|---|
| 窗口 | 保持当前最小 900 × 650 pt；常用验收 1200 × 800、1440 × 900；全屏同一结构 | 复用 NSWindow / NSSplitViewController，不重绘交通灯、窗角或阴影 |
| 侧栏 | 初始220 pt，可拖200–320 pt，始终开启；移除toolbar/主菜单显隐和分割线收拢 | 原source-list NSOutlineView；保宽度保存，旧collapsed恢复为开启，不能通过原生toggle selector重新收拢 |
| 行 | 实际命中行高30 pt；符号、无图占位及封面统一22 pt对齐框；文字和SF符号由原生source-list配置，选中沿原生字重，媒体行相对组标题轻缩进，全部符号/封面同一前缘 | 同一SidebarRowCellView度量；当前SDK挂载后13 pt字体/符号配置，不能以全局systemFont对象或预配20 pt冒充原生最终样式；封面到达不移动文字，组折叠三角沿系统 |
| 组标题 | 11–12 pt semibold，secondaryLabelColor；组前留 16 pt，标题与首行 6 pt | 不给标题叠玻璃胶囊、不显示数量按钮 |
| 选中 | 原生圆角中性灰，保持当前稳定的非强调选中呈现；文字高对比 | 复用现 SidebarRowView；不能先蓝后灰，不强制窗口或焦点激活 |
| 图标 | SF Symbols template + controlAccentColor；图标与封面同一22 pt对齐框，符号沿挂载后的原生source-list配置 | 不写固定 RGB 蓝/红，不重复设置被Outline覆盖的字号；状态错误/警告另用系统语义色及图标 |
| 侧栏计数 | 默认不在每行右侧常驻计数；数量按Q09分别由标题、目录卡或本地下拉提供，AX可读 | 避免数字列抢占名称空间；未完成加载不把未知显示成 0 |
| 侧栏与主背景 | 共同消费当前列表首张缩略图，轻度染色及 0.75 s 过渡；两面同步可见 | 复用 AppKitListBackgroundTint / ListThumbnailTintSource，侧栏用显式被动染色宿主；内容区一层底色，不全幅叠 NSBox/玻璃；本轮状态见V04/V10 |
| 材质 | 侧栏恢复旧版不透桌面的系统底色，叠原轻染；toolbar仍由系统负责，内容区不铺玻璃 | 原同一Tint source与投影，去behindWindow桌面混色；不新增取色/缓存，不降低整窗alpha；旧版强度深0.12/浅0.09先保同图对照，不凭主观猜测改饱和度 |
| 深浅模式 | 跟随系统外观；不为模仿暗色参考图强制全 App dark | labelColor / secondaryLabelColor / separatorColor，减少透明度和提高对比度时仍可读 |

默认“列表封面取色”保留已接受的轻染强度和 0.75 s 过渡、侧栏与主背景共同跟随；可选“macOS原生”模式按§18 T07退出取色与opaque覆盖。排序/筛选/搜索改变真正的第一条内容后更新来源，重排导致首图不变则不重采样；滚动、选中、hover 不换背景。“所有播放列表”固定的新建卡不参与取色，从它之后首张实际列表封面取色；列表目录为空、登录/错误页和全部缺图时回到系统底色，不抓取其他页面的图。减少透明度/提高对比度时回归系统底色；修材质可见性不得改变原生中性选中或强制焦点。

### 4.2 网格与卡片

| 项目 | 统一标准 |
|---|---|
| 内容边距 | 改用 Steam 浏览页的左右/底部 8 pt 度量，首行可见安全距 8 pt；来源提示存在时从提示下缘另起安全距，不贴 toolbar。页面顶端/锚点规则见 U07；旧 24–40/28/32 pt 规则退出 |
| 网格密度 | Steam 基准：横间距 8 pt、壁纸卡行距 10 pt、方形封面。所有主界面壁纸网格与目录同宽时单张封面同边长/同列线，不再有堆叠缩进。目录行高另含其名称和数量，文字不能被挤入 10 pt 行距 |
| 列数算法 | 请求列数 `p` 为整数3–6，默认5；`A=max(1,clipWidth-8-8)`，`fit=max(1,min(6,floor((A+8)/(100+8))))`，有效列数 `n=min(p,fit)`，边长 `max(1,floor((A-(n-1)*8)/n))`。clip已扣侧栏/原生滚动条，Inspector为overlay不扣宽。主窗口保持现最小尺寸，正常至少3列；脱离窗口或暂态不足最小卡宽时按fit安全降档而非强行溢出，不写回3–6请求偏好、不声称支持低于主窗口最小尺寸。离屏零宽不应用布局，控件只报告可行端点 |
| 缩放 | 所有主网格初始请求 5 列，选择只在 3/4/5/6 列间改变，按 PageID 保存，目录独立。左“−”缩小卡片/增加列数，右“＋”放大卡片/减少列数；沿 Steam 两段原生控件外形，按钮、菜单、快捷键共用同一命令与可用性。窄窗暂容不下请求列数时不覆盖偏好；下一次点击按当前有效列数变化，避免第一次点击无视觉变化：请求6而有效5时，放大应5→4，缩小仅在有效列数还能增加时启用。resize不写偏好；同次命令更新可用性与AX。旧 width→基础列数及 targetWidth 两种算法均退出；迁移见 §13归档 |
| 壁纸卡 | **完全采用现 Steam 方形卡与内部玻璃 bar**，圆角按现 14 pt；封面 aspect-fill，不拉伸，不改变真实图片/视频/Scene 画面或桌面填充设置 |
| 壁纸bar | 仅两个按钮：左`exclamationmark.circle`固定查看详情，右按当前来源事实投影下载/播放/沙漏/停止四种互斥状态；中间保原标题。退出bar心形和眼睛，喜爱与空格预览仍走既有命令/详情；源DTO不变时也须及时投影pending/ready/stop/失败 |
| 壁纸标题 | 仍在内部 bar 中；不在封面下另加同名一行。文件大小、时长、分辨率保留在详情/菜单及VoiceOver语义，卡片根与placeholder不再显示悬停元数据tooltip，不把现 bar 撑成两行 |
| hover / 按下 | 保留白色描边；hover按缩略图中心等比轻放大1.025，按下不缩放。共用原滚动phase暂停tracking/采样，结束恢复；bar沿原状态显隐，减少动态关闭缩放 |
| 选择 | 单选以当前 Steam 卡片选择呈现；多选右上角勾选标记用系统强调色；playing、focus、selected、favorite 分别建模，不共用一个 Bool |
| 列表目录卡 | 与壁纸卡同单封面边长、同列线；只显示一个方形封面，自选图优先，否则使用成员顺序首项缩略图，未就绪/不可用用媒体占位；不堆叠、不拼宫格；前封面圆角沿现 12 pt，封面下8 pt同一行，左名称13 pt medium、右数量12 pt secondary；长名称截尾，数量不挤出卡框；无壁纸控制 bar |
| 新建卡 | 第一格固定，系统淡色底 + SF Symbol `plus`，下方“新建列表”；可键盘聚焦/AX 激活；不参与目录排序、选择计数、拖动、播放和取色 |
| 列表封面 | 唯一Artwork owner提供自选单图或规范手动成员首项；先确定身份再判可预览，首项无图/不可用不借健康后项。默认共享媒体符号`photo.on.rectangle.angled`/原生后备`photo.on.rectangle`，目录/侧栏/头部同源；支持恢复自动，不复制媒体原件；已实施，验证与试用状态见V01 |
| 封面更新 | 规范首项身份/其资源revision或自选asset改变时更新；普通显示排序/搜索不重写成员首项。后项变化不新建封面需求；临时drag预览不发布成员/背景真值，成功drop后才按权威首项更新 |
| 内容滚动 | 原 NSScrollView + NSCollectionView 可复用布局，不自造惯性；网格滚动条按当前系统行为；Inspector 仍强制隐藏滚动条 |

图像原始比例差异是方形裁切的已接受变化；我的图片会从现瀑布流改为等高方格，这是明确的布局变更。完整图像仍可在原详情/Quick Look 查看。Music 参考中的封面外标题只用于列表目录，用户最后指定的 Steam 壁纸卡规则优先。

### 4.3 标题、空态和响应

普通壁纸页采用参考图一的紧凑 toolbar 标题，内容区不再重复巨型标题；结果/筛选说明复用现标题、tooltip与列表summary，不为补数量另添常驻行。用户要求缩小列表头（U05）：首版封面72 pt、窄窗64 pt，名称22 pt semibold、最多两行，描述非空时在标题下显示（最多三行，完整内容可从编辑查看），保留数量及“随机 / 播放 / 添加”原生胶囊动作，随机和添加仅图标、播放为图标+文字。普通单行名目标高约112 pt；长名/窄窗按原生 fitting size 增高，不能固定168 pt裁字/按钮。头部与网格左右8 pt线对齐，封面/文字间16 pt、底部至少16 pt，随同一内容滚动；旧112/80 pt封面与28 pt标题退出。前轮证据见§13归档，尺寸仍待最终同窗口验收，不能以削按钮缩小头部。

空库/空列表只显示 SF Symbol + 一句提示，不放导入/添加/浏览按钮；真正入口在工具栏。最近页提示“播放过的壁纸将显示在这里”；喜爱页提示从详情、菜单或工具栏加入特别喜爱（卡片bar不再放心形）；空列表提示从顶部添加壁纸。搜索无结果显示“没有符合条件的壁纸”与“清除筛选”，不能冒充空库。加载/账号失败/离线分别呈现，可重试且保留已加载快照。

页面切换立即响应选择，不人为等待 0.75 s 才加载内容；0.75 s 属于主窗口/侧栏/设置共用的背景过渡；Editor/Picker改为详情同款材质，不再运行缩略图取色过渡。复用现 bar 动画，不再引入全页淡出到纯底色的闪白阶段。尊重系统减少动态效果；关闭动画不得改变操作完成顺序。

唯一 NSToolbar 由 App 的主窗口装配持有，Shell 和来源控件只消费注入值/动作：左侧 `固定侧栏tracking separator ｜ 页面标题`，中间 flexibleSpace，右侧按“来源/任务 → 页面动作 → 内容组织 → 视图 → 搜索”排列。U03要求这些职责形成独立原生视觉组：组间用Steam的 `.space`，不把全部 bordered item 连成一个长胶囊；组内仅真正成对的缩放合并；所有播放/随机/上下张控件退出工具栏。筛选/排序邻近，搜索独立最右；不绘制分割线/背景胶囊，无职责不留空组。无层级不放返回；所有来源的返回在功能区顺序第一，独立图文胶囊。侧栏固定开启，无显隐按钮/菜单/分割线收拢；从目录进入的自建列表在右侧功能区首位放独立“返回”组，位置/形态对齐作者工坊返回，不挤到标题或侧栏边；Steam作者返回保留。逐页顺序见下表，`｜`表示原生空隙；所有删除/移除统一trash图标，具体作用域由文案和默认不勾选的源文件复选框说明。最窄窗优先保导航/当前页识别与当前页主动作，原生搜索允许收拢但⌘F必展开；组织/缩放/低频命令可先入可执行overflow，长标题先原生截尾，不能为露全名缩小按钮或把必要入口隐藏到hover。

工具栏宽度优先级：页面标题、搜索、核心主动作最高；选择/正在使用的筛选次之；缩放、来源账号及低频组织动作可进系统 overflow。各来源搜索统一首选220 pt，账号按钮共用32 pt原生度量，窄时交系统overflow；标题最小保留约 100 pt 并截尾。旧主窗口最小宽度内不裁切按钮，所有隐藏到 overflow 的动作仍可通过菜单/键盘访问。NSToolbar 原生溢出与标准控件依据 [Apple Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)；具体优先级由本表制定。

搜索占位统一为“在〈页面/列表名称〉中查找”，作用域只限本页；本地页修改即查询快照，远端沿现 debounce/请求取消，不逐键同步网络。不把所有页连成新的全局搜索，也不在切页时沿用另一个来源的查询字符串。图标按钮统一用现系统控件尺寸与 SF Symbols，原生菜单/搜索/segmented 控件先复用，不再逐模块手画相同按钮。

联合排序对缺字段单独处理：未知大小/时间始终置末，不因降序跑到最前；同值以稳定来源键+ID 决胜；元数据补齐后局部更新，保留可见锚点。Pixabay 下载旧文件的时间只能先取已存在文件的创建时间作为“本地记录时间”并标明来源，不能把本次扫描时间写成历史下载时间。

Video 当前“添加时间”分支读取 lastUsed，不能直接当成统一添加时间 authority。迁移保留旧顺序用于对照；新入库内容记录来源的真实 firstIndexedAt/createdAt，旧内容无可信时间则未知且稳定排序，UI 文案与实际字段一致。该语义纠正须独立回归，不能只改标签或用当前时间填满旧数据。

“我的下载”保留 Steam 当前对失败条目的可见边界；queued/downloading/failed 是否出现在当前下载投影，由现服务合同决定，任务弹层持续可访问。联合页不再另行按“必须存在可播放文件”过滤整份 Steam 记录，避免误隐藏失败项、未知类型或待处理记录；Pixabay 进行中任务仍来自原任务状态，不创造假本地文件条目。

### 5.3 下载页详情与账号

选中 Steam 项打开原 Steam 详情；选中 Pixabay 项打开**原 PixabayDownloadsInspectorView**，其排版、按钮、元数据、缩略图和隐藏滚动条保持不变。混合页通过已选内容引用委托对应 provider 挂载 InspectorHost，不让 Pixabay 详情伪装成 Steam record，也不把原页面选择集整份复制进两家服务。

“原详情不变”不允许继续双写：Video/SIL 详情保留布局与来源元数据，其原心形/标签按钮必须注入固定规范引用和新关系命令，标签改称“添加到列表”，状态订阅统一 store；不能临时改来源全局 selection 后再调用旧 addTag/toggleFavorite。Pixabay 原 footer 仍保留两按钮，不强塞新组织按钮；该来源通过右键和主菜单完成新组织动作。原 Web/Scene 属性入口和开发调试能力保留，已退役的不可见诊断入口不恢复。

下载任务按钮采用原 Steam 任务面板结构，第一阶段原 Steam 任务完全保留；补入 Pixabay 任务分组时只观察原在线服务的进度/错误，不接管下载执行。只展示来源真实支持的取消/重试；无取消 API 时不造一个无效按钮。Steam 账号控制只控制 Steam，离线/未登录不应阻断 Pixabay 和已有本地内容。

### 5.4 新建、编辑与加入列表

新建入口：所有播放列表的首卡、toolbar、侧栏“播放列表”组标题/空白处右键、内容“添加到列表 → 新建列表”。统一主窗口附属原生模态面板（owned child，见Q06），名称初值“未命名列表”，`取消 / 创建`，Return 确认、Esc 取消；去首尾空白后非空即可，支持中文/emoji，允许同名，ID 使用 UUID。名称不作为文件路径，显示过长截尾但不因不必要的文件名校验拒绝正常名称。

普通新建立即建立空列表并进入；从选中内容新建则在一次事务内建立并加入成员，成功后仍留当前内容页，通过非阻断提示提供“打开列表”。写入失败不先在侧栏显示一份幽灵列表。编辑列表用紧凑原生模态面板，含名称、单个本地封面/恢复自动及可选描述，材质与详情/Steam登录一致；Picker使用同款材质，两者固定附属主窗口且阻断下层输入，取消不写、保存原子提交，规则见V02/V10；删除列表明确“仅移除列表，保留 n 张原始壁纸、下载、喜爱与最近记录”，空列表也可删除。

“添加壁纸”打开主窗口附属模态面板（详情同款材质，无缩略图取色/淡入）：来源分段“全部 / 我的视频 / 我的图片 / 我的下载”，搜索、统一卡片/多选、底部已选数量和“取消 / 添加 n 项”。只列本地或已下载且可引用条目；搜索/来源变化只保留仍在当前查询中的选择，滚动不清选择，跨类型一次添加使用“全部”；添加已有成员显示已在列表且不重复，不当作报错。新增追加尾部；列表本来为空时新加入顺序按本次显示快照顺序，禁止遍历 Set 决定顺序。

拖动卡片到侧栏列表等价“添加到列表”，修饰键/拖动图标表达复制关系，不移动真实文件。本地资料库及最近/喜爱/自建列表成员均可单卡拖入侧栏；内部重排及其专属准入/整理命令退出，取消不写；侧栏及目录手动拖排共用sidebarRank；目录固定依sidebarRank；退目录排序菜单，旧保存sort值不改变目录次序或锁住拖排。hover让位仅临时呈现，成功drop才提交一次，取消零写；固定行/新建卡不可拖，不显示插入线。文件外拖导入只在“我的视频/图片”与列表详情接受；列表详情先按原导入服务类型路由并成功入库，再添加关系，不直接从临时 URL 播放。远端网页拖入不隐式下载。

异步导入捕获固定目标（资料库 / 喜爱 / playlistUUID）、导入命令代次和 resetEpoch：切页不改目标，喜爱页导入仍加喜爱，最近页导入始终只入资料库；目标列表已删则仅保留成功入库项并提示未加入，不改投其他列表。按原来源能力接受文件：视频沿现支持格式，SIL 仍支持目录递归；混合输入逐项报告新增/已存在关联/失败。只给成功项加关系；关系写失败不能删已导入的源文件或伪报全成功。导入本身不新增自动播放路径，显式播放仍经过原 ImportedVideoAutoplayGate。

## 6. 卡片、菜单与键盘的统一交互

### 6.1 壁纸卡片内部 bar

保持现 Steam 形状、材质、位置、标题和下载进度表现；共享的是视图与状态呈现，不把其 service 订阅搬给所有卡片。通用bar仅左详情、中间标题、右下载/播放/切换/停止互斥主动作；收藏/列表/Steam订阅留原菜单或适用详情，不再在bar堆扩展动作。 bar 沿部署目标 macOS 26 使用原生 [NSGlassEffectView](https://developer.apple.com/documentation/appkit/nsglasseffectview)，不叠手绘玻璃、不为原生化删现进度/标题/交互；Shared 接替后原同职责呈现退出，禁止长期双 UI owner。

| 内容状态 | 主动作 / 常驻表现 | 心形与列表操作 |
|---|---|---|
| 本地/已下载且可用 | 设为壁纸；所有类型成功后保持bar常显及“停止播放”主按钮，委托当前准确票据；图片的停止结束会话/轮换并保留已应用系统桌面，不伪造图片进程或暂停 | 可标记喜爱、加入列表；喜爱反馈即时，持久化失败回滚并提示 |
| 正在准备切换 | 接受当前票据后立即显示沙漏并禁重复点击，提交后停止、失败后恢复可用动作，保持旧壁纸直到真实交接；不以延时或UI乐观标志冒充pending | 可组织内容；新选择能取消旧意图，旧回包不高亮新卡 |
| 本地静态图片 | 主动作“设为壁纸”→沙漏→停止当前会话/轮换；不显示暂停/视频时长，桌面图保留 | 与其他类型同一喜爱/列表关系 |
| 未下载的远端项 | 主动作下载；下载完成只变为可播放，不自动切换 | 心形与“加入列表”禁用，tooltip“下载后可加入”；Steam 订阅仍可用并有账号检查 |
| 排队/下载/校验/保存 | 沿原进度与可取消边界，原应常驻的 bar 继续常驻 | 尚未正式本地发布时不能加入；完成回包须核对来源与代次 |
| 下载失败/依赖缺失/未知类型 | 原错误与重试/查看详情；无有效启动能力时不假显示播放按钮 | 已在列表中的引用保留；自动轮换跳过，不触发自动下载/依赖弹窗 |
| 源文件后来丢失或下载被删除 | 稳定占位与“不可用/未下载”；右键本地重新定位、Steam重新下载/作品页、Pixabay已有原元信息时重新下载，否则查看原网页后在原浏览下载；均可移除关系 | 保留用户列表/喜爱引用；只认真实来源ID，不给独立Steam视频伪造作品号，不造CDN链接；恢复不自动播放 |

本地发布状态与获取/更新意图是两个独立维度，不能压成一个 availability：Steam 旧版本 ready、更新 failed/downloading 时仍可播放旧健康版本并显示更新进度/“重试更新”。保留下载页现有多选“重试 N 项”，只作用于明确合格的 N 个任务；“不新增远端批量下载”不意味着删除已有本地失败任务批量重试。普通首次下载失败和“有旧版可用的更新失败”必须有不同呈现与能力。

“可组织”与“可播放”分开：已有本地发布记录但暂不支持播放的内容仍可喜爱/加入列表，避免以启动校验过严限制用户组织；尚未完成本地发布或文件已丢失的引用不能新加入，只保留此前关系。Steam 作者标签、分类和远端筛选字段继续由原服务持有，不因本地“标签”改名而迁成播放列表。

当前 bar 的 hovering、keyboard focus、playing、launch pending、download progress、multi-select 各自显隐规则先行为冻结再抽取。滚动期间沿原 WallpaperGridScrollView 退让 hover/GIF，滚动结束恢复；不可在统一卡片时退回每帧全网格扫描、常驻 mouse monitor 或焦点抢占。最近出现但未复现的“删除后 hover bar 不出现”仅作为回归场景，不写成已证根因或顺带增加防护。

| 操作 | 壁纸内容页 | 所有播放列表目录 |
|---|---|---|
| 单击封面 | 普通模式先替换旧选择再打开该来源原详情；不播放、不下载。已选再点保持详情，不发生关/开闪烁 | 单击直接进入列表；新建卡单击开新建 sheet，符合侧栏导航预期 |

| 双击 | 仍按一次选中/详情处理，不引入隐式双击播放，避免与现单击链冲突 | 不重复打开/重复创建 |

| 方向键 | 视觉网格按行列移动，自动滚入可见区；不改变播放来源 | 在目录卡间移动焦点；Return 打开，AX 与鼠标可达性一致 |
| Return | 单项可用时设为壁纸；未下载时只下载；多选不批量播放 | 打开目标列表或新建 sheet |
| Space | 原生 Quick Look 支持本地图片/视频；Web/Scene 使用原预览/详情能力，不冒充可 Quick Look 的视频 | 不播放列表；可打开列表详情，操作提示明确 |
| Esc | 依次关闭最上层 transient/sheet，再退出多选或关闭 Inspector；搜索编辑按原 responder 行为，不擅自清空全部状态 | 关闭 sheet/返回上级按现原生 responder；不删除列表 |
| ⌘A / ⌘F | 原生导入面板与搜索/文本交AppKit responder chain；网格全选当前过滤结果，⌘F 聚焦本页搜索 | ⌘F 搜索列表；不选中新建卡，目录无多选则不劫持 ⌘A |
| Delete | 按页面语义移除，与toolbar同一确认及默认off源文件选项，始终校验当时目标ID；文本编辑时只删文字 | 聚焦已有列表时提示删除列表；焦点在搜索时只删文字 |
| ⌘Z | 撤销喜爱、列表成员增删、列表排序/重命名/删除；统一 NSUndoManager，实体文件删除不伪装成可撤销 | 撤销同一用户关系事务；恢复列表保原 UUID/顺序 |

有选择模式的页面统一使用该模式的显式多选；不在本轮顺便换成另一套 Cmd/Shift 选择习惯。保留已有系统快捷键，新增命令先核对 MainMenuBuilder 冲突；不臆定一套覆盖用户快捷键的新组合。Editor/Picker存在时，App菜单/主窗口的上下张快捷域不操作下层：非文本控件禁用⌘←/⌘→，文本保行首/行尾；原壁纸继续播放，系统全局hotkey/状态栏原能力不受影响。后台窗口 hover 继续服从原 `.activeInActiveApp` 语义，不因为失焦怀疑而 makeKey/orderFront。

菜单迁移必须同时覆盖 [MainMenuBuilder](../../MyWallpaperX/App/MainMenuBuilder.swift)、[AppDelegate 验证/转发](../../MyWallpaperX/App/AppDelegate.swift)、[主菜单动作](../../MyWallpaperX/App/MainWindowMenuCommands.swift)、[窗口键盘和预览绑定](../../MyWallpaperX/App/MainWindowController.swift)，不能只改 toolbar。采用稳定 command identifier/selector + 当前 PageID/引用能力验证，退出按显示标题匹配和落入 default:true 的旧准入；混合页不通过改 bridge.isActive 冒充来源页。

### 6.3 移除与文件删除的语义

| 所在页 / 命令 | 实际结果 | 文件与其他关系 |
|---|---|---|
| 自建列表“从列表移除” | 默认off删该playlistID成员及对应最近记录；on另逐项删除真实源文件 | off保其他关系；on保其他引用但真实源已缺失，无虚假可撤销物理删除 |
| 特别喜爱“移除” | 默认off取消喜爱及对应最近记录；on另逐项删除真实源文件 | off保文件/列表；on其余引用保留但真实源已缺失；保原锚点 |
| 最近条目“移除” | 默认off只删所选最近关系；on另逐项删除真实源文件 | off不停止播放、保其他关系，新的成功使用可再进入；on沿原source活动资源合同 |
| “清空最近使用” | 明确确认后只清历史，保源文件/列表/喜爱 | 沿现原记录清除命令，不把全历史清空偷换为源文件批量删除 |
| 我的下载“移除” | 默认off持久隐藏下载页并清对应最近记录，原文件及raw source事实保留；on才委托原来源实际删除 | off在既有列表/喜爱中仍可本地播放，不能伪报未下载；on成功项显示源已缺失。绝不取消Steam订阅；错误/部分失败逐项报告 |
| 我的视频/图片“移出资料库” | 默认off持久隐藏当前库页并清对应最近记录，保raw索引/派生资源、源文件及其他关系；on才委托原来源删除真实源文件 | off在既有关系中仍可用，on成功后其余引用显示真实缺失；不能把隐藏当索引purge或因投影暂空批量清关系 |
| 详情/来源页明确的物理删除 | 按原来源确认、权限、活动资源与删除合同执行 | 不跨来源按同名文件删除；不把“移除列表”路由到此入口 |

关系保留适用于**曾合法加入的**本地内容；不改变 D9 的入场规则。自动轮换排除不可用项，手动点它给定位/重新下载提示；恢复下载不自动播放。物理删除成功后清对应下载详情与执行缓存、撤对应在途详情请求；失败不清其他内容，防复活的原事务tombstone随原GC退出。原生确认框删除文件复选框与正文左缘对齐。批量删除统一一次确认，逐来源分组提交，返回每项结果；不能用第一家成功清空所有选择，也不能用迟到完成清掉新页面的新选择。

改造前 Pixabay `deleteLocalFile(at:)` 吞掉文件删除错误后更新集合；现原来源 owner 的 `deleteLocalFiles(at:)` 已返回可验证逐项结果，仅成功项退出本地快照（基础W11/W13，状态见§10）。混合投影不得把 downloadedIDs 消失当物理删除成功。删除失败保留真实可用资源和失败项，不假移走；成功项才更新来源快照，完成不能清理后来建立的选择会话。

## 7. 共享职责、数据流与耦合控制

### 7.1 先划清共享范围

| 层 | 负责 | 明确不负责 |
|---|---|---|
| Models / 内容引用值类型 | 规范 WallpaperReference、来源/类型、能力、成功事件、PageID、PlaylistID | 不 import AppKit/来源 service，不直接读文件或发网络 |
| Core / 用户内容关系 | 单一 UserCollectionsStore：列表、成员顺序、喜爱、最近、来源别名与迁移事务 | 不复制完整媒体模型、文件索引、缩略图缓存、下载任务、播放器或每帧状态 |
| 来源 provider | 原 Video/SIL/Steam/Pixabay 服务的稳定引用、显示元数据、可用性、缩略图租约和已有命令适配；adapter 保原 SteamWorkshopPreviewState、账号订阅与进度观察，仅向卡片交值/回调 | 不各存一套全局列表/喜爱/最近，不向 Shared 传 Steam record 私有依赖 |
| Shell 呈现与控件 | 选中页面与查询呈现状态、原生侧栏/目录/网格、布局及值/动作投影 | 不实例化来源服务或承担跨模块toolbar/播放命令owner，不实现下载/渲染/静态系统壁纸应用 |
| Shared / 卡片与网格规则 | 现 Steam 卡片呈现、bar 状态、布局度量、选择/hover 呈现和空态 | 不访问 `.shared` 服务、运行网络查询、写收藏数据库，不订阅 Steam 账号 |
| App 装配 / 播放桥 | 唯一主窗口toolbar跨来源布线、混合投影及Inspector委托；引用解析为原播放请求，唯一事务成功关联回引用 | 不增加第二个 handoff、计时器、图资源 owner 或最终输出 |
| 原运行时与下载器 | 保留真实播放、发布/退休、权限、目录、认证、缓存与任务执行 | 不感知页面文案、sidebarRank 或目录网格布局 |

依赖方向为 `Models ← Core 关系/合同、Shared UI、Modules 适配 ← App/Shell 装配`；Modules 不互相 import 服务实现，Shared 不反向引用 Modules。Shell 只依赖内容页能力和 providers 的合同，业务类型分发集中在已有装配边界，不散入每个 toolbar、cell 和菜单的 switch。 密度同样只有一个 Shared 纯规则、Presentation 每页一份偏好，App 将值/命令注入来源 Grid/Toolbar；不在 Shared 查服务或递归猜窗口，远端查询/分页/账号仍归模块。

一份 `CardPresentation` 提供 title、thumbnail handle、favorite、selection、publishedAvailability、独立 acquisition/updateState、primary/secondary actions 和各自 progress；点击只上送 typed command。来源特有“书签订阅/查看作者/属性”作为可选动作描述，不塞入通用的 Steam 字段。通用卡片不得 import SteamWorkshopService、SILService 或 WallpaperManager；来源 preview state 不在 Shared 里冒充第二图像缓存。播放/停止命令还须在 App 边界核对规范引用及当前 ticket，过期卡片的 Stop 不能停掉后来提交的新壁纸。

建议位置是 Models 新增共享引用/列表值，Core/LibraryCollections 放持久化与查询，Shared/Components 承接真实卡片/玻璃 bar，Shell 放页面与 toolbar 装配，来源适配留在原 Modules。名称与文件拆分在实施阶段按真实消费者决定；不是要求创建同名的一堆空协议文件。单文件不超过 1000 行，也不为这个限制把单一事务碎片化。

### 7.2 引用与持久化

| 数据 | 建议字段 / 约束 |
|---|---|
| WallpaperReference | provider namespace + 不透明稳定 sourceID，媒体类型为元数据而非界面路由；本地用现 UUID，Steam 保留现作品 ID **或合法的 `video:<stem>` 独立下载合成 ID**，Pixabay 用 video ID；不强制 UInt64，不同来源同号不碰撞 |
| 引用别名 | 显式保存 Steam/Pixabay 下载与其静默导入 Video record 的映射；同一下载只占一份收藏、历史和成员。只依据原记录 provenance/可信路径归属，禁止相似标题合并 |
| Playlist | UUID、name、createdAt、modifiedAt、sidebarRank；成员不内嵌整份来源模型；保留合理的重复名称，不把名称作为持久化主键 |
| PlaylistMember | playlistID、规范 reference、position、addedAt；对 playlistID + reference 唯一，位置事务内整体重排/校验 |
| Favorite | 规范 reference、favoritedAt?、migrationOrder?；只有已知时间才填时间，无时间的旧标记保稳定顺序 |
| Recent | 规范 reference、lastSuccessfulUseAt?、commitSequence、migrationOrder?；最多 50；旧快照未知时间不伪造；本地标题/封面提示可有可无，不取得资源 authority |
| 页面状态 | 按 PageID / PlaylistID 保存搜索、筛选、排序、缩放、scrollAnchor；不按可变名称保存；不把搜索结果当实际成员 |
| 播放来源 | 持久化来源描述与上次规范引用，可重建候选；不持久化 NSView、URLSessionTask、daemon execution 或过期租约 |

首选单个版本化 SQLite 用户关系数据库（系统 SQLite3，项目已有 SQLite 使用经验），以事务保证同名合并、关系增删、删除列表与撤销的一致性；其体量与媒体索引分离，不复用 VideoLibrary 私有 WallpaperIndexStore 造成上行依赖。若实施 spike 证明现有持久化设施可直接满足上述原子性，则复用设施并修订本节，不在 UI 层分散多个 UserDefaults 数组。

数据库路径放现应用 Application Support 下，迁移前备份仅涉及旧索引/设置和关系元数据，不复制真实媒体。写事务串行，快照异步生成并绑定 revision；主线程只应用值快照，不做全库 JSON 序列化、磁盘扫描、文件 hash 或 SQLite 大查询。损坏/未知新 schema 不能按空库自动覆盖：保留原文件、可读来源库仍可用，受影响的关系列表显示明确恢复错误。

规范 identity 不等于文件版本：同 sourceID 的重新下载/原子替换保留用户关系，provider 以资源 revision 触发原缩略图/播放失效链。两个分别导入的真实副本不因字节相同合并；硬链接/符号链接的既有路径语义由现导入服务裁决，不引入每次扫描全文件摘要。

当前 Video/SIL 移除后重导入会生成新 UUID，“资源回来就自动复活原 ID”尚不是现有能力。provider 保存已进入关系的原 UUID、最小 locator/来源证明与缺失状态；原记录恢复直接重用身份，记录已删则仅凭可信原行/文件归属或用户“重新定位”建立 alias。同路径另一文件、同名副本或无证明重导入不自动接关系。显式定位限既有不可用本地引用，经原单文件导入及持久成功后，同一关系事务重验epoch、旧canonical/关系与同provider目标，再记locator并合并alias；取消、失败或陈旧回执不重关联。新源已入库而关系失败时保新源并提示未关联，不删原媒体或自动播放。定位信息不取得文件生命周期权威；独立Steam视频后来补sidecar也只按已证归属建alias，不猜作品号。

晚建立的可信 alias 也在同一关系事务中归并：成员重复保留最早位置/加入时间，喜爱保留已知最早标记时间，最近保留最新成功次序，其他名称/来源提示不覆盖真实 provider 元数据。发布一份 identity revision 使查询、选择、封面和运行队列共同解析到规范引用；不靠列表自己去重后仍让写侧留下双记录。

### 7.3 页面、命令和快照

页面提供一个不可变 `PageSnapshot`：有序内容 ID、总数/过滤数、选择、loading/error、capabilities、revision；同一次快照派生 toolbar、菜单和网格，避免各自从来源计算出不同可用性。选择 owner 是当前内容页；两家下载服务继续拥有其业务状态，但不同时持有混合网格的选择真值。

组合查询顺序固定为“页面基础成员 → 规范引用去重 → 搜索/筛选 → 稳定排序 → 显示快照”；最近页先限制 50 再过滤。删除/播放/加列表命令捕获稳定 ID 和页面代次，执行时重新解析当前能力，不能捕获 indexPath 后跨 await 删除另一张卡。批量动作默认所有目标均支持时才启用，否则显示可执行子项数量并要求明确选择，不能静默丢掉不支持项。

现有 NSCollectionView 复用/diffable 能力优先保留；不要借改版重写全套 grid renderer。新混合页可采用原生 [NSCollectionViewDiffableDataSource](https://developer.apple.com/documentation/appkit/nscollectionviewdiffabledatasource-axww)，前提是保留选择、可见锚点、drag 与缩略图租约；不能仅因采用原生 API 就声称流畅度已提升。

Inspector 仍唯一使用现 InspectorHost，内容由 provider 挂载；方向换选的真实预览框不得先位移再复位，保既有最终排版/隐藏滚动条，Host门不能代替真实来源子内容布局验证（V09）；快速 Steam→Pixabay→图片切换要撤销旧挂载/异步详情，隐藏页面不得重新打开 Inspector。Quick Look 在装配层把支持的引用映射到原本地 URL，Web/Scene 继续原能力；不为每个混合页面新增一个全局 QLPreviewPanel singleton。

## 8. 混合播放列表与自动轮换

### 8.1 唯一播放来源与候选

在现产品播放/导航职责上扩展一份类型无关的队列状态（下称 PlaybackSequence），不是另建播放器。它拥有“来源描述、候选引用顺序、当前位置、前后历史、是否轮换”；Manager 继续唯一拥有意图和切换提交，原 policy/command multiplexer 拥有暂停音量，执行端保留各自生命周期。timer 只允许一份，最终从原 Video-only 调度迁入同一 sequence 调度职责，旧 timer 和 CrossRuntimeWallpaperNavigator 的旧候选算法明确退役。

PlaybackSequence 是 WallpaperManager 现产品导航职责内的状态；纯候选/顺序算法可放 Core，实际提交/计时撤权仍由原 Manager 驱动，不再创建全局 SequenceService。App 只装配 provider 解析与来源能力，UserCollectionsStore 不启动播放器或 timer。manual、timer、ended、候选失败、已提交输出丢失、缺文件后的产品级后继全部进入同一来源规则；原 `playbackControl`/`WallpaperApplication` 的全库失败 fallback 同时撤权，不能迁走 timer 后仍从旧分支越过列表选视频。执行端内部同内容恢复保留原 owner。

| 来源 | 选择 / 顺序规则 |
|---|---|
| 自建列表 | 手动或本页当前选择排序的完整成员顺序；点“播放”从选中可用项开始，无选中从第一项；点单项主动作以此项为起点 |
| 特别喜爱 / 最近 | 采用开始播放时的有序快照；最近记录自身变化不能把队列当前项反复移到首位而造成 A/B 循环 |
| 本地视频 / 图片 / 下载页 | 采用本页有序快照；显式在搜索结果点播放/“播放结果”时只取该结果集，清搜索或切页不会悄悄扩队列 |
| 远端浏览页点已下载项 | 仅该本地内容作为当前来源，不把整页未下载远端结果带入轮换；用户可从“我的下载”或列表开始多项播放 |
| 没有列表来源且用户明确上下张 | 全局后备为“全部本地可播放内容”规范去重投影；只在显式导航时建立，不由启动失败/设置更改/空列表偷偷触发 |
| 启动恢复 | restorePlaybackOnLaunch 关闭时无 session/timer；开启后，新版显式来源恢复最后成功引用/暂停和合法来源，来源已删只恢复最后引用并停自动，引用不可用则保系统画面提示。首次升级旧快照的无来源兼容分支按下文原有确定性视频后备，二者不得混用 |

浏览页面不改播放来源，明确点击播放/设为壁纸只创建 **pendingSource/pendingCursor**，与唯一 ticket、意图 epoch、sequence revision 和推进代次绑定；只有该次非 recovery 成功提交才原子采纳 committedSource、cursor、成功历史与新截止期；撤销现 prepare 前对 recent/history/index/source 的写权，同内容明确重选与内部恢复分别结算。失败/取消保留旧来源、位置和剩余计时；A→B 坏 Scene→C 的迟到 B 不能改 C 的队列，自动 visited/失败跳过集合也不能跨代次生效。

菜单/热键/状态栏的上下张遵循同一当前来源和播放模式：随机模式下“下一张”先消费已成功返回的前进历史，历史耗尽后从当前来源的其他可用项抽样；“上一张”回到实际成功播放历史，无历史时保相邻回退。顺序/循环模式的手动上下张保相邻项。全部复用唯一PlaybackSequence，不按入口另建队列或强制顺序；跨类型自动推进继续按顺序/随机设置。此处按2026-10-28用户反馈修订原全局相邻裁决。无合法来源的显式全局导航才使用后备；空列表、失败或来源尚未加载不触发后备。

队列是来源的一个运行快照，不是第二份持久化成员表。用户明确修改当前列表成员/手动顺序时，在当前项后续边界更新队列 revision；已被移除的当前项继续显示到下一次切换，下一项从当前已解析后继中选择。临时排序/搜索只在下次明确播放时建立新快照；更改排序不会直接切壁纸。删除列表使当前队列变成可结算的会话快照，当前播放继续；不把自动轮换悄悄退回全库。

来源初载未完成与来源不存在分开：等待初载不写“全库来源”，期间不自动跳走；当前队列非资源租约，只在开始准备时由原来源申请正确版本的 lifetime。列表/最近被用户显式删成员时更新后继，但普通最近自动移首不重排在播快照；候选归零保持当前健康输出并停止推进。删列表后的会话快照只在本次会话使用，重启按上表的已删来源政策处理。

旧恢复兼容仅由快照 schema/迁移 manifest 的明确 legacy 状态准入，不能只因当前 source=nil 就启用。首次升级旧视频状态、或旧工坊 replay 失败时，保留原“最近可用视频→首个可用视频”的确定性后备，经原能力和规范引用解析后走同一事务，保留暂停/设置与 restore cause，不随机、不计新最近；成功后固化规范来源并结清 legacy 状态。已存在新版列表来源的失效、空列表、Stop、reset 和关闭恢复绝不进入该兼容分支，不让陈旧 SQLite 越过完整 fallback=[]/显式删除复活旧项目。

### 8.2 模式与计时语义

| 现有设置 | 视频 | 图片 / Web / Scene |
|---|---|---|
| 循环当前项 | 保留原循环，不自动走下一项 | 保持当前壁纸，不人为发明 ended 或定时切换 |
| 顺序/随机 + 启用自动切换 | 新壁纸成功提交后开始现设定的完整间隔；视频持续按原 timer 模式循环 | 同一间隔轮换；无需伪造媒体时长；静态图片保持显示到 timer 到期 |
| 顺序/随机 + 关闭自动切换 | 保留现视频播完再切行为 | 没有自然结束事件，保持当前项直到手动下一张；设置页说明该差异，不新增隐藏默认时长 |
| 手动上下张 | 复用原节流/取消；统一遵循上述播放模式与成功历史语义 | 同一规范候选，逐项委托来源；按同一产品事务交接，只有目标真实成功才移动 committed cursor |
| 点击“随机播放” | 使用现随机模式，重置该来源的运行序列；不静默改用户是否启用自动切换 | 同左；若定时未启用，不假定 Scene/Web 会自己结束 |

timer 的截止期在**成功提交**后重置，准备时间不侵占新壁纸展示间隔。准备期间只允许一个待切目标；旧 tick 不再次发起另一候选。本轮已实现候选：用户/系统暂停时冻结轮换剩余时间，恢复后继续（基础W16，状态见§10）；这是相对改造前 Video timer 不读取有效暂停的新增语义。原 multiplexer 独占可观察的有效 pause 快照/变更事件（含初始值与 revision），调度订阅它，不另建系统策略观察者或轮询。静态图片不伪造引擎 pause。计时用单调时钟，睡眠/唤醒不补播漏掉的 N 项。

全局播放/暂停不能再用 `isAnyEnginePlaying` 单独决定动作和文案：动态健康端点或活动静态轮换才具备可暂停能力；toggle 切换 multiplexer 的 **isUserPaused**，有效暂停仍为 user OR system。系统暂停时点击暂停仍能设置独立用户暂停，继续只清用户暂停，不清系统暂停。状态栏、F 键、主菜单读取同一产品级能力/意图；静态轮换显示“暂停/继续轮换”，无活动 session 的系统静态图不提供假播放按钮。首次订阅、恢复和 provider 注册不能漏掉当前 pause 值。

Stop 与 pause 分开：Stop/退出/reset 同步推进原产品意图和 rotationGeneration，撤销截止期、queued tick、失败重试、待导航、pendingSource 与旧回包写权，随后按原生命周期释放候选/执行端。须实际取消并清空原 pendingManualNavigationWorkItem/方向/用户标志，迟到闭包复核原代次。Stop 后 resume、改间隔、目录/alias 更新或旧完成均不能复活 session；只有新的显式播放/导航或获准的启动恢复可建立它。暂停只冻结而不销毁来源；停止静态轮换可保留 OS 已应用图片，不冒充清除系统壁纸。退出先完成可失败的当前代次 flush；成功后同步撤销准入并进入不可逆 teardown，失败留在原会话供用户重试，动态保留原restore开关与暂停恢复政策；已写静态图的退出恢复按§18 T06和退出时syncSystemWallpaper开关执行。

视频自然 ended 与 timer tick 争用时按票据/代次只接纳一个推进。手动上下张的随机历史导航只使用已成功提交历史，前进历史耗尽再抽样；自动失败项不写历史，不把准备过但没显示的内容作为上一个。手动选择新项清空失效 forward 分支，保留现已验证的节流行为。

### 8.3 成功事件、最近使用与失败

从现 Manager 的唯一成功提交出口派生一次 `PlaybackUseCommitted(reference, ticket, intentEpoch, displayCohort, cause)` 事件；引用必须在请求创建时携带，不能事后只凭路径/recordID 猜来源。Video/Web 的可交接证据、Scene 实际 presented、图片系统 API 多屏应用结果仍按原事务合同，不改成“发出请求就算成功”。

| 请求入口 | 必须贯穿的上下文与旧保护 |
|---|---|
| 本地视频/图片、卡片/详情/菜单 | 捕获规范引用、source descriptor/revision、cause、推进代次；静态通知从仅 URL 补 typed 上下文，最终仍交原 system-still endpoint |
| Steam/Pixabay 下载视频静默导入 | 原 ImportedVideoPlaybackRequest 扩展来源上下文；保留 autoplayToken、取消与 PlaybackResourceLifetime，将现唯一 beginPlaybackIntent 提前到导入准入并先 begin 再 claim 原 gate token（begin 会撤旧 gate）；完成后携同一票据 prepare，不再 begin/另造 epoch |
| Steam Web/Scene | 关联原 prepareWebPlaybackProcess/claimScenePlaybackIntent 已产生的 ticket/epoch、精确版本 lifetime；保留 Scene newSelection:false 等恢复语义，不在 App 转发再抢新意图 |
| 启动 replay / 崩溃与拓扑恢复 | cause 明确为 restore/recovery，贯穿 AppDelegate、工坊 replay 和静默导入；不当普通 userSelection 写最近、不随机重抽，restore=false 不能被入口绕过 |

正常成功更新队列与 UI 不依赖关系数据库成功落盘。最近写入失败只报告并按同 commit identity 幂等重试，不回滚已显示壁纸、不重新启动/重新分配播放意图；reset/退出代次变化撤销旧重试写权。

最近更新条件：成功建立一个新的用户/轮换内容选择；自动轮换成功也记入。下载完成、选中、预览、准备 accepted/launched、失败/取消、旧票据迟到、同一票据的多屏重复回执、恢复同内容的崩溃/拓扑/属性重建均不新建记录。用户明确重选同一健康壁纸，即便复用输出，也以新的成功选择事件刷新时间；这与不计内部恢复有明确区别。

同一规范引用替换旧位置，更新成功时间和序号，再截取 50。系统墙钟回拨时以单调递增的提交序号保持本次会话因果序，展示时间仍是真实日期；跨启动使用持久化序号接续，不因时间相等或同 ID 字符顺序产生抖动。

自动候选只含本地可用且原 provider 判定可启动项；未下载、依赖缺失、文件丢失、正在删除、unknown、明确不可用项保留在列表但跳过，不自动下载/修依赖/弹登录。运行中出现真实失败按一次推进最多遍历当前候选数，失败项本轮记跳过；全部失败时停止自动推进并提示，不密集无限重试。**候选失败**只要旧端点仍健康就保旧；**已提交 output lost** 时不能承诺恢复不存在的健康输出，应沿原事务的输出丢失/系统后备结算，再在原来源内作有界恢复。显式手动重试或资源状态变好才恢复资格。

静态图仍由原 system-still endpoint 应用；多屏部分失败沿原回滚处理，不能因列表统一而先停动态壁纸。Scene/Web 属性窗口、音频/输入、显示器拓扑、启动恢复和旧版本资源租约均照原合同；不在 UI 批次改 shader、VM、编译、最终合成或每屏异类内容能力。

## 9. 用户数据迁移与回退

### 9.1 可重入、一次性切换

首次升级在原缺失清洗、最近归一化、默认种子注入及旧存储重写**之前**捕获一致元数据快照 → 按现优先级物化旧库/编辑日志 → 生成迁移映射和计数 → 写同目录临时新版关系库 → 事务校验成员/别名/顺序/最近上限 → 原子发布数据库与内部 schema/migration marker → 切换唯一关系读写 owner。来源原存储 owner 提供无清洗的快照入口，不能为备份先构造会删失效项的 SILService/Manager。媒体存在性影响可用性，不影响旧关系是否被迁入。

Video 输入不是仅 SQLite：UserDefaults `Wallpapers` 完整失败保存快照（**包括 []**）优先于 SQLite；无该完整快照时，用原 initial-index 的 seed/SQLite baseline + `WallpaperIndexStartupChangesV1` 有序 steps/显式字段编辑按原规则物化。显式删除不能被陈旧 SQLite 行复活；SQLite 读取失败时不丢 fallback/journal，也不能把缺失部分当空库宣告迁移完成。SIL 读取清洗前原 JSON 与标签表，最近读取归一化前原快照；不承诺恢复升级前已经被旧版本删除且无备份的数据。

原索引使用 WAL，备份必须由原队列的读事务/SQLite backup 取得一致视图，不能只复制主 `.sqlite3`。快照 manifest 记录 schema、源 revision/文件身份、完整性与计数；UserDefaults、SIL 和启动编辑输入在短暂串行准入边界内冻结或一致重放，捕获期间新导入/删除不丢、不双计。 启动失败时须在原owner暂缓破坏性清洗和旧关系写；只读浏览/播放可用，不能构造旧service后任其删离线记录。已有final（含reset-complete）直接打开；仅有恢复input时沿原UUID映射续作，捕获完成前须持久化可续作input，不能静默重读后来清洗的live源。随后等待来源初载仅用于解析可用性，不能反过来替换清洗前迁移输入。异步 UI 暂空不当空库，不长期锁主线程。

schema 与迁移 marker 放同一关系数据库事务内；临时库发布前完成 checkpoint/关闭写句柄，再原子替换，不能把数据库 rename 与另一个 UserDefaults 写入误称同一原子事务。marker 绑定输入 manifest、resetEpoch、映射与完成状态；新版产生任何关系编辑前，旧写入口必须全部转到新 owner 或被串行排队，不能开放长期双写窗口。

失败保留旧存储与临时错误依据，继续旧可读路径；不能用空数组覆盖新库/旧库。重启重跑同一迁移不能重复建列表/合并两次，marker 只在数据真正落盘后生效。真实用户媒体只读；实际破坏/故障演练只对隔离 HOME 和索引副本做。

### 9.2 旧 owner 退出与回滚窗口

原 Video tags/favorite/recent 和 SIL tags 先只作为迁移输入；新关系列表成为唯一写 owner 后，旧模型如暂需字段只能是新库只读投影，不允许同时修改两边。原库文件索引、播放恢复和导入功能保持工作；移除旧字段/键之前逐一追踪 importContext、deletionScope、随机历史、自动播放、reset、flush/exit 和启动兜底调用者。

实施期间保留一份迁移前一致元数据备份及明确版本标记，用户验收和回退演练结束前不自动清掉唯一副本。一旦新版产生关系编辑，**只切旧 UI 不能称为无损数据回滚**：应回到同一新版存储的旧呈现适配；退回老 App 须显式导出/逆迁移可表示字段并告知混合列表无法完整表达，不能直接覆盖新数据库。开发备份/故障恢复与下节正式用户“导入/导出设置”分别验收；不新建云同步/跨设备平台。

全新安装、升级、迁移失败/重试、reset 和退出 flush 走同一关系服务。旧 UI/旧模型只有在新旧正反例、迁移与回退演练、真实页面试用通过且无产品消费者后退役；不靠 rg 零命中一个名字就证明整个链可删。仅有一个轮换 timer 不要求删除原 policy idle 计时、切换截止期或原生引擎帧时钟，它们职责不相同。

### 9.3 正式个人设置导入/导出兼容

保留设置页原“导出设置 / 导入设置”按钮、保存/打开面板与确认/结果提示，设置装配接入新关系合同；不让旧 `importPersonalSettings` 再直接写 Video/SIL 的退役关系字段。原 schema5 已覆盖偏好、视频喜爱/tag、SIL/tag，新协议不能只打包视频而漏混合列表，也不能把正式用户入口降为开发工具。

基础schema6（本轮升级schema7，见§14）：保留原可导出 preferences（UI22补齐快捷键开关/四绑定、Scene HDR/媒体信息和播放性能档等可移植偏好；旧optional字段不覆盖），增加规范引用/最小 locator、playlists、ordered members、每引用显式 favorite 状态和迁移来源；排除媒体字节、缩略图/派生缓存、凭据、daemon/lifetime/待执行任务。**最近历史、页面/搜索/滚动状态和运行播放来源继续不属个人设置导出**；仅原已导出的全局视频排序偏好接入新 Presentation 的视频页排序值，schema6以最小显式字段表达新版排序，旧v1–5缺字段不覆盖、dateAdded用明确旧版时间序列，不冒充入库/成功时间；导入恢复记录保该值before/target并核同epoch/后续编辑，导出读取唯一呈现owner。开发一致备份才包含完整界面状态。可保留只读派生的旧 entries/tags/silEntries 兼容字段，但同名多列表/混合成员在旧 App 中不可完整表达，须说明降级边界，不能伪称旧版无损。

旧版v1–v5路径（本轮另保v6缺新字段语义，见§14），沿原缺可选偏好不覆盖、热键本地优先、同路径显式标题/喜爱覆盖与成员合并规则，经同名映射进入新库；缺文件保留 unavailable 引用。新版输入按 playlistUUID 幂等 upsert，已有同 UUID 元数据应用导入值、成员按原现有顺序保留并追加新增项，不删未涉及列表/成员；同名不同 UUID 不误合并，引用 alias 规范化后去重。显式 favorite=false 只清该引用，未提供状态不清现有喜爱。旧 payload 重复导入复用其来源/tag 映射，不重复建列表；未知更高 schema 先拒绝并保留文件，不静默忽略新字段写成不完整成功。

备份中的缺失关系属于用户明确恢复历史组织信息，和浏览页首次给未下载内容创建关系不同；它只得到 unavailable 状态，不因此下载/播放，也不放宽 D9 的普通新增资格。

跨 UserDefaults、SQLite 和 SIL JSON **不存在天然单事务**。由现设置导入装配先只读解析/验证并生成命令 ID/有界恢复记录，按相同 resetEpoch 串行执行来源元数据和关系写入；记录各 owner 的旧值/目标值与完成阶段，崩溃/失败在开放后续编辑前幂等续作或恢复。新关系部分仍在单库事务中提交；来源写和偏好应用不能以一次 SQLite commit 冒充全完成。全部完成才统一发布成功摘要；否则报告真实阶段、保留恢复依据，不盲目用旧快照覆盖后来的用户编辑。导入不新增下载、媒体删除、自动播放或最近事件，设置变化也不能让已 Stop 的队列复活。

### 9.4 清缓存、重装级重置与退出

“清理缓存”继续只处理各原 namespace 的预览/缩略图/静帧和 Steam 浏览/详情缓存；不得清关系列表、喜爱、最近、alias 或原媒体。新共享卡消费原缓存，不新增漏在设置清理入口外的第二缓存。

“重置应用”（原“重置默认”）保持原重新安装级语义：在同一 resetEpoch 下先撤销播放/序列、待导航、迁移/导入/alias/最近写入和 Undo，再清设置、库/UI 状态与全部用户关系，按原政策恢复示例与默认值并 flush；实际下载/媒体文件保持原不删除政策，不清未知目录。清理后写新的完成 marker/代次，旧投影键、待写日志、迁移备份不得被自动当首次输入灌回。重置前已接纳的媒体任务若不能取消，其晚完成只结算原任务，不能恢复旧列表/喜爱或自动播放；用户明确重导入备份是新的命令。退出只 flush 当前已提交代次，不能等待旧任务后又回写已重置数据。
